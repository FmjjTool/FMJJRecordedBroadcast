# 本地资料站服务启动器 + 腾讯文档修订增量（2026-11-15）

## 需求

- 在工具箱里做一个「本地小程序 Web」服务启动器：几个按钮，启动后自动用系统浏览器打开本地站点，也可随时点「打开网站」。
- 从 GitHub 拉取 `FmjjTool/webwiki`（前端）与 `FmjjTool/webwiki-api`（后端 / 腾讯文档同步）。
- 套用腾讯文档拉取：本地网站 + 腾讯文档预览。
- 私有项目保护：必须先登录 GitHub 才能拉取代码、一键部署。
- 腾讯文档重复不再拉取：按上一次拉取时间定位，再逐条校验内容；同版本 / 同修订号不同编辑人必须保留。
- 其他需求先放。

## 方案

### 1. 新增 `src/toolbox/webwiki/` 引擎

- `config.py`
  - 资料站根目录默认 `统一导出目录/本地资料站`（`download/` 已在 .gitignore）。
  - 端口默认 API 8000 / 站点 8090，可配置。
  - GitHub 登录态存 `config/webwiki_auth.json`（不进导出目录）。
  - 读取 Windows 系统代理；给 git / pip / npm / 同步脚本补 `HTTP(S)_PROXY` 与 UTF-8 环境。
  - 自动探测 Python / Git / Node；Python 优先用当前解释器同级 `python.exe`。
- `auth.py`
  - GitHub OAuth 设备码登录：申请设备码 → 二维码（内容为 `github.com/login/device`）+ 8 位设备码 → 轮询 Token。
  - 授权页显示「GitHub CLI」（使用其公共 OAuth Client ID，免用户自己注册应用）。
  - 保留 Personal Access Token 兜底；Token 只写本机。
- `gitops.py`
  - 仓库不存在则 `clone --depth 1`，存在则 `fetch + merge --ff-only`。
  - Token 通过 `GIT_CONFIG_COUNT` / `http.extraheader` 传入子进程环境，不出现在命令行和日志。
  - 本地有未提交改动时拒绝拉取，避免覆盖。
- `deploy.py`
  - 资料站专用 `.venv` + `pip install -r webwiki-api/requirements.txt`。
  - `npm ci`（无 lock 时 `npm install`）+ `npm run build`。
  - 运行 `sync_once.py` 同步腾讯文档；文档版本没变只发约 76KB 探测请求，有变化才逐表拉取（webwiki-api 自带行级哈希增量）。
- `server.py`
  - 用资料站 venv 启动 `uvicorn app.main:app`（127.0.0.1）。
  - 内置 `ThreadingHTTPServer` 静态站：服务 `webwiki/dist`，history 路由回退 `index.html`，`/api`、`/uploads` 反代到后端；不需要 nginx。
  - 只监听回环地址；停止时依次关闭静态站与后端（Job Object 兜底）。

### 2. 新增页面 `src/gui_qt/pages/localwiki.py`

- 状态卡：GitHub 登录、两个仓库提交、腾讯文档库更新时间/行数、本地服务 URL。
- 按钮：登录 GitHub / 拉取代码 / 安装依赖 / 同步腾讯文档 / 构建前端 / 启动服务 / 打开网站 / 停止服务 / 打开目录 / 一键部署。
- 登录后才允许「拉取代码」「一键部署」；未登录有明确提示。
- 腾讯文档预览：下拉选择文档并用系统浏览器打开；可跳转腾讯文档监控页。
- 目录 / 端口可改；运行日志实时滚动；启动后自动打开浏览器可勾选。
- 注册到侧栏「🧰 本地工具」与首页信息工具入口。

### 3. 腾讯文档修订记录增量

- 去重键改为 `(doc_key, rev, sub_rev, author_uid)`：同修订号不同编辑人不再互相覆盖。
- 默认增量：从第 1 页开始翻，遇到「修订号 + 编辑人 + 时间」都与本地一致的记录即停止；同版本不同编辑人全部保留。
- 新增「♻ 全量重拉」按钮，需要重建时翻完全部页面。
- 增量写库时逐条校验内容：完全一致不重复插入，内容变化则更新时间/昵称。
- JSON 快照改为从完整库导出，增量拉取不会把历史导出文件覆盖成只有本次几条。
- 增量无新增时跳过 JSON / Excel 重写，避免每次重写几万行。

## 追加：GitHub 登录改为账户密码 + 识别本机账户

用户反馈设备码扫码流程不好用，改为：

- 打开登录框先自动识别本机 GitHub 账户：
  - `git credential fill`（Git Credential Manager）读取 `github.com` 凭据；
  - 兜底读 `~/.git-credentials`；
  - 拿到 Token 后调用 GitHub API 校验，显示 `@登录名` 与来源，可一键「使用此账户登录」。
- 手动登录改为「账户 + 密码 / Personal Access Token」两个输入框。
- GitHub 自 2021 年起停用账户密码做 Git / API 认证，密码框实际必须是
  Personal Access Token（`ghp_…` / `github_pat_…`）；填真实登录密码会返回 401，
  界面会明确提示，不会静默失败。
- 移除设备码 / 二维码相关代码与 `webwiki_github_client_id` 配置键。

验证：本机 GCM 识别到 `@xinmuxinmu`，Token 校验通过；手动登录与识别登录共用同一保存路径。
