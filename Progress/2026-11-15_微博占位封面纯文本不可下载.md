# 微博占位封面纯文本条目直接标记不可下载（2026-11-15）

## 问题

- 资产页里「生日动态」等无图文微博条目仍显示「重新下载 / 下载封面」按钮；
- 点击后才提示「此条目无可下载图片（raw json 无 pics 且无封面）」；
- 用户反馈：无图文的应该直接报为不可下载。

## 根因

- `_item_is_text_only` 把非空 `cover_url` 一律视为可下载媒体；
- 微博生日/活动自动帖的封面是 `pc.us.sinaimg.cn` 下的卡片占位图，raw 数据里没有
  `pics / pic_ids / live / 视频源`，因此没有被自动加入「不可下载」标记；
- 列表按钮按「未标记不可下载 + 有封面」显示，点下去才发现没有真实媒体。

## 方案

- `_item_is_text_only` 增加占位封面例外：微博条目的封面域名是
  `pc.us.sinaimg.cn` 时，不把封面算作可下载媒体，继续按 pics/live 数量判定；
- 真实封面（`wx*/ww*.sinaimg.cn`、本地封面路径等）行为保持不变，
  避免把有真实封面图的条目误判为纯文本。

## 改动文件

- 修改：`src/gui_qt/pages/asset.py`（`_item_is_text_only`）

## 验证

- `python -m py_compile src/gui_qt/pages/asset.py` 通过。
- 判定用例 7 组：
  - 微博生日占位封面 → 纯文本（True）
  - 微博真实封面 / 本地封面路径 / 有图 / 有视频 → 非纯文本（False）
  - B站仅封面、抖音有 ID → 非纯文本（False）
- 扫描 5123 条微博记录：仅 3 条占位封面自动帖
  （`20220526_weibo_untitled`、`20230526_weibo_untitled`、`20260607_weibo_untitled`）
  会被标记为不可下载；其余 620 条带真实封面的条目不受影响。
- `AssetPage` 离屏实例化通过。
