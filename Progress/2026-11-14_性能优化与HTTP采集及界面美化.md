# 2026-11-14 性能优化、HTTP 采集与界面美化

## 需求与范围

在保留工具箱功能的前提下检查和优化性能；核实各平台是否可以减少 Playwright 和手工登录依赖；改善桌面界面的观感。

本轮保持平台数据模型、功能入口、文件格式、数据库表结构及正常采集结果的兼容性。异常路径补充了回退、取消和资源释放处理。所有回归数据为合成输入或临时库，公开接口验证使用独立匿名会话。

## 已完成的性能优化

| 位置 | 原问题 | 调整与验证 |
| --- | --- | --- |
| `src/media_downloader.py` | Range 探测只需要响应头，却使用完整读取正文的 `httpx.get`；服务器忽略 Range 时可能在正式下载前额外读取整个视频/模型 | 使用流式请求上下文，仅取响应头即关闭。保留状态码、超时、跳转和失败返回；离线大文件声明测试确认正文未被读取 |
| `src/gui_qt/pages/info_accounts.py` | 逐条揭示结果使用 `list.pop(0)`，大队列反复搬移剩余元素 | 改为 `deque.popleft()`；FIFO、重复项处理、旧轮结果、150ms 显示节奏保持一致 |
| `src/gui_qt/pages/info_results.py` | 同一条数据在排序和渲染时各解析一次日期 | 仅在本次刷新内复用解析结果。150 条数据调用次数 300 → 150；改动前后排序、并列顺序、文本、勾选、滚动和离屏像素一致 |
| `src/image_sorter/core/sqlite_cache.py` | 已分类 MD5 批量写入在自动提交模式下逐条提交 | 批量使用一次事务，其余单条写入保持自动提交。5000 条完整方法交替执行各 5 次，中位数约 0.196s → 0.020s，约 10 倍；逐行值一致 |
| `src/toolbox/tcdoc/storage.py`、`tables.py` | SQLite 连接上下文提交/回滚后没有主动关闭，依赖垃圾回收 | 增加 `closing`，先提交/回滚再关闭；结果已完整读取后返回。覆盖正常路径、异常路径、旧库导入、补列、增删改和部分同步 |
| `main.py` | `QTimer.singleShot` 延后的 FFmpeg 检测依然在主线程同步等待，最坏阻塞 5 秒 | 探测放后台，原提示及浏览器检查在主线程继续；7 种成功/失败场景的提示和顺序一致，等待期间 Qt 心跳持续运行 |

MD5 批量异常时现在整体回滚，避免留下半批标记；这是事务优化带来的异常状态调整。上述耗时是本机合成数据基准，不代表所有设备或整个应用的提速比例。

## HTTP 采集检查与改动

HTTP 与免登录是两回事：Cookie 可以表示登录状态，也可以只是站点通过 HTTP 自动发放的游客票据。实际链路表已同步到 README 的“各平台的 HTTP 与浏览器回退”。

- **微博账号追踪**：普通游客资料请求被拒时，复用已有访客通行证方法取得临时 SUB/SUBP，再通过 HTTP 请求同一个资料接口。保持原字段和精确计数补齐；随后依次为已启用 Cookie HTTP、原游客浏览器。游客成功时不读取存档 Cookie。
- **抖音账号作品**：修正登录态分支，Cookie HTTP 失败后会尝试一次游客 HTTP；无 Cookie 时不会重复同一游客 HTTP。保留浏览器末级回退、翻页、数量限制、限流、逐条回调与取消。失败阶段保留已收到的条目供最终兜底，同时继续后续回退争取补足目标条数。
- **抖音追踪**：游客 HTTP、已启用 Cookie HTTP 都失败后才启动原浏览器；各层异常不会跳过后续回退。
- **抖音昵称**：修正空串游客态被 `filter(None, ...)` 过滤的问题。使用轻量资料 HTTP 查询和同一会话取得游客票；失败后仍可用 Cookie HTTP 和作品列表回退。
- **小红书追踪**：统一 HTTP 失败分支的三元组返回，修复非 200 / 页面解析失败时解包异常阻断 Cookie 回退的问题。

匿名实网验证：

| 项目 | 结果 |
| --- | --- |
| 微博公开账号资料 | 仅首页游客票时 `ok=-100`；自动临时游客票后同接口 `ok=1` |
| 改后微博追踪完整入口 | 返回原有 14 个字段；粉丝/关注/微博数/获赞均为整数；存档 Cookie 读取 0 次、浏览器调用 0 次、创建的 Session 全部关闭 |
| B站公开账号 card 接口 | HTTP 200、`code=0`，有账号资料 |

适用边界：

- B站已有 HTTP 主链，账号列表的已存 Cookie 优先策略用于避免游客接口遗漏最新内容，保留。
- 快手主页作品仍依赖浏览器指纹/签名；账号指标虽用 HTTP GraphQL，通常仍需要网页设备 Cookie。
- 抖音部分详情仍有浏览器依赖；`a_bogus` 的 Node.js 签名依赖保留。
- 小红书主页现有实现只读取首批内嵌数据，不能把它描述为全量翻页采集。
- 音乐平台已有 HTTP 主链，浏览器还承担失败回退或缺失字段补齐；腾讯文档日常指标/表格同步也已使用 HTTP，需要权限的内容仍要登录态。
- 其他平台的全量、登录后采集没有使用真实用户凭据实测；保留其既有能力并通过隔离路由检查。

## 界面调整

仅调整 `src/gui_qt/theme.py`、`main_window.py`、`pages/home.py` 的外观：

- 统一蓝色交互强调、浅色背景和深蓝灰暗色背景；提高次级文字与卡片的层次。
- 导航采用独立背景、轻量悬停和选中指示；功能入口、分组顺序和点击路由保持原状。
- 首页统一标题、指标、图表和工具卡片的间距与圆角，工具卡片增加方向提示。
- 图表使用当前调色板，窄窗口给图例预留文字宽度；导航图标补充局部字体回退。
- 明确按钮、输入框、标签页、复选框、单选框的选中与禁用状态，恢复原生勾号/圆点。
- 保留一次加载 QSS、通过调色板快速切换主题的机制。

真实 Qt 离屏检查包含浅/深主题、1120×700 默认尺寸、880×560 最小尺寸、导航与首页全部路由、主题往返切换及控件状态。首页截图使用固定合成数据（4,286 条），不代表真实采集量。
