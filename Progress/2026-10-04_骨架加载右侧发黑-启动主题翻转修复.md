# 2026-10-04 骨架加载右侧发黑（启动主题翻转）修复

## 现象

启动应用进入骨架加载页时，右侧内容区出现大片深色（实测 #1a1d27，深色主题的
Window 色，视觉近黑），与界面主题不一致；骨架灰块反而显示为白色。用户系统为
浅色模式，期望整个骨架屏与浅色界面一致。

## 根因

启动时序中存在一次「构造后、显示前」的调色板翻转：

1. 用户配置 `theme=dark` + `theme_follow_system=True`，Windows 系统为浅色。
2. 旧启动序（main.py）：
   - `apply_theme(app)` → 应用深色 QPalette（Window=#1a1d27）
   - `MainWindow.__init__`：`SkeletonPage` 在**深色调色板下构造**，灰块/文字色
     在构造时从 palette 读出并写死进内联样式（块 #23262f）
   - 紧接着 `_check_theme_schedule()` 同步执行启动对齐：跟随系统 → 
     `set_theme("light")` + `app.setPalette(浅色)` + `retheme_all`
3. **关键机制**：`app.setPalette()` 对「已构造但尚未 show 的控件树」不生效——
   进程内探针实测：翻转发生在 0.53s，窗口 0.9s 显示，**1.58s 时骨架/导航控件
   的 palette 仍是 #1a1d27**；而 `retheme_all` 只重映射内联样式（骨架块
   #23262f → #ffffff 白色）。
4. 渲染结果：深色底（残留调色板）+ 白色块（已重映射的内联样式）+ 导航也残留
   深色 → 用户看到的「右侧发黑、与界面不一致」。

反向配置（theme=light + 系统深色）同样触发（浅底+深块的镜像混合态）。

## 修复（main.py 一处）

把「跟随系统/定时对齐」从 `MainWindow.__init__` 的 `_check_theme_schedule`
提前到 **首次上色之前**（任何控件构造之前），启动全程只应用一次主题：

```python
theme.init_theme()
theme.install_auto_remap()
# 跟随系统/定时对齐必须在首次上色前完成（只改内存态+配置，不碰 UI）
theme.check_auto_switch()
theme.apply_theme(app)
```

`MainWindow._check_theme_schedule`（main_window.py 231 行）保留：启动时已是
no-op（主题已对齐，不再翻转），运行期 10s 定时器仍走它（此时窗口已显示+打磨，
调色板传播正常，为生产已验证路径）。

## 验证（进程内打点探针：patch set_theme/apply_theme + grab 渲染采样）

**场景一：用户配置（theme=dark + 跟随系统浅色）**

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 主题应用次数 | 2 次（0.32s 深 → 0.53s 构造途中翻浅） | 1 次（0.37s 对齐后直接浅色） |
| 骨架控件 palette | #1a1d27（残留深色） | #f4f5f7（与应用一致） |
| 渲染采样 | 深底 #1a1d27 + 白块 #ffffff 混合 | 全浅色系（#f4f5f7/#eef0f4） |

**场景二：纯深色（follow_system=False, theme=dark）**

无翻转、单次深色应用，骨架全深色一致（nav=#1a1d27、块=#23262f），无白块。

## 教训

- **`app.setPalette()` 对尚未显示的控件树不生效**（Qt 应用级调色板传播的坑），
  且 show 之后也不会补解析；任何「构造中途改主题」的时序都会产生混合态。
  主题对齐逻辑必须发生在**首次上色之前**。
- 排查手段：进程内打点（monkey-patch set_theme/apply_theme 记录时间线）+
  `win.grab()`（控件树渲染）与 `grabWindow`（真实合成画面）双重采样对比，
  比猜测可靠得多；`grabWindow` 抓全屏存在遮挡窗口/坐标系混用陷阱。
- **offscreen 最小复现与真实 Windows 平台行为不一致**（offscreen 下隐藏期
  翻转后 show 会重解析调色板，真实平台不会）——结论必须以真实平台探针为准。
