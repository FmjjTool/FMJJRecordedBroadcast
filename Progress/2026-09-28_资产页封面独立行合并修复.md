# 资产页「xxx封面」独立行合并修复（2026-09-28）

## 问题

同一条内容在资产页分成两行：正文条目（有播放/点赞数据）+「xxx封面」独立行（播放0 赞0，🖼1）。
小红书、快手、抖音、微博全中招（用户反馈截图：快手「那就珍惜当下吧」、小红书「喜欢却不是谁的错」等）。

## 根因

`_parse_media_name` 解析媒体文件名 `{date}_{author}_{title}[_封面].ext` 时：
- 只剥末尾的**序号/live 序号**段，不剥 `封面` 段
- 分组键 = `_sanitize_title_key(title_key)[:20]`（净化会删掉 `_` 和所有符号）

于是正文媒体组键 = `标题`，封面组键 = `标题+封面`——**短标题（净化后 <20 字符）时两者不同组**；
json 匹配每条只弹出一个组（match 后 break），正文组先命中（`.mp4`/`.jpg` 按文件名排序在前），
封面组永远落单 → 作为「无 json 媒体」生成播放0赞0 的独立行。

长标题（≥20 字符）时封面键被 `[:20]` 截断后与正文同键、侥幸同组——所以只有部分条目分裂。
实测 109 条中有 23 条封面独立行；另有标题 19 字符时封面键截断成 `标题+封` 的边角情况。

B站不受影响：B站封面是 `{stem}.jpg` 与视频同名（`_backfill_bili_covers` 生成），天然同组。

## 修复

`_parse_media_name` 末尾追加一段：`while rest and rest[-1] == "封面": rest = rest[:-1]`
——封面文件与正文媒体归入同一组，json 弹组时一并带走。
