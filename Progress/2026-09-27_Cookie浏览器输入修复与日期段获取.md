# Cookie 登录浏览器可输入修复 + 日期段获取（2026-09-27）

## 任务一：Cookie 登录浏览器无法输入（修复·v2 最终方案）

### 现象
Cookie 管理弹出的登录浏览器里可以点击但完全打不了字（淘宝手机号、5sing 账号密码等登录框都输不进去）。用户带着第一版修复（AttachThreadInput）实测仍无法输入。

### 排查过程（三轮递进，均端到端实测）
| 尝试 | 结果 |
|------|------|
| ① AttachThreadInput 合并输入队列 + SetFocus | 焦点确实落到浏览器窗口，但 Chromium 按键仍被丢弃 |
| ② 补发 WM_ACTIVATE/WM_ACTIVATEAPP + 延迟回压焦点 + 激活事件过滤器 | 焦点稳定在浏览器上，但普通 VK 按键仍进不了页面 |
| ③ **无边框顶层贴合（最终）** | **PASS：键盘字符精确进入页面输入框** |

### 根因
浏览器窗口作子窗口嵌入对话框后，Windows 不再向它发送激活消息（WM_ACTIVATE/WM_ACTIVATEAPP），Chromium 据此判定窗口「未激活」而**主动丢弃键盘输入**——这不是焦点/输入队列问题（①② 已把焦点真正送到位），是 Chromium 内部的激活状态检查，消息补发绕不过去。

### 最终方案（`src/gui_qt/cookie_manager.py`）
放弃子窗口嵌入，改为**无边框顶层贴合**：
- 浏览器保持顶层独立窗口（去 WS_CAPTION/WS_THICKFRAME + WS_EX_TOOLWINDOW 不进任务栏/Alt-Tab），贴在对话框页签区上——视觉等同内嵌，键盘输入原生可用
- `_reposition`：贴到 host 的全局物理矩形（host 设 WA_NativeWindow 取原生句柄，免 DPI 换算），150/400/1000ms 定时回贴
- `_FollowFilter`：对话框移动/缩放/激活时保持贴合，最小化时跟随隐藏、还原时回贴
- 「⌨ 改独立窗口」保底按钮：恢复标题栏变普通独立窗口（可拖动缩放）
- `_cleanup`：关闭对话框时隐藏浏览器（Playwright 收尾关闭进程）

### 端到端验证（真窗口实测，模拟真实用户操作）
- 浏览器矩形与 host 矩形完全对齐（±2px 内）——视觉内嵌成立
- 点击页面后浏览器成为前台窗口（真实激活链，fg_is_browser=True）
- 键盘注入字符精确进入页面输入框：输入框读回 'fmjj77'
- 测试结论附带：中文 IME 会拦截 VK 合成按键（验证需用 VK_PACKET Unicode 注入），真实物理键盘不受影响
- 临时测试脚本与 html 已清理

## 任务三：浏览器登录「无法保存登录信息」排查（2026-09-27 午后）

### 现象
用户报告浏览器登录后无法保存登录信息。查 cookies.json：最后写入时间为 9月25日 19:40（taobao/weibo），当天所有登录尝试全部未落库。

### 根因（两个叠加）
1. **快手页当时 DNS 解析失败**（用户首报 ERR_NAME_NOT_RESOLVED）：机器配有本地代理（127.0.0.1:11119），代理开启时 Chromium 走系统代理导致国内站解析失败；而应用其余采集器全部 requests 直连不受影响——登录浏览器与采集器网络路径不一致
2. **页面加载失败后登录对话框残留**：worker 异常只弹「浏览器启动失败」，对话框留着，用户点「已获取」只会得到「尚未捕获到任何 Cookie」，看起来像"保存坏了"

### 修复（`src/gui_qt/cookie_manager.py`）
- 登录浏览器 launch 加 `--no-proxy-server`（全部为国内站点，直连即可；与 app 其余采集器保持一致，杜绝代理开启时 DNS 失败）
- `_fail`：弹「浏览器启动失败」确认后 **dlg.close() 自动关闭**，不再留僵尸对话框

### 验证（两阶段实测）
- A：模拟启动失败 → 弹窗自动确认 → 登录对话框 1s 内自动关闭 ✅
- B：真实浏览器（含 --no-proxy-server）→ 贴合正常 → 4s 捕获 9 Cookie → 点击「已获取」→ set_cookie 正常调用（687 字符）→ 对话框关闭 ✅（auth.set_cookie 测试内拦截，未写真实 Cookie 库）
- 附带：快手/5sing/抖音 goto 复测全部正常（0.6~2.6s）；保存链路代码本身经全流程实测完好——问题全在「页面加载不出来→没登录→没东西可保存」
- 测试残留 Edge 进程已清理（用户自己开着的 Edge 未动）

## 任务二：日期段获取（按发布时间过滤）

### 需求
账号获取增加按日期段获取模式：从某日期到某日期、或从头开始到某日期，用日历表选择。

### 实现
| 文件 | 改动 |
|------|------|
| `src/gui_qt/pages/info_accounts.py` | 策略行新增「📅 日期段」按钮；`_show_date_range_dialog` 日历对话框（两个 QCalendarWidget 并排 + 开始/结束「不限」勾选）；`_parse_publish_ts`/`_date_bound_ts`/`_filter_posts_by_date` 模块级辅助；worker 接入过滤 |
| `src/toolbox/config_manager.py` | 默认配置加 `fetch_date_start`/`fetch_date_end`（load 只返回默认表内键，不加会被静默丢弃——发布 2.8.10 纠正时 taobao_verify_seller_id 已踩过） |

使用方式：
- 点「📅 日期段」→ 日历点选开始/结束日期（或勾「开始不限(从头)」「结束不限(到现在)」）→ 确定
- 按钮实时显示当前范围（如「📅 日期段: 09-01 ~ 09-20」），配置持久保存
- 获取时日志显示「日期段过滤已启用: …」，每账号显示「日期段过滤: N → M 条（范围外 X 条）」
- 手动获取与定时获取共用同一过滤；开始=当天 00:00:00，结束=当天 23:59:59
- 时间解析：绝对（2026-09-27 14:30[:59]、2026/9/27、2026年9月27日）+ 相对（刚刚/X秒/分/小时/天/周/月前、今天/昨天/前天）；**解析失败的条目保留**（宁多勿漏）

### 验证
- 单测：时间解析 10 组（绝对/相对/乱码/空）、边界（00:00:00/23:59:59）、过滤 4 组（含仅上界、仅下界、解析失败保留、无范围原样）、配置 round-trip、按钮文案状态机——全过
- 端到端真实采集：B站 1470981 设「从头 ~ 2026-09-25」获取 8 条，全部落在范围内（2025-08-16 ~ 2026-09-22），无泄漏；测试导出的 24 个文件已清理（68 个原有文件未动），collected.json 已恢复
- cookie_manager 模块导入冒烟通过

端到端测试的 8 条 B站帖子经 `_collect` 进了增量 SQLite 库（真实公开数据，属正常采集行为，不影响功能）
