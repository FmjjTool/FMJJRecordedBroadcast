## 根因一：图集被当视频（9 图只下 1 张）
- `douyin.py` 三处结果构建器（API/页面/Playwright）都不识别图集：`aweme_type=68`
  或"有 images 且无 bit_rate"的笔记，其 `video.play_addr` 是**背景音乐 mp3**，
  被当视频链接返回 → 下载器只下到封面
- 修复：新增 `DouyinParser._note_images()` 判定；三处构建器统一接入
  （kind=note、video_url 置空、images 带全部直链）；Playwright 构建器复用同判定
- `download_ops.refresh_douyin_urls`：图集回填 images、清掉 mp3 残留 video_url
- 解析面板（common.py）显示"图文/笔记"和图片张数；已获取页 [图文] 标签认 kind=note

## 根因二：搜索页弹窗链接整条链失效（获取全空 + 下载 0 文件）
新链接形态 `douyin.com/search/关键词?...&modal_id=xxx`（旧代码只认 /user/ 弹窗）：
1. `URLRecognizer` 不匹配 /search/ → `parse_url_info` 走 parse_video 兜底
2. `_get_video_id` 按路径末段取 ID → 取到的是**搜索关键词**（日志实锤：
   `aweme_id=%E4%B8%89%E8%A7%92%E6%B4%B2...` = "三角洲表情包"）→ 接口必然空详情
3. 空数据被包装成 VideoInfo 报"获取成功"→ 入已获取列表 + 下载 0 个文件误导用户

修复（四处）：
- `base.py` URLRecognizer：douyin 模式补 `douyin\.com/search/`
- `douyin.py _normalize_url`：/search/ 弹窗同 /user/ 一样重写成 /video/{modal_id}
- `douyin.py _parse_once`：页面解析失败后插入 **aweme/detail + a_bogus 兜底层**
  （游客→Cookie 内部自动兜底，比 Playwright 轻；风控期实测最可用，图集也只这条链
  拿得到完整 images；Playwright 降为最后手段）；新增 `_build_from_parsed_dict`
  统一转换（/note/ 分支同步复用）
- `douyin.py _parse_from_page`：页面无作品数据（video_info 空）一律返回 None，
  不再用 og:title/<title> 造空壳
- `multi_downloader`：`_get_video_id` 支持 modal_id query；`_parse_douyin` 对
  非纯数字 aweme_id 直接报错（不再发无效请求白打风控计数）；返回值带 raw_data
- `download_ops.parse_url_info`：空壳拒绝（无标题/作者/图集/封面 → 报"获取失败"，
  不再入已获取库）；multi_downloader 兜底同校验

实测：两类弹窗链接均走 aweme/detail 拿到完整图集（39 图 / 8 图），无需启动浏览器；
无 modal_id 的搜索页、关键词当 ID 均正确报错。增量库扫描确认 douyin 表 82 行无垃圾
（空壳未污染），导出 json 也无空壳文件。

## 教训
- 弹窗链接 ID 在 query（modal_id），路径末段是搜索关键词——**取 ID 必须先看
  query 参数**，否则把"三角洲表情包"发成 aweme_id 还白打两次无效请求
- "获取成功"必须以**内容字段**为门槛（标题/作者/图集/封面），页面级 og:title
  造出的空壳会一路穿透展示、入库、下载全链路
- 抖音单作品解析链顺序：页面 → aweme/detail（轻、带签名、Cookie 兜底）→
  Playwright（重、风控期常挂）——重浏览器永远最后
