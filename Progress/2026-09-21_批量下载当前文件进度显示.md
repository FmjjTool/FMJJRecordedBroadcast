# 批量下载显示当前文件进度（2026-09-21）

## 问题
资产管理「全选 → 下载所选」批量下载时，总进度条只有条目级计数（`批量下载 2/15 标题`），当前文件（视频流/图片）的下载进度完全不显示——大文件下载期间界面像卡死，不知道实际情况。

## 根因
批量下载以 `quiet=True` 调用子下载函数，而子下载函数在 quiet 模式下把 `byte_progress_callback` / `progress_cb` 全部传 `None`（原设计只有单条下载弹独立进度框），子进度根本没上报渠道。

## 修复方案
子下载链路新增 `sub_bridge`（进度桥）+ `cancel_ev`（取消事件）参数，批量模式把总进度条的信号桥和取消事件一路传下去：

### 1. `_batch_download_checked`（总控）
- 新建 `sub_bridge = _ProgressBridge()`，`updated` 信号连接总进度条标签：
  - 视频流字节进度（total > 100000）→ `批量下载 2/15  标题  ⬇ 5.0/45.0 MB`
  - 图片/live 文件计数 → `批量下载 2/15  标题  ⬇ 文件 3/12`
- 批结束时 disconnect，防对话框关闭后残留信号

### 2. 下载链路（`asset.py` 四个方法）
- `_download_for_item` / `_download_bilibili_item` / `_download_video_item` / `_download_images_for_item` 均加 `sub_bridge=None, cancel_ev=None` 参数
- quiet + sub_bridge 时：本地 bridge 替换为 sub_bridge，进度直接上报总进度条
- 字节回调从 `if not quiet else None` 改为始终传 `bridge.emit_bytes`（无监听时发射空信号，无害）
- `cancel_ev = cancel_ev or threading.Event()`：批量取消事件贯通到 `download_media`，点「取消」能真正中断当前文件（图片/抖音/微博视频；B站 ffmpeg 拉流不支持中断，跑完当前条目后停）
- 单条下载（非 quiet）路径行为不变

## 验证
- `py_compile` 通过
- offscreen 信号测试：字节进度 → `批量下载 1/15 初次约会… ⬇ 5.0/45.0 MB`；文件计数 → `⬇ 文件 3/12`；空信号忽略
- 所有调用点均关键字传参，新增参数向后兼容
