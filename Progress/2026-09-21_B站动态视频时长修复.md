# B站动态视频时长修复（2026-09-21）

## 问题
B站动态视频（t.bilibili.com）在资产页完全没有时长显示，明明本地已下载视频。

## 根因
B站动态的原始 json 中，视频时长只有文本格式 `duration_text`（如 `'00:53'`），`duration` 字段为 null。采集端（BilibiliParser 的 `MAJOR_TYPE_ARCHIVE` 分支）此前只读了 `duration`，从未提取 `duration_text`，导致 json「时长」字段为空。

## 修复（三处兜底）

### 1. 采集端 — `src/platforms/bilibili.py`
`MAJOR_TYPE_ARCHIVE` 分支补上 `duration_text` 提取：按 `:` 拆分，`MM:SS` / `H:MM:SS` / 纯秒均换算为秒，写入 MediaItem 的 `duration` → 导出 json「时长」字段（新采集数据直接有值）。

- 修复过程中发现并修正一处切片 bug：乘数列表应取 `[1, 60, 3600][:len(vals)]`（循环从 vals 尾部配对 秒/分/时），原 `[-len(vals):]` 会把 `00:53` 算成 3180 秒。

### 2. 存量数据兜底 — `src/gui_qt/pages/asset.py`
`_load_disk_items` 扫描时，json 条目若「时长」为空但本地有视频文件 → 新增 `_probe_video_duration()` 用 ffprobe 读本地视频实际时长（带 mtime 缓存，避免每次扫描重复探测；ffmpeg 缺失/失败静默返回 0）。

### 3. 独立媒体条目 — `src/gui_qt/pages/asset.py`
无 json 的纯视频独立条目（download 里散落的视频文件）同样用 `_probe_video_duration()` 补时长，详情页可见。

## 配套显示
详情对话框时长行用 `_fmt_duration_cn`（两位中文格式：`53秒` / `01分19秒` / `01时02分03秒`），解析自 json「时长」字段 `_parse_duration_text`（兼容 `M:SS` / `H:MM:SS` / 纯数字秒）。

## 验证
- `00:53→53s`、`01:19→79s`、`1:02:03→3723s`、`0:00:30→30s`、空/None→0，全部通过
- 真实视频 ffprobe 实测：`少司缘一分钟…mp4→78s`、`初次约会….mp4→166s`，正确
- 两个文件 `py_compile` 语法通过
