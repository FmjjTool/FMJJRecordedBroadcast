## 直播录制：录制完成后写容器时间码（tmcd 轨）

### 需求

### 处理方案

- 新增 `src/toolbox/timecode.py`：
  - `parse_start_time()` 从文件名解析录制起点（`主播_20261116-183009.ts` / `日期_时-分-秒` / `日期_时分秒`），非法日期返回 `None`；
  - `probe()` 用 ffprobe 取帧率/时长/编码；`is_segment_file()` 识别 `_001` 分段；
  - `write_timecode()` 用 `ffmpeg -c copy` 重封装为 mp4，`-timecode HH:MM:SS:00` 写 tmcd 轨，`-movflags +faststart`；音轨不兼容 mp4 时仅把音频转 AAC 再试一次，视频始终不重编码；写后读回 tmcd 轨的 `timecode` 校验，失败不留半成品。
- 界面：`live_record_window.py` 工具栏「FLV 修复」旁新增「写时间码」，菜单「工具 → 写时间码…」，弹出 `TimecodeDialog`：源文件、起始时间（默认取文件名）、输出文件（默认同目录 `_时间码.mp4`，重名自动加序号）、覆盖开关、日志与状态；后台线程执行，信号回主线程更新。
- 文档：`software-feature-guide` 直播录制章节补「工具 → 写时间码」。

## P1：录制时间轴锚点（墙钟 ↔ 视频时间）

### 需求

- 在 P2（写容器时间码）之后补 P1：录制时记录首帧墙钟与视频 PTS 的对应关系，供弹幕对齐与写时间码使用，精度目标 <0.5 秒。

### 处理方案

- 新增 `src/toolbox/timeline.py`：
  - `TimelineRecorder` 每场录制写 `<视频主干>_时间轴.json`，结构 `{version, platform, room, base, created, files:[{file, anchors:[{pts_ms, wall_ms}]}]}`，每加一条锚点立即原子落盘（崩溃不丢，写失败不影响录制）；
  - `video_ms_for_wall()` / `wall_ms_for_video()` 分段线性换算：两条锚点之间按 PTS 增量截断，断流停顿段不外推（画面停在原处）；
  - `start_datetime()` 取首帧锚点，供「写时间码」当起始时间。
- 采集端接线（`live_record.py`）：
  - `FfmpegRecorder` 新增 `on_media_start(wall_ms, file, pts_ms)`：TS 管道模式在写入第一段字节时回调（精确到秒内）；直写 FLV / 分段模式用 1 秒轮询输出文件，出现即记锚点（误差 ≤1 秒）；分段文件各自 pts 从 0 起算；
  - `StreamDownloader` 在每段文件真正写入首批字节时回调；
  - `RecordManager.start_record` 建时间轴并注入回调，断流续录时以 `-output_ts_offset` 为 pts 追加新锚点。
- 「写时间码」联动：起始时间优先取时间轴首帧锚点，没有时间轴才退回文件名时间；对话框选中文件时打印「已读到录制时间轴（首帧锚点）」。

### 验证结果

- `python -m compileall -q src tests` 通过。
- 新增 `tests/test_timeline.py` 9 项：文件名/读写/空文件/坏 JSON、暂停段映射（不外推）、正反换算、未知文件、`FfmpegRecorder` 首帧回调（真实 ffmpeg 管道，回调墙钟与当前时间差 <60 秒、pts=0、文件非空）全部通过。
- 全量离屏测试：**515 项全部通过**。
- 联调：给 3 秒 ts 写一条首帧锚点后，`TL.video_ms_for_wall(锚点+5s)=5000`；`write_timecode()` 自动改用时间轴时间（日志显示「起始时间取自录制时间轴（首帧）」），读回 tmcd 一致。

## 直播录制：录制 / 监控中关闭窗口与退出软件的保护

### 需求

- 用户截图（直播录制窗口，1 场录制中 + 监控运行中）要求：录制过程中或监控中，关闭页面或软件都要弹窗确认；直接关闭可能损坏文件；点确认后逐步关闭录制并开始打包。

### 处理方案

- 新增 `src/toolbox/live_shutdown.py`（不依赖 Qt）：
  - `collect_segments()`：按场次主干收集全部分段（`主播_时间.ts`、`_001.ts`…），跳过 0 字节文件；
  - `package_file()`：单文件直接 `-c copy` 重封装成 `<主干>_打包.mp4`，多分段用 concat demuxer 合并后重封装（不重编码，`+faststart`）；
  - `output_path()`：重名自动加 `_2`，音轨产物（.m4a/.aac/.mp3/.wav）保持原后缀；
  - **不删改原始录制文件**；找不到 ffmpeg / 打包失败时返回原因并保留原文件；`package_many()` 按场次去重。
- `gui_qt/live_record_window.py`：
  - 新增纯函数 `collect_activity(panes)` 汇总「录制中（含输出路径）/ 监控中」；
  - `activity()`、`confirm_shutdown()`、`stop_and_package()`：关闭窗口时弹确认框（录制中明确写「直接关闭可能损坏文件（丢文件尾、打不开、花屏）」），确认后先 `stop_monitor()`，再逐个 `stop_record()`（等 ffmpeg 收到 q、写完文件尾），最后调 `live_shutdown.package_many()`，用模态进度条显示「正在停止 … / 打包 …」，失败清单单独提示；
  - `closeEvent` 改为走 `confirm_shutdown()`，取消则 `event.ignore()`。
- `gui_qt/main_window.py`：
  - 后台模式（关闭到托盘）下有录制 / 监控时弹三选一：「隐藏到托盘继续录制」/「停止录制、打包并退出」/「取消」；无录制时同样可隐藏继续监控；
  - 未开后台模式：关闭即退出，先确认「停止并打包后退出」；
  - 托盘菜单「退出」先 `stop_and_package()` 再走原清理流程，不再静默杀录制。
