# 2026-11-21 抖音表情包并入「采集工具」（第 4 个页签）

## 需求与判定

用户要求：「直播录制-弹幕姬里面的抖音表情包放到采集工具里面去（第四个 tab）」。

- **搬家而非复制**：原「抖音表情收集」是非模态二级窗口，入口在弹幕姬抖音页工具栏。按用户原话把它并入侧栏「内容采集 → 采集工具」容器，作为第 4 个页签；弹幕姬页工具栏的「表情包」按钮与独立窗口一并下线，避免两套入口。
- **不新建侧栏页、不新建管理器**：它只是采集工具容器内的一个功能面板（L2 页面内面板），数据来源仍是 `toolbox/douyin_emoji.py`，没有第二套业务逻辑，不符合约定 12 的「管理器 / 中心」条件，因此只登记为容器页签。
- **实时来源不断线**：窗口改成页签后不能依赖「本页 = 弹幕姬页」的 `page.emoji_sink`，改为弹幕姬抖音页把 rtf 片段喂到 `app.douyin_emoji_sink`；采集工具页构造后注册、`shutdown` 注销，切走页签也继续收，关掉弹幕姬窗口（连接保持后台）同样有效。B站弹幕页不喂，避免 B站表情混入抖音表情包。
- **导出目录收敛**：功能页不放开输出目录（项目硬性偏好），去掉原窗口的目录输入与「选择…」，固定跟随全局统一导出目录的 `抖音表情包` 子文件夹，另给「打开目录」按钮；仍保留原格式（webp/gif/png）与同名 `_2` 序号。

## 反馈修复：去重漏掉 CDN 域名

用户实测「本地弹幕包」补收 48 个表情，截图里大量看起来重复，问「没有去重吗」。

- 真因：抖音同一张表情会在 `lf3/lf5/lf6-webcastcdn-tos.douyinstatic.com`、`p3/p11-webcast.douyinpic.com` 之间轮换下发，路径完全相同；旧去重键「去掉 `?` 签名」保留了域名，于是同一张图被当成 3 份。样本 `582775732015_20261024.jsonl`：95 个 rtf 图片片段 → 48 个不同 URL，但只有 **28 个不同 path**（14 个 path 分布在多个 CDN 域名）。
- 修复：`url_key` 改为只取 `urlsplit(url).path`（对象 key + `~tplv-` 图床样式），忽略域名与 query；path 为空时退回去 query 的整段。
- 安全性实测：同一 path 的 `lf3/lf5/lf6` 三个域名、`p3/p11` 两个域名分别下载，HTTP 200、字节数与 md5 完全一致；28 个不同 path 的内容 md5 两两不同，说明剩余不是同图。
- 结果：同一弹幕包读取 48 → **28** 项；剩余 28 张是内容不同的图（同一套猫/狗系列的不同帧），不是漏去重。该「弹幕包补收」功能已在第三轮按用户要求删除，此处只记录当时的去重结论；会员表情栏本身返回的 48 个是 48 个不同对象（不是 CDN 重复）。

## 反馈修复：未开播（已结束）拉不到会员表情

用户实测「直播已结束」的直播间（`live.douyin.com/582775732015`）点「一键拉取全部」失败，要求「直接用网络抓一次」。实测结论：

- `room/web/enter` 在本机**游客和登录态都返回 HTTP 200 + 空 body**（风控表现，项目里原有记录），旧逻辑直接报「未取到 room_id/anchor_id（直播间可能已结束）」。
- 但**未开播页面 SSR 里数据是齐的**：`"roomId":"7709824534500608818","web_rid":"582775732015","anchor":{"id_str":"78087831246",...}`，只解析 `roomStore.roomInfo.room` 拿不到 anchor（它的 owner 为空）。
- `privilege/subscribe/info` 用 SSR 的 `room_id`+`anchor_id` 实测返回 **48 个表情**；`room_id` 传 `0` 同样返回 48 个——接口只认主播 ID，与是否开播无关。
- 19 位长号 `7709824534500608818` 页面没有 anchor 段，改走 `webcast/room/reflow/info`：返回 `room.id_str` + `owner.id_str`（同为 78087831246）+ `status=4`，未开播也能拿。

实现：

| 位置 | 改动 |
| --- | --- |
| `toolbox/douyin_emoji.py` | 新增 `_page_room_ids()`（页面 SSR 正则取 `roomId` + `anchor.id_str`）与 `_reflow_room()`（19 位长号走 reflow）；`fetch_vip_emojis` 改为按「长号 → reflow / 短号 → enter → 页面 SSR」解析主播 ID，`room_id` 缺失时传 0；`describe` 兜底 `emoji_tip`、`member` 读 `is_member`；表情名优先 `text`，其次 `img.uri` 文件名（不再是清一色「表情」） |
| `gui_qt/pages/douyin_emoji_page.py` | 会员表情栏说明补「开播中、已结束都能拉」 |
| `src/skills/software-feature-guide/SKILL.md` | 会员表情栏章节改写：主播 ID 三级兜底、room_id 可传 0、不再写「固定 7 个」 |
| `tests/test_douyin_emoji.py` | 新增「enter 空包 → 页面 SSR 兜底」「19 位长号 → reflow」两条用例 |

## 第三轮反馈：只保留截图部分，断开弹幕姬，账号从账号配置取

用户给出最终形态截图（顶部「直播间输入 + 一键拉取全部」、下方表情网格、底部导出），要求：其余部分全部不要、断开与弹幕姬的链接（完全不相干）、账号从「账号与登录」已存账户拿。
