# 2026-10-12 歌曲下载自动保存对应平台封面

## 问题/需求

下载歌曲时自动下载一张对应平台的封面，保存为与音频同名的图片文件（如 `歌手 - 歌名.mp3` 旁生成 `歌手 - 歌名.jpg`）。

## 根因/方案

- 封面 URL 数据其实早已在手：四平台引擎 `SongInfo.cover_url`（各 scraper 均已填充）、网易云引擎 `MusicInfo.pic_url`，但下载流程从未将其存为独立文件——网易云仅内嵌进音频标签，四平台直接丢弃。
- 方案：
  1. 四平台引擎 `download_song` 成功后调用新增 `_download_cover`，用 `SongInfo.cover_url` 下载封面，存为与音频同名的图片（扩展名跟随 URL，缺省 `.jpg`）；已存在跳过；任何失败静默，不影响歌曲下载主流程。
  2. 网易云引擎封面字节只下载一次：新增 `_fetch_cover_bytes`/`_ensure_cover_file`，字节同时用于标签内嵌（MP3 APIC / FLAC Picture / M4A covr）与另存独立文件；文件已存在的旧下载补齐封面文件。
  3. GUI 批量下载兜底构造 `SongInfo` 时补传 `cover_url=picUrl`（此前该字段被丢弃，换源/重名构造路径拿不到封面）。

## 改动文件清单

- `src/music/downloader.py`：新增 `_download_cover`；`download_song` 成功后触发封面下载
- `src/netease/music_downloader.py`：新增 `_fetch_cover_bytes`/`_ensure_cover_file`；三个标签写入函数改为复用 `cover_bytes` 参数（不再各自重复下载封面）；已存在文件路径补齐封面
- `src/gui_qt/pages/netease.py`：批量下载兜底 `SongInfo` 补传 `cover_url`
- `_smoke_cover_download.py`：冒烟测试脚本

## 验证结果

- `_smoke_cover_download.py` 全部 23 项通过：本地 HTTP 服务模拟封面下载（正常保存/同名跳过/无扩展名默认 .jpg/404 静默/内容过小静默/连接异常静默）、`download_song` monkeypatch 验证封面触发与同名落盘、网易云封面字节复用/另存/已存在跳过/pic_url 为空不生成、标签函数签名、GUI 兜底补传断言
- 离屏导入验证：`gui_qt.pages.netease`、`netease.music_downloader` 导入 OK
- 旧调用方签名兼容：`cover_bytes` 均带默认值，全仓无其他调用方
