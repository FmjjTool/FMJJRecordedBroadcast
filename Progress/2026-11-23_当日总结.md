## 视频操作预览占用文件导致命名投稿无法改名

### 需求

用户反馈：进过「视频操作」和「命名投稿」后，视频文件被占用，命名投稿无法改名，要求优化这段逻辑。

### 根因

- `EditorPage` 的 `QMediaPlayer` 在 `on_hide()` 里只 `pause()`，媒体源仍指向视频文件；Qt 后端持有句柄直到换源/退出，切页后一直不释放。
- 命名投稿改名走 `toolbox.organize_engine._locked_reader()`（`FILE_SHARE_READ | FILE_SHARE_DELETE`）再 `os.rename`；播放器句柄不共享删除，所以打开即失败或改名报共享冲突，表现为「文件被占用，改不了名」。
- `EditorPage.release_view_resources()` 原本没有任何调用方，属于死代码，不能兜住切页场景。

### 处理方案

- **切页松手**：`EditorPage.on_hide()` 改为停播并 `setSource(QUrl())`，真正释放文件句柄；`release_view_resources()` 复用同一逻辑，退出 `shutdown()` 也复用。
- **续播**：释放前记住 `position`，回到视频操作页重新建源后跳回原位置，不因松手丢进度。
- **按文件定向释放**：新增 `EditorPage.release_media_file(path)`，路径相同才释放；命名投稿在 `_do_rename()` 进入后台前遍历 `app.pages` 调用它，避免其它入口直接在页内改名时仍撞锁。
- **短暂占用重试**：改名改用 `_rename_with_retry()`，对 Windows `ERROR_SHARING_VIOLATION`/`ERROR_LOCK_VIOLATION`（32/33）及 `EACCES/EBUSY` 最多重试 6 次、每次 0.3 秒（约 1.5 秒），覆盖杀软/同步盘/后端延迟释放句柄；其它错误不重试。
- **提示可读**：重试仍失败时提示「视频仍被占用，改名未执行：<文件名>（可能有程序正在预览/播放或同步该文件，关闭后重试）」，替换原先直接抛出的 `[Errno 32]`。
- 未改动命名规则、附属文件同步、元数据写入与投稿流程。

### 改动文件

| 文件 | 改动 |
| --- | --- |
| `src/gui_qt/pages/editor.py` | 新增 `_release_preview()` / `release_media_file()`；`on_hide()` 释放媒体源；`on_show()` 重新建源并续播；`shutdown()` 复用 |
| `src/gui_qt/pages/rename.py` | 新增 `_is_sharing_violation()` / `_rename_with_retry()`；`_do_rename()` 先释放本软件内预览占用并带重试改名 |
| `src/skills/software-feature-guide/SKILL.md` | 「命名投稿」补充改名不再被预览挡住、外部占用重试与提示口径 |
| `tests/test_rename_locking.py`（本地，未入库） | 占用判定、重试成功/放弃/不重试、释放钩子 6 项 |
| `tests/test_page_preload.py`（本地，未入库） | 原「切页只暂停」用例改为「切页释放句柄 + 回来重建源 + 只释放同文件」3 项 |
