# 2026-11-20 音乐搜索下载合并单页（原「音乐信息获取」并入「音乐下载」）

## 需求与选型

用户问「音乐下载和音乐信息获取能合并到一个页面吗（不是说分两栏）」。确认走**方案 B：以下载页为主壳扩展**。

- 两页原本已经共用侧栏入口「音乐搜索下载」，但内部是 `TabbedPage` 的两个页签，看起来仍是两块 UI，所以这次把容器改成单页。
- 不新建页面类、不新写渲染框架：`MusicSearchDownloadPage` 直接继承 `NeteasePage`，保留原注册名与页面状态字段，旧配置/快捷卡片不失效。
- 不新增「中心/管理器」：两页是同一层级的搜索工具、共用同一套 `music.SongInfo` 数据模型，合并只是入口与结果视图收敛，符合约定 12。
- 五平台对比保留「同一首歌横向对比」的价值：第一版做成了单一扁平列表（只有平台标签），用户看图后指出「五个平台的单独框架没有啊，然后封面也没办法加载」——改为**五个平台各一栏独立框架并排**（每栏白底圆角框 + 标题 + 计数 + 各自滚动），行内恢复封面缩略图；这样既是一页，又保留原来的横向对比。平台筛选保留，改为整栏显示/隐藏。
- 第二轮反馈「按照匹配度排序没有做，然后默认勾选第一个也没有做」：去掉按歌名归一化的字母排序，改为栏目内按**与搜索词的匹配度**排序（完全相同 0 / 前缀相同 1 / 包含 2 / 不相关 3，稳定排序，同分保留平台自身相关度顺序）；每栏第一条（匹配度最高）默认勾选，与原信息页一致。

## 空状态（追加）

- 切到「五平台对比」时先渲染五个空框架（各栏标题 `平台 · 0`、居中「—」占位、顶部提示「输入歌曲名后点「搜索五平台」」），不再是一片空白；搜索无结果时框架保留并把状态栏改成「五平台都没有搜索结果…」；切回单平台时清空。

## 未验证 / 注意

- 未跑真实下载与真实导出（避免写入用户的歌曲目录与导出目录）；下载/导出逻辑用打桩验证到分发层，建议实机各点一次。
- 少数歌曲平台搜索接口本身不返回封面（如 QQ 无 albumMid 的翻唱版、酷狗部分 VA 合辑），这些行显示空白占位，属数据缺失而非加载失败。
- 勾选框的白色对勾图标在系统临时目录生成 `fmjj_music_check.png`（QSS 只用文件路径），删掉后下次打开页面会自动重建；只有本页使用，未改全局 QSS / 调色板。
- 五平台对比固定使用「各平台默认音质」（网易云无损），单平台模式仍按平台音质下拉。
- 酷狗概念版需登录，不在五平台对比内，仍走单平台入口。
- `Progress/` 下同目录还有其它并行任务的未提交改动；本次未提交、未推送。
