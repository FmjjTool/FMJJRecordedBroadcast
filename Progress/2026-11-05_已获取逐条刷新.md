# 已获取逐条刷新（2026-11-05）

## 需求
账号采集时，「已获取」页仍然要等整轮结束才一次性出现；用户要求每拿到一条就先入库/显示，而不是按轮次或按账号成批刷出。

## 根因
- 旧实现每个账号抓完后先 `_collect(posts)` 再统一刷新；并发账号完成时间接近时，会在同一帧一起出现。
- 抖音 Playwright 兜底要等整页加载完才返回列表，HTTP 直调被风控时尤其明显。
- 「已获取」页的 `refresh_count` 有 `isVisible()` 判断；采集时停在「账号获取」页会跳过刷新，切回时才整批重建。

## 方案
- `InfoAccountsPage` 增加结果揭示队列：采集线程先把结果写入 `collected.db`，再交给主线程；主线程每 150ms 揭示一条作品（不是按账号一批）。
- `_collect(infos, persist=False)` 支持只进内存、不重复写库；队列揭示时用它去重。
- 抖音解析器新增 `on_items` 回调：HTTP 每页/Playwright 首个接口响应就回调已解析作品，不再等整账号抓完；回调只给本次目标数量。
- 采集 worker 增加 `round_id`，新轮开始先清空旧揭示队列；旧轮结果仍进内存但不动新一轮 UI。

## 改动文件
- `src/gui_qt/common.py`：`_collect` 增加 `persist` 参数
- `src/gui_qt/pages/info_accounts.py`：揭示队列、150ms 单条节奏、round_id 透传、先落库后揭示
- `src/platforms/douyin.py`：`fetch_user_posts` / `_fetch_user_posts_http` / `_fetch_pw_once` 增加 `on_items` 回调

## 验证
- 真实抖音账号（count=3）：结果按单条出现，实测 29.6s / 29.8s / 30.0s 各一条。
- 真实 B站账号（count=3）：结果按单条出现，实测 26.41s / 26.52s / 26.63s 各一条。
- 抖音 HTTP 直调仍会被风控回退 Playwright（约 20s）；本次改善的是「拿到就回传/逐条揭示」，不改变平台接口本身的耗时。
- `python -m py_compile` 三个改动文件通过；真实采集后队列可清空、最终条数正确。
