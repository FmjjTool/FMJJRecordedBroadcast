# 腾讯文档「表格数据同步」合并进主程序（2026-11-03）

## 需求
腾讯文档的智能表格（歌曲库 / 无料周边 / 演出场次等）在远端被改动时，
希望能同步到本地，可离线查询、可比对改了什么。先在 `test/` 验证可行，
验证通过后合并进主程序。

## 验证结论（`test/tcsync.py`，实验代码，未进主程序）
- 接口 `dop-api/opendoc` 免登录可读公开文档；3 个文档 / 19 张表 / 7110 行全量拉取成功。
- 以 `record_id` 为键 + 内容 md5 做增量，新增 / 修改 / 删除判定实测准确，连跑三遍全 0。
- 已知限制：类型 19 公式列服务端不给计算值；`grid` 普通表格是 protobuf 不兼容；
  dashboard / smartcanvas 无数据行。协议细节见 `test/README.md`。

## 合并后结构
- `src/toolbox/tcdoc/tables.py`（新增）
  - 抓取：`_list_tabs` 拿工作表清单 → 按 `tab` 分 `BATCH=5000` 分段拉数据，
    靠 `max_row` 判完整性；**拉不全时计 `pending`、绝不删本地行**
  - 解码：JSONP 剥壳、base64+zlib（补 `=` padding）/ 内联 JSON 两形态、
    `k` 前缀键名归一化
  - 渲染：14 种字段类型（文本/数字/复选框/日期/图片/附件/链接/单选/多选/成员/
    关联/创建时间/自动编号/公式留空），关联字段两阶段 `resolve_links()` 翻主字段文本
  - 存储：独立库 `download/腾讯文档数据/tables.db`（`sheets` / `rows` / `changes`）
  - 导出：每表一个 sheet 的 Excel → `download/腾讯文档数据/表格数据/`
- `collector.py`：同一次浏览器会话里顺带同步表格（`sync_tables=True`），复用登录态
- `job.py`：`_store_tables()` 落库 + 日志；`sync_tables()` 供页面单独触发
- `gui_qt/pages/tcdoc.py`：第 4 个 Tab「📋 表格同步」（表清单 / 分页浏览 / 变更记录 /
  单表 Excel 导出），底部开关「同时同步表格数据」
- 配置键：`tcdoc_sync_tables`（默认开）、`tcdoc_table_page`（每页行数）

## 修掉的坑
1. 关联字段 id 用 `str(dict)` 取 → 字段顺序每次响应都变，误报 300 行「修改」；
   改为递归遍历 + `_ID_RE` 白名单后稳定。
2. 大表 `endrow=10000` 一把拉，截断会被误判为删除 → 改分段 + 完整性校验。
3. `export_excel` 收到 `path` 却没用，内部仍读默认库 → 传参修正 + 空 workbook 兜底
   （openpyxl 空表保存抛 `IndexError: At least one sheet must be visible`）。
4. `import_legacy` 去重键 `(doc_key, ts)`：`daily.ts` 是 TEXT、旧库是 INTEGER，
   类型不一致导致每次导入都重复插入 → 统一按 `str(ts)` 比对。

## 验证
- `_smoke/_smoke_tcdoc_tables.py`：82 项全过（解码 / 渲染 / 增量 / 导出 / 拉不全保护 / 主窗口切页）
- `_smoke/_smoke_tcdoc_page.py`：全过（旧版迁移用例改为自造旧库，不再依赖用户机器上的历史目录）
- 真实数据：`job.sync_tables()` 端到端跑通，正式库 3 文档 19 表 7110 行；
  篡改库里最早一行后重跑 → 识别为「修改」并回写远端真实值（`{'added':0,'updated':1,'removed':0}`）

## 用户可感知
- 远端改了一条很早以前的记录，本地也能识别并覆盖：比对只看 `record_id` + 内容 md5，
  与记录新旧无关。
- 同步失败（浏览器没起来 / 未登录 / 表被删）只影响表格 Tab，浏览量采集照常。
