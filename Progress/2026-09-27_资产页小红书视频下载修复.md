# 资产管理页小红书视频下载修复（2026-09-27）

## 问题

用户反馈：资产管理页小红书条目只能下载封面，视频流一直无法获取。
截图中最新两条条目（9/26、9/27）无蓝色下载按钮，媒体目录里各只有 1 张封面 jpg。

## 根因

`refresh_xhs_urls`（小红书笔记页重新解析回填直链）只接入了 info_results / info_parse / info_batch 三个页面；
**资产管理页 asset.py 有自己独立的下载函数链，从未接入回填**：

1. 账号获取（fetch_user_posts）的卡片条目「链接」是**笔记页 URL**（含 xsec_token）而非直链，`raw_data` 为空
2. `_item_has_video` 用 `_is_direct_media_url` 判定 → False → 路由进 `_download_images_for_item`（图片分支）
3. 图片分支的 `_extract_pic_urls` 只认微博（pics/pic_ids）和B站（opus.pics/draw.items）字段 → 无图可下
4. 只剩 `cover_url` → 以单图名义下载 1 张封面，**视频流从头到尾没被尝试**

实测 `XiaohongshuParser.parse()` 本身正常：视频笔记能拿到 `sns-video-v3.xhscdn.com/...mp4?sign=...` 直链。

## 修复（asset.py 三处 + tooltip）

1. **`_item_has_video`**：platform=xiaohongshu 且「链接/原始URL」含 xiaohongshu.com → 返回 True
   （路由进视频下载路径，同抖音时效直链模式）
2. **`_download_video_item.work()` 加小红书分支**：候选 raw_url → 链接 → 裸笔记页逐个 parse；
   视频笔记回填直链 vurl2；图文笔记取 note_images 走图片下载（同抖音 note 模式）
3. **下载前兜底**：xhs 且 vurl2 仍非直链且无 note_images → 显式 raise「视频流获取失败：
   笔记链接可能已失效或被风控」，防止 download_media 静默跳过视频只下封面
4. **行按钮 📥 tooltip 同步路由**：视频条目显示「下载视频」（B站用 `_bili_dynamic_type` 判 AV 动态），
   不再一律显示「下载封面」误导排查方向

## 验证（离屏端到端，真实网络 + 真实下载）

| 条目 | 实际类型 | 修复前 | 修复后 |
|------|---------|--------|--------|
| 9/26 我与各位共清欢 | 视频笔记（22s） | 只下封面 | **13.65 MB mp4 + 封面** |
| 9/27 苏州国风起时 | 图文笔记（13 图） | 只下封面 | **13 张图 + 封面** |

两条路径（视频流直链 / 图文 images）全部真实验证通过。

## 已知行为说明

- 小红书图文笔记在 `_item_media_complete` 语义下永远判「不完整」（按视频条目要求本地视频），
  批量下载会重复进入但 skip_existing 快速跳过，与抖音 note 行为一致
- 坏路径时期下载的旧封面文件（`{stem}.jpg`）会与新的 `{stem}_封面.jpg` 共存，可手动删除
- 直链 `?sign=` 有时效：下载前重新解析的设计正好规避过期（与 refresh_xhs_urls 同思路）
