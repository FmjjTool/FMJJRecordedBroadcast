# 2026-11-22 本地资料站「拉取代码」：通道走全 + 以云端为准

## 需求

用户截图「拉取代码」对话框报 `merge webwiki-api 失败（退出码 128）：fatal: refusing to merge unrelated histories`，质疑「有网络为什么拉取不了，我需要他尝试所有通道」，随后补充「仓库默认都是使用云端的」。

## 根因

1. **不是网络问题**：fetch 已经成功，失败发生在随后的本地 `merge --ff-only`。`download/本地资料站/webwiki-api` 是浅克隆，`.git/shallow` 里同时有本地 HEAD（`4c0c201`）与 FETCH_HEAD（`9c8d501`）两个边界，两者没有共同祖先（远端历史被重写 / 仓库重建），git 直接以 128 拒绝合并。
2. **通道也确实没走全**：旧实现只有「系统代理 → 直连」两档，系统代理读注册表（本机 `ProxyEnable=0`、`ProxyServer` 残留 `http://127.0.0.1:12450`），约定 15 里的本机常见端口 `7890 / 10809 / 12450` 与 `git config http.proxy` 都没进候选。
3. 旧逻辑还要求「确认没有本地提交」才敢对齐远端，只要本地有提交就停在报错；而本项目仓库以云端为准，本地提交不该阻塞拉取。

## 改动

| `src/toolbox/webwiki/config.py` | `proxy_candidates()` 按约定 15 重排：直连 → `WEBWIKI_PROXY`/`HTTPS_PROXY`/`ALL_PROXY` → 系统代理 → 本机常见端口（HTTP + SOCKS5，先探活、同端口只探一次）→ `git config http.proxy`；新增 `normalize_proxy()`、`proxy_alive()`、`git_config_proxy()` |

## 账号登录状态检测中间层（登录状态页签黄/红不再只停在弹窗里）

**需求**：用户问「某个账号黄或者红了，侧栏『账号与登录』卡片会在对应区间变色吗」，确认现状不会后要求：**只检测登录状态、不检测账号主页**，并且「检测在中间层发生」。中途先做成了「账号配置每行加状态徽标」，用户随后纠正：要做的是「登录状态」页签那个页面，账号配置那页的改动全部撤销。

**为什么单独一层（判定依据）**：

- 检测要联网（每个平台一次站内接口校验），不能放在绘制路径上；界面只读结果。
- 登录态由「Cookie 管理」按平台统一维护：同一平台的多个账号共用一张票，所以**按平台检测、按平台行展示**，同平台只发一次请求。

**状态口径**（取自 `tracker.whoami.probe`）：`ok` = 站内接口确认票有效（已登录）；`warn` = 已保存但平台无校验通道/接口不可达（无法验证）；`bad` = 未登录或登录态已失效；`unknown` = 未检测。`ok_at` 只在检测为已登录时更新，掉登录后仍能显示「上次正常」。
