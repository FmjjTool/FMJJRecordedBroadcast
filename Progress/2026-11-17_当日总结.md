## 腾讯文档 push 判断链路梳理（只读）

### 范围

- 用户询问当前「判断 push」的处理线；本轮只读源码，未启动应用、未请求腾讯接口、未向任何表写入。

### 链路结论

1. 采集侧 `job.run_scheduled()` / `collect_all()`：纯 HTTP 采集 → SQLite（`tables.db` 远端快照、`collected.db`、`increment.db`）与 Excel，不写腾讯文档。
2. 判断侧 `bridge.build_pending()`：本地条目 → 时间窗 → 账号过滤 → 分组 → 四级去重 → 待同步行。
3. 写入侧三条出口：GUI 中间层「复制 TSV」手工粘贴；映射回写 `openapi.build_actions()` + `execute_actions()`；命令导入 `import_pending.py`。

### 判断细则

- 时间窗取 `days`（默认 30）；账号过滤 `accounts="default"` 只保留远端表已出现过的发布账号，传列表按名单，`None` 不过滤。
- 分组键为 `(平台, 日期, 标题前20字)`，无标题退化为条目 key；B 站同分钟「视频 + 动态」合并成一行。
- 去重判定 `_matches()` 四级：URL 交集 → ID 交集 → (平台, 日期, 标题前20) → 标题 ≥10 字时 (平台, 标题前20)；任一命中即整组视为已同步。
- 输出固定 12 列加 `_images`，按发布时间倒序。

### 写入细则与闸门

- 映射回写：以主键索引远端记录，无则新增、有则逐字段 `value_key` 比较，只提交变化字段，从不删除。
- 命令导入：按平台解析链接主键去重，逐条新增并读回校验；图片先上传取 imageID，单选列用文本快速添加。
- 三道闸门：`validate_write_scope()`、`TdClient.validate_write_target()`、`import_local.validate_target()`（测试表另需 `--allow-test-document` 且只匹配 `TEST_TARGET`）。

### 已知判定风险

- 远端判断读的是 `tables.db` 缓存快照，不是实时接口；表刚被手工修改时仍按旧快照判断。
- 标题兜底偏松：同平台 + 标题前 20 字（≥10 字）即判已同步、不看日期，可能漏推；标题被截断或改标点则可能重复推。
- `_remote_index()` 的 ID 索引未按平台区分。
- `bridge` 只判断组是否存在，不做字段级更新；补空字段需另走 `--fill-choices` 或映射回写。
- `openapi.encode_value()` 不支持图片与「选项不存在」的单选，映射回写会报错；目前只有命令导入覆盖这两种情况。
