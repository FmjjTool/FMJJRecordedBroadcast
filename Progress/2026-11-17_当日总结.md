## 夸克网盘备份：按内容判定覆盖 + 字节级上传进度

### 需求

- 「相同的文件如果与云端大小 md5 这些匹配的，则不覆盖，否则覆盖」。
- 「上传进度能不能也同步返回？」并附截图：备份 `temp_20261107_01` 时进度条停在 0%、日志停在「待处理 24 个文件」，看起来卡住不再继续。

### 根因

- 该目录里第一个文件是 **3.05 GB 的 mp4**（`2026-11-16_17-57-09_…_repack.mp4`），旧实现有三个体验缺陷：
  1. 上传前要整份读盘算 md5 + sha1，3 GB 约十几秒，界面没有任何提示；
  2. 进度百分比按**文件数**分摊，大文件传到 90% 时进度条仍是 0%～4%；
  3. 单分片超时设成 300 秒，真卡住时长时间无反馈。
- 覆盖判定只看 `size + mtime`：文件只是被复制/改时间（内容没变）也会先删云端再重传，浪费一次 3 GB 流量。

### 处理方案

| 位置 | 改动 |
| --- | --- |
| `api.py` | 新增 `list_index()` 返回 `文件名 → {fid, size}`（覆盖时要云端那份的 fid）；`upload_file(..., hashes=, on_stage=)` 支持复用上层算好的 md5/sha1，并在「算校验 / 开始传输」两个阶段回调；`_put_part` 增加一次重试，单分片超时 `TIMEOUT*5`(300s) → `PART_TIMEOUT=150s` |
| `backup.py` | 扫描后先累计总字节数，进度百分比改为**按字节**：`(已完成字节 + 当前文件已传字节) / 总字节`；新增 `hash` 阶段事件（大文件「校验中」）；判定改为两级：<br>① 快路径：本地 `size + mtime` 未变且云端大小一致 → 不算 md5 直接跳过；<br>② 慢路径：算 md5，与状态库记录比对，**内容一致就只刷新记录、不重传**；内容或云端那一份对不上才覆盖 |
| `backup.py` | 覆盖时优先删**云端同名文件**（用列表返回的 fid），再删状态库旧 fid，避免云端攒 `(1)(2)` 副本；`replace_changed` 关闭时走纯追加 |
| `quark_backup.py` | 进度文案分级：`🔍 校验中 3/24 · 3.05 GB · 文件名`、`⬆ 上传中 3/24 · 1.2 GB / 3.05 GB · 文件名`，文件名超长截断；百分比直接取后端字节进度 |

- 关于「云端 md5」：实测夸克 `file/sort` 与 `file/info` **都不返回 md5/sha1**（字段表里没有），所以校验口径为「本地 md5 与上次上传记录一致 + 云端该文件大小一致 → 视为相同」。本机没有记录但云端同名同大小时按相同处理并补记录，避免无脑重传。

### 验证结果

- 引擎三段（真实登录态，临时配置目录，验证后清理云端测试目录）：
  1. 首跑 `上传 3`，进度事件含 `run/hash/file/done` 且带 `percent`/`size`
  2. 二跑（未改动）`上传 0 · 跳过 3`（快路径）
  3. 只 `os.utime` 改 mtime、内容不动 → `内容一致，跳过：a.txt`，`上传 0 · 跳过 3`（**不再重传**）
  4. 改内容 → `已删除云端旧版本：a.txt` + `上传 1 · 跳过 2`，云端 `a.txt` 22 B、**无 `(1)` 副本**

### 实测：Cookie 有，但接口还要签名（关键结论）

- 隔离 profile 打开 `yun.139.com` 登录后，Cookie 实测包含：`token`、`skey`、`auth_token`、`a_k`、`WT_FPC` 等（证明网页登录确实走 Cookie）。

## 移动云盘：签名算法还原成功（待真实登录态收尾）

### 做法

- 用隔离 profile 打开 `https://yun.139.com/w/`，下载页面加载的全部前端脚本（18 个，含 `app.*.js` 665 KB、`chunk-vendors.*.js` 2.4 MB）到 `_smoke/_yun139_js/` 供离线检索。
- 在 `app.*.js` 里定位到请求头组装处，找到 `getNewSign` 实现：

```js
getNewSign: (params, data, ts, rand) => {
    s = encodeURIComponent(JSON.stringify(data));
    s = s.split("").sort().join("");        // 字符级排序
    return md5(md5(base64(s)) + md5(ts + ":" + rand)).toUpperCase();
}
// mcloud-sign = `${ts},${rand},${sign}`
```

- 用 Python 复刻后实测四种变体，其中「URI 编码 → 字符排序 → base64 → md5 → 再与 md5(ts:rand) 拼接取 md5 大写」这一种让服务端错误码由 `1010010014 签名校验失败` 变为 `1010010002 鉴权失败`，**证明签名层已通过**。
