## 新增 skill：标准版 / FULL 内置版双形态发布

### 需求

用户要求写一个 skill，为后续增加「FULL 版 / 普通版」做准备：普通版就是当前形态，FULL 版内置一切（FFmpeg 等外部工具与组件），做到安装后开箱即用。

### 方案

新增 `src/skills/release-editions/SKILL.md`，把双形态发布固化为可执行规则，而不是只写一句「以后做 FULL 版」：

- **两版本边界**：共用一份代码、一个 `APP_VERSION`、一个 Inno AppId、一个 GitHub Release；FULL 只作为同版本额外资产（`FengMingToolbox_Full_Setup_<ver>.exe`），`SHA256SUMS.txt` 含两行。
- **FULL 内置清单**：ffmpeg/ffprobe（`<app>\bin`）、Playwright headless shell（`<app>\browsers`）、whisper-faster 程序与 base 模型（`<app>\models`）、CLIP 模型（`<app>\models\clip`）、node（`<app>\bin\node`）；7-Zip 已随包。
- **查找顺序契约**：ffmpeg 沿用现有 `_bundled_binary`；node 需新增「包内回退」（现在只查 PATH）；Playwright 需在 frozen 态优先包内 `browsers/`，且 `PLAYWRIGHT_BROWSERS_PATH` 必须在 `sync_playwright()` 前设置；CLIP 需新增包内 `models/clip` 回退（现在只认 `config/models`）。
- **更新契约**：`updater` 按 edition 严格筛选资产，标准版只匹配 `FengMingToolbox_Setup_`，FULL 版只匹配 `FengMingToolbox_Full_Setup_`，禁止串包。
- **不做的部分**：FULL 默认只内置 `base` 转写模型与 headless shell，不内置完整 Chromium（436.4 MB）、不复制本机 `models/`（含 small 463.7 MB 与缓存）。
- **落地分级**：P0 代码契约（edition 标记、内置回退、面板「已内置」）→ P1 构建与发布（`--edition full`、双产物、两行 SHA、FULL 烟测）→ P2 体验（安装时选版本、跨版本切换提示、体积优化、第三方声明）。

## 新增约定 15：GitHub 访问网络顺序（直连 → 代理 → 其他）

### 需求

用户要求把 GitHub 的联网口径固化进 skill：优先直连 GitHub，直连不通才回退代理，最后才用其他方式。

### 方案

新增 `convention-skill` 约定 15，并按约定 4/12 同步 `AGENTS.md`、`quick-commands`、`summarize-update`：

- **第一档 直连**：`git -c http.proxy= -c https.proxy= push origin main`，同时清空 `HTTP_PROXY/HTTPS_PROXY/ALL_PROXY`、`DefaultWebProxy`，不让本机残留代理配置参与。
- **第二档 代理**：仅直连出现 DNS 失败 / 超时 / 连接重置 / TLS 失败 / 443 不通时回退；候选顺序为用户指定或 `HTTPS_PROXY` → 7890（Clash）→ 10809（v2rayN）→ 12450（旧配置）→ `git config http.proxy`；切档前先 `curl -x` / `Test-NetConnection` 探测端口，端口不通直接跳过。
- **第三档 其他**：交回宿主执行、SSH over 443（`ssh://git@ssh.github.com:443/...`）、只读镜像 GET（不用于 push、不写进 `.git/config`），且必须先告知用户。
- **约束**：一次只升一档、记录每档真实错误、不并发混用、不静默换档、不长期写死代理；三档都失败按约定 1 停止并报告，禁止 `--force`。

### 遇到的问题

1. **隐私扫描误报**：首次 FULL 打包被 `models\faster-whisper-base\config.json` 拦截——它是模型参数不是本机配置。已加白名单（仅 `models/` 下的 `config.json`），其余隐私规则不变。
2. **GitHub 直连不稳**：`api.github.com` / `uploads.github.com` 的 TLS 握手时通时断（同一 IP 多次重试只有 1/6 成功）。按约定 15 从直连回退到本机 `socks5h://127.0.0.1:12450` 代理后稳定，最终经代理上传成功。
3. **长上传容易被中断**：`Invoke-RestMethod` 缓冲整个文件且控制台被关就中断；改为后台 `pythonw` + `curl --http1.1 --speed-limit/--speed-time` 流式上传，成功完成。
4. **组件目录位置**：`run_pyinstaller` 会清空 `build/`，因此 vendor 放在 `build_full_vendor/` 而非 `build/`。
