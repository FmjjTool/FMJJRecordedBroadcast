# 内存泄露风险排查报告

- **日期**：2026-11-25
- **性质**：只读静态分析，未改动任何代码
- **范围**：`src/` 全部模块，重点为主窗口、页面生命周期、直播录制/弹幕长驻链路、WebUI 服务、云盘 API、缓存与子进程管理
- **方法**：按常见泄露模式分类扫描（无上限缓存、Qt 对象驻留、线程/定时器、句柄与子进程、渲染对象、WebUI 全局状态），逐类核对代码

## 一、总体结论

**存在泄露风险，但整体内存卫生水平显著高于同类 PyQt 应用。** 确认的泄露集中在少数几个「模块级 dict/list 无淘汰机制」的缓存上，均为单点修复即可解决；长驻链路（弹幕、录制、转码、性能监控、WebUI）普遍使用有界数据结构，防线齐全。

| 等级 | 数量 | 说明 |
| --- | --- | --- |
| 高 | 2 | 确认泄露，量级可达数百 KB～数 MB/目录 |
| 中 | 4 | 确认驻留无清理，量级受使用方式影响 |
| 低 | 2 | 确认存在，影响很小 |
| 疑似 | 3 | 需运行时验证 |

## 二、高风险（确认泄露）

### 1. `_DIR_INDEX`：目录文件索引缓存无任何淘汰

- **位置**：`src/toolbox/tcdoc/import_pending.py:142`（写入点 `:167`）
- **问题**：模块级 `dict[str, tuple[int, dict[str, Path]]]`，key 为目录路径，value 为该目录**全部文件的完整索引**。代码注释自述「作者媒体目录动辄上万文件」。仅按 mtime 更新同一 key，从不清除旧 key，进程生命周期内只增不减。
- **触发场景**：腾讯文档「导入比对」功能扫描过的每一个作者媒体目录都会永久驻留；长期运行中换不同目录反复比对，内存线性增长，单个目录条目可达数万个 `Path` 对象（数百 KB～数 MB）。
- **依据**：`_DIR_INDEX[key] = (stamp, files)`，全文件无任何 `pop/clear/maxlen` 逻辑。

### 2. `_OWNERS_CACHE`：同目录模式的第二处无淘汰缓存

- **位置**：`src/toolbox/tcdoc/import_pending.py:171`（写入点 `:191`）
- **问题**：模块级 `dict[str, tuple[int, dict]]`，key 为 `.stem_owners.json` 路径，value 为解析后的整份 JSON dict。同样无淘汰，目录被删除/改名后旧条目仍驻留。
- **触发场景**：与 `_DIR_INDEX` 同链路，叠加增长。

## 三、中风险（确认存在，量级受使用方式影响）

### 3. `_DURATION_CACHE`：视频时长缓存无淘汰

- **位置**：`src/gui_qt/pages/asset.py:224`（写入点 `:251`）
- **问题**：模块级 dict，key 为 `(path, mtime)`，ffprobe 时长结果，无淘汰。key 含完整路径字符串。
- **触发场景**：资产页浏览视频越多累积越多；数千视频后为 MB 级，单条很小。

### 4. `self.overlays`：弹幕悬浮窗只增不减

- **位置**：`src/gui_qt/live_record_window.py:337`（创建 `:489-495`）
- **问题**：`DanmakuOverlay` 是独立顶层窗口（含 QTimer + ChatCanvas + GiftLedger），按主播 key 缓存于 `self.overlays`。删除主播（`on_delete`，`:1096-1103`）只移除 manager 条目，overlay 不 close 不 deleteLater，仅 `hide()`。
- **缓解**：timer 启停正确（`danmaku_overlay.py:305/309`），无 CPU 空转；单 overlay 持有 `deque(maxlen=80)`，量级随历史主播数增长。

### 5. `_img_local` / `_img_miss`：弹幕图片 URL 缓存无淘汰

- **位置**：`src/gui_qt/pages/douyin_danmaku.py:50-51`（写入 `:97` 及下载链路）
- **问题**：模块级 dict（url→Path）与 set（未命中集合），无淘汰。条目为路径字符串，量级小但理论上无限增长。

### 6. `_danmu_auth_cache`：弹幕鉴权 token 缓存过期不清除

- **位置**：`src/toolbox/bili_live.py:750`（写入 `:782/:790/:806`，TTL 检查 `:769-771`）
- **问题**：读取时检查 10 分钟 TTL，但过期条目只跳过不清除；监控过的直播间数量累积。通常几十个，风险有限。

## 四、低风险

### 7. `open(...).read()` 无 with 的裸读

- **位置**：`src/gui_qt/pages/music_tag.py:639、1247、1404、1517、1553`；`music_tag_dialogs.py:1365`
- CPython 引用计数下基本无句柄泄露，模式不佳，建议改为 `with`。

### 8. fire-and-forget Popen

- **位置**：`live_record_window.py:964`（ffplay 预览）、`asset.py:5490`、`image_sorter_widgets.py:852/854/1977`、`image_sorter_folder_panel.py:677`（explorer）、`updater.py:330`（更新脚本，有意脱离）
- 一次性独立进程，不保存句柄，内存泄露风险低。

## 六、已排查确认无泄露的模式（良好实践）

1. **无 QtWebEngine / 无 matplotlib / 无 asyncio**：相关泄露模式整体不存在；WebUI 用 `ThreadingHTTPServer` 线程模型。
2. **Qt 对象销毁**：`deleteLater` 51 处覆盖 toast/右键菜单/刷新前旧卡片；QDialog 均带 parent；`page_lifecycle.py:183-185` 主动保护运行中的 QThread；骨架页 removeWidget+deleteLater。
3. **QTimer**：34 处全部带 parent 且启停对称（`performance_monitor.py:43-45`、`settings.py:522`、`douyin_danmaku.py:1715/1776` stop+deleteLater 置 None）。
4. **任务租约**：`common.py:114-137` acquire/release 对称（含异常路径）；信号桥只连接一次，避免动态 connect 泄露。
5. **有界数据结构**：性能监控 `deque(maxlen=3600/2000)`；弹幕消息 `deque(maxlen=80)`；礼物榜单 `deque(maxlen=500)`；抖音弹幕页日志超限截断（8000→4000、4000→2000）。
6. **图片缓存全部有上限**：`cover_loader.py:190-194` LRU；缩略图超 240 清 80；图片排序 ByteLRU（64MB/4MB 上限）+ `clear_memory_caches`。
7. **录制/转码子进程清理**：`live_record.py` `_close_all` 关管道 + pump 线程 join；`convert_engine` 超时 kill+communicate；`danmaku_render` finally wait/kill；`sevenzip` terminate/kill + reader join；`asr_engine` kill 后置 None。
8. **线程池**：36 处几乎全部 `with` 自动 shutdown；唯一手动处有 `finally: pool.shutdown`；抖音浏览器会话池有 is_alive 过滤、空闲自移除、崩溃补线程上限。
9. **WebUI**：任务 2 小时过期 prune + 日志 300 条上限；会话 64 上限 + TTL 逐出；`stop()` 时 shutdown/server_close/join。
10. **弱引用**：`theme.py:460-466` 用 WeakKeyDictionary/WeakSet 防控件驻留；`collected_library` 只驻留 slots dataclass 轻量记录。

## 七、修复建议（已于当日实施，见当日总结任务五）

按收益排序，以下 1-4 项均已实施并通过隔离验证（15 项断言全部通过）：

1. **`import_pending.py` 两个缓存**（已修复）：`_DIR_INDEX` 8 条上限、`_OWNERS_CACHE` 64 条上限，FIFO 淘汰。
2. **`live_record_window.py` 主播删除**（已修复）：overlay 执行 `close()+deleteLater()+pop`。
3. **三个小缓存加 maxsize 逐出**（已修复）：`_DURATION_CACHE` 2048、`_img_local/_img_miss` 2048、`_danmu_auth_cache` 64 + 过期清除。
4. **顺手加固**（已修复）：`music_tag*.py` 6 处裸读改 `with`。

以上均不涉及核心八模块的业务逻辑改动（`import_pending.py` 属腾讯文档中间层、`live_record_window.py` overlay 清理属对象生命周期）。
