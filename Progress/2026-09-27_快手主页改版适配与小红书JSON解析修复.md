# 快手主页改版适配与小红书 JSON 解析修复（2026-09-27）

## 问题
「账号获取」中快手与小红书均失败：
- 快手：`快手 Cookie 已接入但主页无作品数据（Cookie 可能失效）`
- 小红书：`小红书主页作品需要登录`（但存档 Cookie 有 `web_session` 登录特征）
- 用户反馈：有 Cookie 还是无法解析

## 根因
### 小红书（两个叠加 bug，均在数据侧而非 Cookie）
1. 登录态页面的 `window.__INITIAL_STATE__` 含 JS 语法（`"pwaAddDesktopPrompt":undefined`、`"selectedIds":new Set([])`），`json.loads` 失败 → 数据明明在页面里却被判为空
2. 登录态 SSR 的 `user.notes` 是按 tab 分组的**二维数组** `[[card, card], ...]`，`_extract` 按一维 dict 遍历全部 `continue` 跳过

两个 bug 叠加 → 游客请求空 + Cookie 请求"解析失败"→ 误报「需要登录」。

### 快手（2026-09 web 改版，与 Cookie 无关）
- 主页改版为 Vite 纯客户端渲染：`__APOLLO_STATE__` 消失，SSR 的 `INIT_STATE` 键名做了字符 -1 混淆且只含系统配置，**页面无任何作品数据**
- 作品列表由浏览器调 `POST /rest/v/profile/feed`（body `{user_id, pcursor, page}`），需浏览器指纹+`__NS_hxfalcon` 签名：HTTP 直连 `result=50 签名验证失败`；graphql `visionProfilePhotoList` 同样被拦（schema 已改为 `userId: String` 参数 + `PhotoEntity` inline fragment，但执行层仍 50）
- 游客/无登录态：`result=109` + `loginUrl` 登录墙
- 另：测试冻结修复时曾把快手存档 Cookie 覆盖为游客态（9 个 cookie、无 `web_st`），加剧了误判

## 方案
- **小红书**：`_balanced_json` 增加清理链（尾逗号 → `undefined`→`null` → `new Set|Map([...])`→数组）；`fetch_user_posts` 展平二维 notes
- **快手 `fetch_user_posts`**：改 Playwright 无头渲染 + `page.on("response")` 拦截 `/rest/v/profile/feed` 响应（签名由真实浏览器生成）；注入存档 Cookie；滚动触发分页（连续 3 轮无新数据判定到底 / `pcursor=no_more`）；`result=109` → 明确报错引导登录；`count<=60` 轮询上限 14 轮、更大 40 轮
- **快手 `_kuaishou_name`（account_names.py）**：APOLLO 消失后改从 `og:title`（`昵称 - 快手`）提取；无设备 Cookie 时 og:title 是通用标题「快手」，过滤跳过
- **单视频 `parse()` 未受影响**：视频页 `short-video/{id}` 仍有 `__APOLLO_STATE__` SSR，无需改动（实测确认）

## 改动文件
- `src/platforms/xiaohongshu.py`：`_balanced_json` 清理链 + notes 展平
- `src/platforms/kuaishou.py`：`fetch_user_posts` 重写为 Playwright 拦截法（`_posts_via_browser`），新增 `_best_feed_video_url` / `_feed_item_to_info`（新版 feed 的 manifest/photoUrls 结构转换）；删除失效的 `_posts_from_apollo`
