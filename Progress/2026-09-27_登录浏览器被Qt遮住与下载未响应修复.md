# Cookie 登录浏览器被 Qt 遮住 + 下载未响应（2026-09-27 下午）

## 现象（用户报告 + 截图）
1. **下载图片对话框 "(未响应)"**：进度停在 0/1、0%，Windows 标记主线程冻结
2. **快手登录浏览器窗口"存在但被 Qt 遮住"**：贴合层跑到主窗口后面，必须点「⌨ 改独立窗口」才能看到，"没办法显示在里面"

## 现场核查
- 当时桌面枚举：应用已关闭、无 Playwright 浏览器窗口（在跑的 msedge 全是用户自己的 Edge，`--no-startup-window` 后台预载，命令行可区分）
- 15:20 会话日志：快手批量下载（yximgs 图 + kwaicdn 视频）全部 200 OK 正常推进，下载 worker 无异常

## 根因
### 被遮住（cookie_manager.py 两处叠加）
1. **贴合浏览器是顶层独立窗口，不受 Qt owned 窗口链约束**。登录框是非模态 `show()`，用户一点主窗口（如去点下载），Windows 把主窗口提到浏览器之上；而 `_FollowFilter` 只装在登录框/host 上，**主窗口的激活事件收不到** → 浏览器永远卡在后面
2. **`_reposition` 的"矩形没变就不动"早退**：即使被触发，位置相同直接 return，z 序从不重抬（原注释还写错了 flag：0x40C0 实际含 SWP_HIDEWINDOW(0x80) 而非 SWP_NOACTIVATE(0x10)，靠 SHOW 优先碰巧能用）

### 下载未响应（既有实测记录的组合复现）
代码注释里有 faulthandler 定位过的结论：**模态嵌套事件循环 + 跨进程覆盖层共存 → 主线程冻死**。资产页右键菜单 `menu.exec()`、详情框 `win.exec()` 都是嵌套循环；快手登录浏览器贴合期间在主窗口里一操作（下载/右键），组合命中 → 主线程冻 → 恰好开着的下载进度框被 Windows 标 "(未响应)"。"有时候"= 仅在登录浏览器开着时发生。

## 修复（src/gui_qt/cookie_manager.py）
贴合层改为**跟随登录框激活状态显示**（`_overlay_should_show` + `_resync`）：
- **可见**：登录框激活，或前台就是浏览器本身（用户正在页面里点/打字——顶层贴合可打字的原方案不回归）
- **收起**：焦点去了主窗口/其他程序（用户在主窗口干活时浏览器必然隐藏 → 被遮住无从谈起，嵌套循环冻死组合不复存在）
- `WindowDeactivate` 延迟 60ms 再判定（焦点可能正切进浏览器，不能误收起）；`WindowActivate` 立即弹出+贴合+抬 z 序
- `_reposition`：矩形相同也抬 z 序（NOMOVE|NOSIZE 不触发重绘无闪烁）；SWP flag 全部改具名常量
- `_info_box`/`_confirm_box` 的 `_restore` 改走 `_resync`（按激活状态决定弹出还是保持收起，不再无条件显示）

## 验证（真 Playwright Edge + 真 Qt 窗口端到端）
1. 打开快手登录 → 贴合浏览器窗口出现 ✓
2. 激活主窗口 → 贴合层自动收起（不再被遮住）✓
3. 点回登录框 → 浏览器立即弹出 ✓
4. 浏览器 z 序在主窗口之上 ✓
5. 前台是浏览器本身时保持显示（打字场景不回归）✓
测试后无孤儿 Edge 进程；临时脚本已清理

## 用户侧说明
- 修复后：登录浏览器开着时去主窗口操作会自动收起（登录框区域显示白底），点回登录框立即恢复——这是设计行为，防冻结
- 之前"有时候下载未响应"与登录浏览器开着直接相关；修复后该组合已拆散。若之后仍在**未开登录浏览器**时出现未响应，需要另行抓 faulthandler 转储定位
