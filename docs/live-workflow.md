# 录制、弹幕渲染与视频迁移投稿

## 图标与直播弹幕

重启 `python main.py` 后，窗口和 Windows 任务栏使用项目根目录的 `icon.ico`。打包配置也会携带同一图标；本次修改源码不替换已安装的旧版 EXE。已固定的旧快捷方式若仍显示 Python 图标，可在运行新入口后重新固定。

直播录制窗口 → 录制设置 → 勾选“开始录制时自动启动弹幕渲染”。每位主播开录时打开独立弹幕窗口，复用同时录制弹幕的连接；停止录制时隐藏，下次开录重新显示。支持抖音和 B站。窗口底部向上排列最近消息、昵称彩色，可调字号、条数、背景透明度。弹幕页的“渲染当前弹幕”也可独立显示当前连接/回放的消息。此功能不把弹幕压入录制视频。

弹幕页的轮询开关表示“下播后继续等待下次开播”：连接成功即停止等待计时器，直播结束后重新等待。录制窗口仍需检测下播，直播中只检测房间状态，暂停反复获取直播流/画质；查询失败保留正在录制的状态。

## 突然关机的数据

已保存的视频和实时记录不会因为窗口消失而主动删除。TS/FLV 适合中断恢复，普通 MP4 如果来不及写结尾可能需要修复。

启用“同时录制弹幕”时，两平台均保存与视频对应的 JSONL，B站另存 XML。JSONL 每条刷新到系统缓存、最多每秒同步磁盘，关闭时再同步；重开修复末尾半行。B站 XML 每条维持闭合，异常时仍可从 JSONL 恢复。弹幕页还有“弹幕文件/实时记录/”下按房间和日期追加的日志。

实时记录降低损失范围，不保证断电零丢失：末尾尚未同步的数据、未生成的回放 ZIP、设备缓存或磁盘故障仍有影响。录制列表和是否录制的设置会在状态变化后自动原子保存；重启后需重新开启监控，不假装仍有活动录制任务。

## A端文件夹迁移

“自动整理” → 添加一个或多个来源文件夹 → 按需勾选包含子文件夹 → 扫描并预览 → 执行迁移/整理。

- 只迁移常见视频扩展名；文本、弹幕、图片、配置及 `.ogg` 音频不迁移。
- 从文件名识别日期时放进工作目录的日期文件夹，例如 `20261002/`；来源视频没有日期时先放在工作目录根目录。
- 来源和目标重复、工作目录子树、文件链接不纳入来源扫描；多个重叠来源去重。
- 空文件或最近 30 秒仍有写入的来源视频暂缓。Windows 会拒绝打开仍被录制器写入的文件。
- 跨磁盘先复制到目标目录临时文件，同步并校验 SHA-256；原子生成不覆盖同名的目标，最后删除来源。保留原修改时间。同名文件自动追加编号。
- 文件在预览后变化时要求重新扫描。复制或校验失败保留来源；目标已复制但来源删除失败会明确提示位置，需核对后处理。

## B站文案与自动投稿

"录播工具箱" → "交互重命名 / 投稿"。自动整理完成后也可点击“前往交互重命名 / 投稿”。投稿入口与自动开关位于交互重命名页，自动整理只迁移视频。

原三栏交互重命名功能已恢复：左栏选日期文件夹/视频，中栏选直播账户和类型，右栏选择无/有弹幕、平台及自动/手动/不保留标题，查看视频信息、截图和新文件名。数字键 1～9 切换类型，Enter 确认，Esc 跳过；已标准命名的文件按 Enter 跳过，点击“重新命名”仍可修改。“参数设置”保留账户、类型、平台的添加/删除/排序，以及后缀、匹配阈值、附加信息和版权开关。

“投稿设置”编辑文案与分区；进入窗口自动读取当前工作目录的视频，日期与复选框默认选择北京时间的今天。未完成重命名/当前会话版权处理的视频可见但暂不可勾选；只上传勾选的视频，拖动可调整分P顺序。“选择工作目录视频”支持日历切换、显示全部日期、全选/取消全选；“刷新视频”重新读取目录。切换工作目录不保留旧目录候选。窗口和上传引擎统一检查 `YYYY-MM-DD_HH-MM-SS_内容` 命名及有效日期时间，未完成改名的文件不能上传。

默认标题参考用户提供的图片：`封茗囧菌{日期}直播全程无弹幕{分P说明}～`。单视频不显示分P文案。严格只对北京时间今天的多个有效录播启用分P，并要求本次勾选文件属于同一主播、来源平台与弹幕版本；每个文件作为同一稿件 `videos` 数组里的一个 P，按列表顺序提交一次。仅存在多个文件但只勾选一个、历史日期、跨日/跨主播/跨平台/不同弹幕版本、重复路径或未完成重命名，均不能算多个 P；分P提示、排序与文案仅在条件满足时显示，不符合分组条件的多视频需分别投稿。

标题和简介支持 `{日期}`、`{平台}`、`{文件名}`、`{P数}`、`{分P说明}`。直播来源平台固定为“抖子”和“B站”，旧配置的“抖音”映射为“抖子”；B站账号管理仍使用原平台标识。日期默认今天，勾选其他同日视频时更新为该日，可为本次手工覆盖。

“保存模板”保存当前命名模板，“另存为模板”新增另一套，可在顶部切换或删除。模板保存标题、简介、平台、标签、分区、投稿类型、来源、封面及投稿开关，不保存本次日期、勾选文件或登录信息。原有文案继续保留；来源迁移配置与自动上传开关也不会因保存模板被覆盖。转载类型须填原直播来源链接，留空封面时用 FFmpeg 提取首帧。

进入窗口自动验证 Cookie 管理当前启用的 B站账号并读取可用分区，无需手工点击验证。账号信息独立显示；需要登录、重新登录或切换时使用“Cookie 管理”，返回后自动验证。登录状态变化会丢弃旧验证结果，并在新的上传请求之前停止旧账号任务。分区读取失败时保留手填分区 ID。上传使用创作中心的预上传接口、UPOS 分片传输与合并，再按“上传成功后自动投稿”开关提交稿件。投稿成功表示进入 B站审核，不代表已公开通过审核。内部接口可能变化，风控/登录失效会提示检查官方页面。

配置完成后，在重命名页勾选“本文件夹全部重命名完成后自动投稿”。逐个确认改名，所选版权元数据处理结束后才推进到下一视频；整个文件夹完成后，按当前文件列表顺序组成一个分P稿件并开始上传。是否提交稿件由投稿设置中的“上传成功后自动投稿”决定。

跳过未标准命名视频、元数据处理失败、视频增删或工作目录变化都会暂停自动投稿。元数据失败时保留已改名的原视频，可按 Enter 重试；如不需要版权处理，取消勾选后再次确认。重命名目标已存在时保留双方文件，需处理冲突后继续。视频上传失败不删除本地文件。既有投稿文案和自动开关配置继续保留。

上传历史位于本地配置目录的 `bili_upload.db`，不保存账号 Cookie。相同账号、文件路径、大小、修改时间和顺序的成功任务会阻止重复投稿；上传中断或提交结果不明须先在官方投稿管理核对，再通过“已核对没有稿件，允许所选任务重试”解锁。分片 PUT 可重试，稿件提交超时不会自动重发。取消正在提交的请求也不保证服务器没有收稿。

## 本次验证范围

隔离测试覆盖迁移数据/同名/变化/失败保留、文件共享写入、JSONL 与 XML 恢复、开播/下播轮询、录制事件联动、分P文案、UPOS 请求参数、CSRF、重复/结果不明的投稿保护，以及恢复的交互重命名控件、改名/元数据/投稿顺序与失败拦截。此前真实已登录账号使用临时生成的 1 秒视频完成封面与分片上传验证，没有调用稿件提交接口。本次恢复使用临时短视频与模拟上传验证，不发布用户录播。公开投稿成功与实际直播长时间连续录制仍需实际使用验证。
