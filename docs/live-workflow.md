# 录制、弹幕渲染与视频迁移投稿

## 图标与直播弹幕

重启 `python main.py` 后，窗口和 Windows 任务栏使用项目根目录的 `icon.ico`。打包配置也会携带同一图标；本次修改源码不替换已安装的旧版 EXE。已固定的旧快捷方式若仍显示 Python 图标，可在运行新入口后重新固定。

直播录制窗口 → 录制设置 → 勾选“开始录制时自动启动弹幕渲染”。每位主播开录时打开独立弹幕窗口，复用同时录制弹幕的连接；停止录制时隐藏，下次开录重新显示。支持抖音和 B站。窗口底部向上排列最近消息、昵称彩色，可调字号、条数、背景透明度。弹幕页的“渲染当前弹幕”也可独立显示当前连接/回放的消息。此功能不把弹幕压入录制视频。

弹幕页的轮询开关表示“下播后继续等待下次开播”：连接成功即停止等待计时器，直播结束后重新等待。录制窗口仍需检测下播，直播中只检测房间状态，暂停反复获取直播流/画质；查询失败保留正在录制的状态。

## 突然关机的数据

已保存的视频和实时记录不会因为窗口消失而主动删除。TS/FLV 适合中断恢复，普通 MP4 如果来不及写结尾可能需要修复。

启用“同时录制弹幕”时，两平台均保存与视频对应的 JSONL，B站另存 XML。JSONL 每条刷新到系统缓存、最多每秒同步磁盘，关闭时再同步；重开修复末尾半行。B站 XML 每条维持闭合，异常时仍可从 JSONL 恢复。弹幕页还有“弹幕文件/实时记录/”下按房间和日期追加的日志。

实时记录降低损失范围，不保证断电零丢失：末尾尚未同步的数据、未生成的回放 ZIP、设备缓存或磁盘故障仍有影响。录制列表和是否录制的设置会在状态变化后自动原子保存；重启后需重新开启监控，不假装仍有活动录制任务。

## A端文件夹迁移

“自动整理” → 添加一个或多个来源文件夹 → 按需勾选包含子文件夹 → 扫描并预览 → 执行迁移/整理。

- 只迁移常见视频扩展名；文本、弹幕、图片、配置及 `.ogg` 音频不迁移。
- 从文件名识别日期时放进工作目录的日期文件夹，例如 `20261002/`；来源视频没有日期时先放在工作目录根目录。
- 来源和目标重复、工作目录子树、文件链接不纳入来源扫描；多个重叠来源去重。
- 空文件或最近 30 秒仍有写入的来源视频暂缓。Windows 会拒绝打开仍被录制器写入的文件。
- 跨磁盘先复制到目标目录临时文件，同步并校验 SHA-256；原子生成不覆盖同名的目标，最后删除来源。保留原修改时间。同名文件自动追加编号。
- 文件在预览后变化时要求重新扫描。复制或校验失败保留来源；目标已复制但来源删除失败会明确提示位置，需核对后处理。

## B站文案与自动投稿

“自动整理” → “B站投稿设置 / 视频上传”。也可直接选择多个视频，拖动列表调整分P顺序。

默认标题参考用户提供的图片：`封茗囧菌{日期}直播全程无弹幕{分P说明}～`。一 P 示例为 `封茗囧菌20261002直播全程无弹幕～`，两 P 为 `封茗囧菌20261002直播全程无弹幕（分两 p）～`。

标题和简介支持 `{日期}`、`{文件名}`、`{P数}`、`{分P说明}`。日期从文件名读取，可为本次手工覆盖；保存配置时不保留单次日期，避免下一场误用旧日期。简介、标签、分区、投稿类型、来源和封面可配置。图片没有提供分区和简介，分区必须自行选择；转载类型须填原直播来源链接。留空封面时用 FFmpeg 提取首帧。

“检查登录/分区”读取 Cookie 管理当前启用的 B站账号及可用分区。上传使用创作中心的预上传接口、UPOS 分片传输与合并，再按“上传成功后自动投稿”开关提交稿件。投稿成功表示进入 B站审核，不代表已公开通过审核。内部接口可能变化，风控/登录失效会提示检查官方页面。

配置完成后，可勾选“整理成功后按配置自动上传 B站”。执行迁移时会预览将要使用的标题和分区；迁移全部成功后按日期分组，每个日期组成一个分P稿件。任一视频迁移失败则暂停本批自动上传，避免发布缺失的整场。视频上传失败不删除本地文件。

上传历史位于本地配置目录的 `bili_upload.db`，不保存账号 Cookie。相同账号、文件路径、大小、修改时间和顺序的成功任务会阻止重复投稿；上传中断或提交结果不明须先在官方投稿管理核对，再通过“已核对没有稿件，允许所选任务重试”解锁。分片 PUT 可重试，稿件提交超时不会自动重发。取消正在提交的请求也不保证服务器没有收稿。

## 本次验证范围

隔离测试覆盖迁移数据/同名/变化/失败保留、文件共享写入、JSONL 与 XML 恢复、开播/下播轮询、录制事件联动、分P文案、UPOS 请求参数、CSRF、重复/结果不明的投稿保护。真实已登录账号使用临时生成的 1 秒视频完成封面与分片上传验证，没有调用稿件提交接口。公开投稿成功与实际直播长时间连续录制仍需实际使用验证。
