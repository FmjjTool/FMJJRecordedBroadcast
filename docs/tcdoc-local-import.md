## 目标与字段

本次单独授权的目标为：[测试表格 / 智能表1](https://docs.qq.com/sheet/DRmFHc1dLcnBvbmtB?tab=ss_q4fwq4)，`doc_key=DRmFHc1dLcnBvbmtB`，`tab_id=ss_q4fwq4`。

脚本根据字段标题和类型匹配，不依赖列顺序或旧字段 ID。

| 表格字段 | 本地来源 / 处理 |
| --- | --- |
| 作品标题 | JSON 的「标题」；为空时取正文第一行，最多 80 字 |
| 作品内容 | JSON 完整「正文」，保留换行，解码 HTML 实体，例如 `&amp;` |
| 发布账号 | JSON 的「作者」；选择字段只匹配唯一的既有选项 |
| 封面图 | 同一帖子的全部本地图片，按 `_1`、`_2` 等顺序写入；单图不带序号 |
| 动态类型 | 默认「动态」，可用 `--dynamic-type` 指定表中已有值 |
| 发布时间 | JSON 的原帖发布时间；无时区时按北京时间，发送毫秒时间戳 |
| 发布平台 | 由导出的 `weibo` 自动转换为「微博」 |
| 发布位置 | 默认「动态」，可用 `--position` 指定表中已有值，不根据 IP 或设备来源猜测 |
| 作品链接 / 链接 | 根据微博 ID 生成规范原帖链接；支持这两个字段名称之一 |

「发布距今（占位）」和「创建时间」不在写入字段中。既有数据、表结构和选择项均不修改。选项缺失时整批停止，不自动创建选项或把图文误判为视频投稿。导出中的通用「类型=视频」不作为微博动态的分类依据。

## 使用方法（PowerShell）

需要 Python 3.10 以上。正常项目环境已有依赖；读取加密凭据需要 `cryptography`。HTTP 使用标准库 `urllib`，不要求 `requests`；缺少 `rich` 的精简环境使用进程内静默 Console 适配。

下列 `$taskPython` 为本次实际使用的 Codex 内置解释器，也可替换为项目 Python 的完整路径。

```powershell
Set-Location 'D:\PythonApps\FMJJRecordedBroadcast'
$taskPython = 'C:\Program Files\WindowsApps\OpenAI.CodexPrimaryRuntime.v26-1112-737-0_26.1112.737.0_x64__3k8sg7r9htsxt\dependencies\python\python.exe'
$taskImportArgs = @(
    '-B', 'src/toolbox/tcdoc/import_local.py',
    '--doc-key', 'DRmFHc1dLcnBvbmtB',
    '--tab-id', 'ss_q4fwq4',
    '--allow-test-document',
    '--export', 'download/已获取数据/微博_文件/20260823_weibo_这两日的日常记录.json',
    '--export', 'download/已获取数据/微博_文件/20261007_weibo_2.0版本的棉花娃娃已经开始陆续发货啦！.json',
    '--export', 'download/已获取数据/微博_文件/20261105_weibo_鱼窥荷.json'
)

# 只检查本地素材，不读取登录、不联网。
& $taskPython @taskImportArgs --offline-preview

# 只读取目标字段和既有选项。
& $taskPython @taskImportArgs --inspect

# 默认在线预览：核对字段、选项和原帖重复情况，不上传图片。
& $taskPython @taskImportArgs

# 确定预览无误后执行：逐帖上传、新增、重新读回。
& $taskPython @taskImportArgs --apply
```

更多参数用 `--help` 查看。`--export` 和 `--post-id` 可重复指定；默认最多 20 条，`--max-records` 可设为 1～50。`--media-root` 指向「微博_媒体」这一层。单张图片的脚本限额为 20 MiB，检查 JPEG / PNG / GIF / BMP / WebP 签名；服务端仍负责图片内容和权限校验。

账号、平台、类型或位置字段如果为选择字段，需要表内已有相同文字的唯一选项。`--inspect` 可查看值；需要调整分类时使用 `--dynamic-type` / `--position` 传入既有值。不能用本脚本修改表结构。

认证默认通过 `auth.get_cookie('tcdoc_openapi')` 读取本工程现有 Cookie 管理目录，遵守管理总开关。安装版若管理器正在使用 AppData，可传 `--managed-config-dir` 指向该**已有当前目录**，不复制、迁移或恢复旧凭据。

## HTTP 流程与异常处理

1. 按精确 `doc_key` / `tab_id` 检查范围，再通过官方文档 ID 转换和子表清单核对目标。
2. 一次预检整批本地文件、字段类型、选项和原帖链接。图片存在性、目录范围、签名和摘要均检查。
3. 根据规范微博 ID 去重，兼容移动版、桌面 base62 链接及追踪参数；已有记录只跳过。
4. `POST /openapi/resources/v2/images` 使用 multipart 的 `image` 文件项发送本地字节，取得临时 `imageID`。
5. `addRecords` 将 `[{"imageID":"..."}]` 绑定到「封面图」，一次只新增一条明确记录。`values` 使用实时字段标题作为键。
6. 新请求读回记录，核对完整文本、选项 ID、日期、链接、图片数、文件名顺序和不同图片身份；不一致则停止后续条目。

图片上传前和记录新增前会重新核对字段、选择项、登录态和重复记录。图片在预览后变化、账号变化或管理器关闭都会停止。HTTP 不跟随重定向、不回写 `Set-Cookie`，不登录、刷新或保存凭据；脚本进程还通过审计钩子拒绝持久化文件写入，包括配置探测和凭据回写。此保护仅针对独立脚本，不代表现有应用已安装全局拦截器。

标准输出为 JSON 行，包括预览、上传进度、新增 ID、读回检查和最终结果；不输出凭据、上传票据、签名图片 URL 或原始数据对象。退出码：`0` 表示预览完成或全部执行成功，`2` 表示检查/执行失败，`3` 表示新增结果不明。

新增遇到超时、连接中断、HTTP 5xx 或缺少 recordID 时，不自动重试。先按错误结果的 `source_link` 查询线上记录，明确结果后再进行在线预览。若有部分条目已成功，结果会保留其 recordID；再次执行会跳过已存在的原帖。

上传完成但新增前停止时，可能有未绑定的临时图片资源；它们的 `imageID` 有效期为 24 小时，脚本不保存或重复使用票据，也不删除远端资源。去重与新增不是服务端原子事务，请串行运行同一目标的导入。
