# 约定skill（强制阅读）

## 定位

本项目最高优先级的强制约定。任何 Agent（含子 Agent、后台任务）在执行任何操作前，必须先阅读本文件并遵守全部约定；未阅读不得开始操作。

## 强制阅读规则

1. 任何 Agent 接到任务后，**第一步是阅读本 skill**，之后才允许执行其他任何动作（包括但不限于：搜索文件、制定计划、编辑代码、构建打包、发布版本）。
2. 本 skill 与任务相关 skill 同时适用：先读本 skill，再读任务对应的 skill。
3. 约定冲突时，以本 skill 为准；本 skill 未覆盖的内容，按任务相关 skill 执行。
4. 新增约定只能追加，不得删除或篡改已有条目；条目连续编号。

## 约定清单

### 约定 1：更新前必须拉取最新代码

**触发条件**：任何“更新”动作之前，包括但不限于修改代码、修改配置、修改资源、发布版本、重建产物等一切会变更仓库内容的操作。

**执行步骤**：

1. 确认远端：`git remote -v`，`origin` 必须为 `https://github.com/FmjjTool/FMJJRecordedBroadcast.git`。
2. 拉取最新代码：`git pull origin main`（或先 `git fetch origin` 再合并）。
3. 拉取成功后，确认无未解决的冲突、工作区状态正常，方可开始更新。

**拉取失败处理**（网络不可达、认证失败、合并冲突、本地未提交改动阻塞、非 git 仓库、远端不匹配等）：

1. **立即停止**，禁止继续任何更新操作。
2. 禁止在旧代码上直接修改，禁止用本地内容覆盖或绕过拉取。
3. 向用户提问，说明失败原因并给出选项（重试 / 处理本地改动 / 更换分支或仓库 / 取消更新）。
4. 或按其他相关 skill 处理（如版本发布流程见 `summarize-update`），但任何情况下都不得跳过拉取。

**禁止事项**：

- 禁止未拉取就更新。
- 禁止拉取失败后强行更新。
- 禁止把拉取失败当作“已是最新”。
- 禁止使用 `git push --force` 等破坏远端的操作。

### 约定 2：改动前先备份，完成后必须本地提交

**执行前检查（任何更改操作之前）**：

1. 执行 `git status`，检查当前代码是否已有备份（即已保存为本地 `commit`）。
2. 若存在已修改或未跟踪文件（未备份），先本地 `git commit` 完成备份，再开始更改；提交前清理临时文件与测试产物。
3. 若无法提交（非 git 仓库、合并冲突、钩子失败等），**立即停止**并向用户提问，禁止直接改动。

**完成后提交**：

1. 每次任务或编辑部分完成后，必须本地 `git commit` 一次，不遗漏。
2. 提交信息需说明本次改动内容；提交后 `git status` 应无未备份的业务改动。
3. 向用户汇报本部分改动摘要与提交哈希。
4. 本地提交不等于推送；推送需用户明确指示或按相关 skill（如 `summarize-update`）执行。

## 执行检查清单

- [ ] 已阅读本 skill。
- [ ] 本次操作涉及更新时，已确认 `origin` 为目标仓库。
- [ ] 已执行拉取且成功。
- [ ] 拉取失败时，已停止操作并向用户提问或按相关 skill 处理。
- [ ] 改动前已执行 `git status`，无未备份内容（否则已先本地提交）。
- [ ] 完成后已本地 `git commit` 一次并汇报。
