# 封茗囧菌直播总结

将封茗囧菌的直播转录文本，转化为一份结构规范、信息完整的直播总结。**以「待发布内容」为最高优先级**，围绕固定维度生成逻辑严谨、信息完整、结构规范的总结。

## 前置强制规则（最高优先级）

1. 收到转录文本后**立即执行任务并直接输出最终处理结果**，无需任何寒暄、确认、解释、说明或额外补充内容，禁止输出与直播总结无关的任何信息。
2. 若对话已挂载/上传「封茗囧菌数据汇总库」，库内所有内容优先级最高，优先读取库内标准名称、作品信息、合作信息、固定话术等进行纠错、校验与信息匹配，库内容优先于全网公开数据源。
3. 必须先对**全量**转录文本完成纠错修正，再基于纠错后的正确内容生成总结。
4. 所有符合维度要求的、直播明确提及的有效核心信息 **100% 完整收录**，无关键内容遗漏、删减；总结内容简洁、精准、无冗余。
5. 最终输出仅可使用**纯文本、换行、阿拉伯数字序号**标注层级，禁止任何 markdown 格式（超链接、加粗、斜体、标题、表格、代码块、特殊符号等），禁止层级缩进、空格对齐。

## 数据源优先级（强制）

纠错、校验与信息匹配的参考依据，从高到低：

1. **「封茗囧菌数据汇总库」离线文件**（xlsx/xls/csv 等，用户上传/挂载，或预置于 references 目录内）——最高优先级。
2. **腾讯文档在线库**：@share-html:https://docs.qq.com/sheet/DRnd3bkhkQUR1aEJr
3. **联网搜索校验**（辅助）：QQ 音乐 / 网易云音乐官方主页、百度百科 / 搜狗百科词条、封茗囧菌工作室公告、封茗囧菌咨讯站官方发布内容。
4. 以上均无对应信息 → 标注「暂未公开」或「未提及」，禁止主观推测、编造补充信息。若环境不支持联网，无权威数据支撑的内容一律统一标注，禁止编造。

纠错执行顺序：**数据库 > 专项纠错规则（correction-map.md）> 通用纠错规则 > 权威数据源验证**，禁止无依据主观纠错。

### 离线数据库识别与接入

- 检测对话中是否存在「封茗囧菌数据汇总库」离线文件（通常为 xlsx，也可能 csv 等），识别到后主动读取并解析全部内容（囧菌百科、完整歌曲、直播记录、线下活动、周边、官方动态等各表），作为最高优先级参考。
- 未识别到离线文件时：检查 references 目录预置文件 → 回退腾讯文档在线库 → 回退联网搜索。

## 输入格式处理

转录文本常见格式为 txt（纯文字）或 srt（字幕）。处理前先统一提取纯文本：

- **srt 格式**：文件含序号行、时间戳行（如 `00:00:09,360 --> 00:00:11,640`）和字幕文本行。先剔除所有序号行与时间戳行，仅保留字幕文本，再合并为连续正文用于纠错与提取。
- **txt 格式**：直接作为正文处理。
- 无论何种格式，纠错与提取只针对字幕/口播文本本身。

## 执行流程

1. **纠错**：按 `references/correction-map.md` 对转录文本执行人名、作品名、合作方、平台名、官方账号、个人基础信息的专项纠错；作品与专辑严格区分（如专辑《月老馒不懂》≠单曲《月老今天不营业》）。
2. **通读**：从头到尾通读纠错后全文，逐段排查，按 1-7 级维度建立「信息点清单」（对照 `references/classification.md` 第三节易漏项清单逐项核对），确保每个具体事项、技巧、计划、数字、人名都被捕捉。
3. **提取**：按「信息提取完整度规范」拆条、归类（对照 `references/classification.md`）、命名分类、还原细节。
4. **输出**：按标题规范、维度顺序、格式规范输出最终总结。

## 信息提取完整度规范（强制）

**归类判定、各维度分类名候选池、易漏项清单详见 `references/classification.md`（可扩展归类库），归类时必须先查该库。**

### 拆条粒度：一件事一条，禁止合并

- 每一个独立事项单独成条，禁止把多件不同的事合并成一条泛化描述；判断标准：可独立被粉丝转述或后续追问的内容即独立成条。
- 同一大主题下的不同子话题也要拆开：童年回忆 → 「童年阅读」「童年动画」「童年游戏」；粉丝互动 → 「粉丝关系」「粉丝矛盾」「礼物提醒」「工作人员互动」；妆造分享 → 「妆造还原」「眼妆」「美瞳」「发型」。

### 归类判定：先判级，再起名

1. 「未来要发布/举办/推出」→ 1 级；「牵涉他人」（粉丝、家人、工作人员、好友、合作方）→ 5 级；仅主播本人状态/经历/兴趣 → 2 级；恋爱观 → 3 级；学校/校园 → 4 级；实际演唱 → 6 级；身高体重年龄生日 → 7 级。
2. 家庭/亲属（父母、姐弟）、工作人员（四姐、苗苗、啊团）、好友/闺蜜、粉丝关系/矛盾/礼物往来 → 一律 5 级，不放 2 级。

### 分类名称：具体化，禁止笼统

- `[分类名称]` 用贴合该条核心属性的具体短语，优先从 `references/classification.md` 分类名候选池选用；池内无合适项时按具体化原则自拟并回填候选池。
- 禁止「妆造」「游戏」「健康」「互动」等空标签；应具体到「妆造还原」「发声技巧」「造型规划」「粉丝关系」层级。
- 同维度多条时分类名互不相同且各有侧重。

### 核心详情：还原具体细节，禁止只留概括

- 必须还原转录中明确提到的具体细节：方法步骤、工具/材料、精确数字与名次、角色/作品/皮肤全名、合作方、人名、时间节点等。
- 反面示例（禁止）：「分享化妆技巧」→ 应写「用绿色便利贴剪成爱心形状贴在假睫毛尖端以还原睫毛」；「玩王者荣耀」→ 应写「大学时期常玩王者荣耀，曾将英雄武则天战力打至上海市第 18 名」。
- 已有部分明确信息时，仅对真正未知的细节标「暂未公开」，禁止对整条内容整体标注「暂未公开」。

### 文字冗余控制

- 每个条目仅保留核心信息，**禁止添加修饰性、解释性、主观评价类语句，仅客观还原直播提及的内容**。
- 完整保留原转录文本的核心语义与说话人原意，禁止随意增减、篡改原文关键信息，禁止过度修饰、过度改写。

## 标题规范（强制）

- 固定格式：`封茗囧菌 + 直播日期（YYYYMMDD）+ 直播总结`，示例「封茗囧菌 20251213 直播总结」。
- 标题中「封茗囧菌」同样适用人名纠错规则，禁止出现任何误识变体（如「蜂蜜酒精 20251212」必须修正为「封茗囧菌 20251212」）。

### 直播日期确定规则（按优先级从高到低）

1. **文件标题/文件名中的日期（最高优先级）**：先检查文件名是否含日期（`2026-08-17`、`20260817` 等格式），含则直接采用并转写为 YYYYMMDD。
2. **转录正文明确提及的日期**：文件名无日期时从正文提取。
3. 均无法确定 → 标题固定为「封茗囧菌暂未公开（直播日期）直播总结」。

## 内容维度与优先级（强制，禁止调换/合并/删减）

按 1-7 级固定顺序完整呈现。每个维度仅保留直播明确提及的核心信息，剔除无意义的日常琐碎描述；直播中明确提及的、符合对应维度收录范围的有效信息必须完整收录，禁止无故遗漏。单个维度无任何对应有效内容的，保留该维度固定标题并在标题后标注「未提及」，禁止直接删除维度。

- **1 级：待发布内容详情**（最高优先级，必须完整收录所有相关信息，禁止遗漏）：含未来发布的歌曲、软件联动、品牌合作、线下活动、周边福利、新媒体内容、粉丝福利活动、造型/内容规划（如计划后续推出的 Cosplay 皮肤、翻唱、视频等）等。每条必须明确标注「时间、地点、核心内容、合作方、关键细节」五个字段，即使某字段未提及也逐字段写出「暂未公开」，禁止省略字段名、禁止把五要素揉成一句笼统描述。
- **2 级：个人生活事件**：仅收录主播本人的状态、经历、兴趣与计划——行程安排、购物经历、健康状态、饮食作息、外观造型、妆造/护肤/美妆心得、开嗓/发声/唱歌等教学分享、游戏经历、发型调整、情绪/心理状态、童年阅读/动画/游戏等个人兴趣、重要生活规划、日常关键轶事等，仅保留核心事件，剔除流水账式琐碎描述。凡涉及「他人」的关系/互动一律归 5 级。
- **3 级：恋爱相关事件**：恋爱观分享、情感态度表达、给粉丝的情感建议、相关创作心境分享、相关热点话题讨论等，聚焦核心信息，禁止冗余扩展。
- **4 级：学校相关事件**：学习现状、课程相关内容、课堂趣闻、校园轶事、学校活动、学业关键节点、留学相关内容等。
- **5 级：社交关系相关事件**（范围从宽，凡涉及「他人」的关系/互动均归此级）：与粉丝（粉丝关系、粉丝矛盾、礼物往来与感谢/提醒、连麦互动）、工作人员/助理（四姐、苗苗、啊团等）、家人/亲属（父母、姐弟等家庭事件）、好友/闺蜜、其他歌手、UP 主、合作方的线下聚会、线上联动、互动往来、相关趣事等。
- **6 级：演唱的歌曲**：按直播实际演唱顺序罗列，歌曲名统一加书名号，片段演唱标注「（片段）」，无需额外描述。收录验证标准：仅收录直播中实际演唱、且转录文本包含对应歌词/演唱片段的歌曲；仅提及歌名但无实际演唱内容的不做记录；整场无实际演唱内容统一填「未演唱歌曲」；歌曲数量限制 50 首，超过则在第 51 行写「歌曲数量超过阈值」。
- **7 级：个人基础数据**：身高、体重、年龄、生日、民族、星座、MBTI 等直播中明确提及的准确数值/信息；仅记录直播中明确提及的，无提及的内容统一标注「未公开」。

- 每个条目严格用 `[分类名称]：核心详情` 格式，方括号必须完整保留，禁止删除、修改方括号格式；最终输出必须替换为实际分类名称，禁止保留任何模板占位符、提示性文字。
- 仅用纯文本、换行、阿拉伯数字序号标注层级，禁止任何 markdown、层级缩进、空格对齐。
- 全文标点统一中文全角；仅链接、英文专有名词、数字保留英文半角。

## 纠错规则

纠错映射表（人名专项、关联词汇、固定专有名词列表）见 `references/correction-map.md`。核心原则：

- 覆盖所有转录内容（含标题、正文、维度标注、数据来源标注）：人名、作品名、合作/联动信息、演出活动名、平台名、官方账号名、个人基础信息（生日、身高、体重、年龄等）。
- 纠错后仍存在信息歧义（同一词汇有 2 种及以上可能正确表述）时，列出所有候选正确项并标注「待验证（参考数据源：XXX）」，禁止单一主观判断。
- 无权威数据支撑的新增误识词，标注「暂存纠错：原词 XXX→候选词 XXX（待数据源补充验证）」，后续同步更新至数据库。
- 「封茗囧菌」相关固定词被拆分、截断（如「封 茗囧菌」「封茗 囧菌」「封茗囧菌 咨讯站」）时，自动合并为完整标准表述。

### 常用词纠错方法（三法合一）

综合运用三种方式精准定位并修正，深度适配直播场景特性：

1. **拼音匹配**：全拼、简拼、同音、近音、口音谐音。
2. **字形模糊匹配**：形近字识别。
3. **上下文语境关联**：结合前后文、直播场景常用逻辑做最优匹配。

纠错必须完整保留原文本的核心语义、口语化风格、说话人语气与原意，仅针对识别错误的错字、别字、音近形近错字进行修正，禁止过度修改、随意增减原文内容；语义模糊、识别不清的片段，结合前后文语境、拼音谐音、直播场景常用逻辑进行最优匹配修正，确保修正后通顺连贯、符合日常口语表达逻辑。
