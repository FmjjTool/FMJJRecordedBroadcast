# 腾讯文档同步编辑范围约束（强制阅读）

## 定位

本项目对「腾讯文档」的写入能力有**硬性范围限制**：只允许编辑两张表，其余一律禁止。

- 允许编辑：`官方动态`、`直播记录`（仅这两张）。
- 禁止编辑：`线下活动`、`完整歌曲`、`歌曲片段`，以及奖讯热榜、周边图鉴、更新日志、官方动态「图集数据库」、囧菌百科等**其余全部页面**，以及其他所有腾讯文档（百科用户反馈与收集、无料周边汇总、用户协议与编辑须知等）。

本 skill 与 `convention-skill` 同时适用：先读 `convention-skill`（拉取/提交约定），再读本 skill（范围约束）。范围问题一律以本 skill 为准，**不放宽、不例外、不因效率或「顺手」而通融**。

本 skill 是纯 Markdown 约束：不提供脚本、不依赖任何 JSON 或其他机器可读清单，白名单与黑名单以下文表格为唯一依据，判断由 Agent 逐项人工核对完成。

## 强制阅读规则

1. 只要任务**触及**腾讯文档同步链路，第一步必须完整阅读本 skill，之后才允许执行任何动作。
2. 触及判定（满足任一条即触发，宁可多读）：
   - 执行或修改「腾讯文档」自动同步、定时采集、增量同步、写回、批量填充、复制粘贴上传；
   - 读写 `src/toolbox/tcdoc/`、`src/gui_qt/pages/tcdoc*.py`、`download/腾讯文档数据/` 下任何内容；
   - 改动腾讯文档的工作表结构、记录、字段、视图、关联、公式列；
   - 生成或覆盖 `表格数据/*.xlsx`、`正文存档/*.md` 等导出产物；
   - 用户的描述里出现「动态」「直播」「线下」「歌曲」「汇总库」「同步数据」等词。
3. 未阅读本 skill 就动手改同步范围相关代码，视为违规；已产生改动必须全部回滚。
4. 条目只能追加，连续编号，不得删除或篡改已有条目。

## 禁止行为清单

以下行为一律禁止，不得以任何理由绕过：

1. 对白名单外的表执行新增、修改、删除、批量填充、清空、排序重排、去重覆盖。
2. 通过改表名、复制表、新建表、临时 sheet 的方式变相承载禁写表内容（例：把歌曲数据写进「官方动态」表）。
3. 修改白名单表的**表结构**：增删字段、改字段类型、改字段名、改选项值、改公式、改视图、改关联关系、改权限。结构变更需用户单独明确授权，默认禁止。
4. 改动或覆盖禁写表的导出产物（`表格数据/*.xlsx`、`正文存档/*.md`、`修订记录`、`成员名单`、`报表`）的**数据内容**。只读查看、读取统计不受限。
5. 把同步范围从两张表扩大到全库（如去掉 `_is_sync_sheet` 校验、按 `SYNC_KINDS` 全量写回、把 target 列表改成「所有工作表」）。
6. 以「全量同步」「数据修复」「一致性对齐」「顺手统一」为借口触碰禁写表。
7. 目标 `tab_id` 无法确认时「猜一个」就写入。
8. 删除或篡改本 skill 的白名单/黑名单条目。

## 上传前置条件（数据清洁度）

表格写入（含中间层「上传到腾讯文档」）必须是**刚刷新过的数据**：

1. 先点「同步前刷新」：采集平台资料（采集任务 + 网媒账号）→ 重新拉取一遍腾讯文档表格快照；
2. 三步都成功才允许上传；任一步失败，上传锁定并列出失败步骤，不允许跳过；
3. 刷新记录 60 分钟过期，上传成功后自动作废——下一次上传必须重新刷新；
4. 禁止绕过该门禁直接调用写回接口（`import_pending.run(..., apply=True)` 等），也不允许用旧快照凑合上传。

实现：`src/toolbox/sync_refresh.py`（状态 `config/sync_refresh.json`）、`gui_qt/pages/tcdoc_bridge.py` 的「同步前刷新」按钮与上传门禁。

### 免校对模式（2026-11-23 用户授权）

用户明确要求为腾讯文档推送增加「免校对模式」，用于快速补录少量已确认的新作品：

1. 模式由用户在中间层工具条勾选「免校对模式」开启，保存在 `config.json` 的 `tcdoc_skip_sync_refresh`；默认关闭，不记忆到其他入口。
2. 开启后，中间层批量上传、右键单行上传、资产页单条上传不再要求「同步前刷新」（资产页也不再自动刷新），直接用当前本地数据与已有快照写入；写回时仍会读取云端当前行做去重。
3. 关闭后恢复上文全部门禁。任何 Agent 不得默认开启该模式，也不得在未开启时绕过刷新门禁直接调用写回接口。
4. 该模式只放宽刷新门禁，不扩大写入范围：白名单表、仅新增、下拉选项当次确认、备注追加等约束全部不变。
5. 风险：快照过期时可能漏判云端已有行；重复链接仍由写回时的读回/重复检测提示人工核对。

## 执行前强制自查（不可跳过）

任何写入动作之前，逐项核对：

1. 目标文档 `doc_key` 是否为 `DRnd3bkhkQUR1aEJr`——不是则直接停止。
2. 目标表 `tab_id` 是否等于 `ss_h2uh2s` 或 `ss_1xgstm`——不是则直接停止。
3. **以 `tab_id` 为唯一判据**，禁止只按表名匹配（表名可被改动，同名不同 tab 的情况必须按 id 判定）。
4. 写入范围必须逐条限定到具体 record（record_id 或明确的新增行），禁止无差别整表覆盖。
5. 任一项核对不通过 → **立即停止**，不写入、不「先写一部分」，向用户说明被拦截的表名与 tab_id，并给出可选方案（只处理允许的两张表 / 用户单独授权 / 取消）。

## 执行后强制汇报

每次写入完成后输出变更清单，缺一不可：

- 目标文档名 + `doc_key`；
- 表名 + `tab_id`（必须落在白名单内）；
- 操作类型与条数（新增 / 修改 / 删除各多少条）；
- 被修改的 `record_id` 列表（或新增行的定位字段）；
- 是否触碰过白名单外的表：必须明确写「未触碰」，若有则立即说明并回滚。

## 越界处理

1. 发现自己在禁写表上已经产生改动：**立即停止后续操作**，列出改动清单，等用户确认后回滚或保留；不得继续扩大改动。
2. 发现历史代码里已存在越界写回逻辑（例如同步任务默认遍历全库）：不得沿用，必须改为白名单驱动，并在改动说明中标注修复点。
3. 需求本身要求编辑禁写表：不执行，向用户复述约束并请其明确授权；授权只对当次操作有效，不沉淀为默认放行。
