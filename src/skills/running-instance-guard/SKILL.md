# 运行中实例保护（Running Instance Guard）

先阅读 [convention-skill](../convention-skill/SKILL.md)。涉及文件与提交时按约定 2/4；涉及录制、采集、同步时同时遵守对应业务 skill。

本 skill 是**强制规则**，不是建议：它约束 Agent 对「已经在运行的程序」的所有操作。

## 一、核心规则

1. **运行中的软件不允许被 Agent 关闭。** 包括但不限于：关闭主窗口、关闭二级窗口、结束进程、发退出指令、重启服务、停止后台任务。
2. **只允许新建。** 需要验证新代码、新配置或新窗口效果时，另起一个新实例（新进程、新端口、新工作目录），不得先杀掉旧实例。
3. **重启必须由用户自己操作**，或用户对本次操作明确说出「关闭 / 结束 / 重启」并要求执行；即便如此，也要先说明风险再动手。
4. 违反规则的典型表现：`taskkill`、`Stop-Process`、`kill`、关窗口、点「退出」、删除正在运行的 `.exe` 或它所在目录、覆盖被占用的文件、强制 `git checkout` 掉运行中程序的源码。

## 二、如何判定「正在运行」

按成本从低到高逐项确认，任一项成立即视为运行中：

| 信号 | 说明 |
| --- | --- |
| 进程 | 任务管理器 / `tasklist` 里存在 `FengMingToolbox.exe`、`pythonw.exe`、`python.exe`（带本项目脚本）、`node.exe` 等 |
| 窗口 | 主窗口、直播录制二级窗口、弹幕浮层、托盘图标仍在 |
| 端口 | 本地资料站、Web 服务端口处于 `LISTENING` |
| 业务状态 | 正在录制（已录时间在走）、正在采集、正在同步腾讯文档、正在打包/上传 |
| 文件锁 | 目标文件被占用、写入失败、`PermissionError` / `WinError 32` |

## 三、禁止与允许

**禁止：**

- 结束、重启、挂起任何属于本软件或用户的进程。
- 关闭窗口、点「退出」、通过脚本发送退出消息。
- 覆盖、替换、删除正在运行的 exe / dll / 配置目录。
- 以「让改动生效」为理由先杀进程再启动。
- 用 `git reset` / `checkout` / `stash` 覆盖运行中实例依赖的源码。

**允许：**

- 新建实例：新进程、新端口、独立临时配置目录（`--work-dir` 之类）。
- 只读检查：进程列表、端口、日志、窗口截图、数据库快照。
- 让用户自己关闭或重启，并说明为什么需要重启。
- 在用户明确授权下执行关闭；执行前必须提示：
  - 正在录制 / 监控时关闭可能损坏正在写入的文件（本软件会在关闭时弹确认，并支持「停止并打包」）；
  - 正在采集 / 同步时关闭会中断本轮任务。

## 四、与录制保护的衔接

- 直播录制、弹幕录制、腾讯文档同步、账号采集都属于「有写入中的文件或未完成事务」的流程。
- 关闭前必须先走正常收尾（停止录制 → 等文件写完 → 打包；或停止采集 → 保存进度），不允许直接杀进程。
- 用户要求「关掉重新开」时：先提醒风险与收尾方式，再由用户决定；Agent 不代替用户点关闭。

## 五、执行检查清单

- [ ] 动手前确认过进程 / 窗口 / 端口 / 录制状态，知道软件是否在运行。
- [ ] 没有执行 `taskkill`、`Stop-Process`、`kill`、关窗口、点退出等操作。
- [ ] 需要验证时用的是新实例 / 新端口 / 临时目录。
- [ ] 需要重启时已说明原因与风险，并交给用户操作（或取得本次明确授权）。
- [ ] 没有覆盖或删除运行中的 exe、目录与被占用的文件。
- [ ] 涉及录制 / 采集 / 同步时，确认收尾路径可保留文件与进度。

## 六、例外与边界

- 用户明确说出「结束掉 / 杀掉 / 强制关闭」并指向具体进程时，按用户指令执行，但仍要先提示数据风险。
- 进程已崩溃、无响应且用户要求清理时，可协助只读定位原因；是否结束由用户决定。
- 本 skill 不改变 `convention-skill` 的提交与报告要求，也不授权修改 Cookie、腾讯文档写入范围或录播核心八模块。
