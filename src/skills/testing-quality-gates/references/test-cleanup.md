# 测试文件与本地残留清理

本文件是测试清理的唯一正文，入口为 [testing-quality-gates](../SKILL.md)。先遵守 [总约定](../../convention-skill/SKILL.md)、[真实凭据保护](../../cookie-data-protection/SKILL.md) 与 [并行协作](../../convention-skill/references/coordination.md)。

## 项目选择与触发

用户选择 `tests/` 作为一次性本地验证目录：已被 .gitignore 忽略，验证后删除、不备份、不入库。代码任务收尾、测试产物收尾或用户明确要求清理时执行；纯只读或仅 Markdown 维护且未生成测试产物，不自动清理其他任务历史残留。不得为了持续回归擅自取消忽略或把测试入库；用户当次明确保留用例或维护测试基础设施时，保留其指定范围并报告。

**先测后删**：先完成适用测试并记录真实结果，失败应先修复或明确定位与报告，再清理。不能以清理为由跳过测试、缩减范围或删除失败证据。

## 所有权与确认边界

| 对象 | 默认处理及确认要求 |
| --- | --- |
| 本任务自己创建且已完成使用的测试文件、缓存、可再生输出 | 按本规则清理；现有项目约定已授权，无需重复逐项申请 |
| `tests/` 整体（含历史用例）与测试缓存 | 先确认目录没有并行使用者且当前任务已获得目录清理所有权，再按项目规则整删、不留空目录；不能只凭“任务结束”清空共享目录 |
| 并行任务在用、用户正在编辑、归属不明的文件 | 不动、不移动；说明归属待确认，只清理自己可确认的路径。整删延期并报告残留，不冒充已完成 |
| 根目录批量临时目录/历史残留 | 先列具体清单并取得用户明确确认；泛称“很乱/没用”不是删除授权 |
| `_smoking/` 整目录、用户提供或可复用的脚本 | 默认保留；整删或删用户脚本须用户明确确认 |
| 备份/真实环境快照 | 还原校验完成且用户对具体目录明确确认后，移入回收站；不直接永久删除 |

用户已在本轮明确授权具体删除清单时继续执行，不重复询问。批量根目录清理的确认要求不反向覆盖已授权的本任务临时文件清理，但不允许以此扩张到陌生文件、整个共享目录或备份。

## 目录与范围

- `tests/`：自动化测试与 fixture；取得整目录清理所有权后全部删除，后续需要时重建。
- 测试缓存：本任务生成的 `__pycache__/`、`.pytest_cache/`、*.pyc / *.pyo、.coverage、coverage.xml、htmlcov/、.tox/、.nox/ 与测试报告。不得按通配符扫进运行实例、用户数据或他人测试工作区。
- `_smoking/`：所有手动冒烟/联调脚本、harness、临时数据、日志和过程截图的固定位置，不散落根目录、`tests/`、src/ 或 Progress/。建议按任务子目录区分所有权；默认保留可复用脚本，只清理本任务可再生输出。禁止强制添加、提交或推送。
- `Progress/ui/<日期>/`：仅最终报告证据截图，不当作临时输出删除。

根目录历史残留候选如下，**只是识别清单，不能凭名字认定可删**：

| 类别 | 示例 |
| --- | --- |
| 一次性目录/探针 | .tmp/、`_tmp_*`、`_probe_*`、`_test_ks_*` |
| 历史烟测 | _smoke/、`_smoke_*.py`、`_smoke_*.png` |
| 调试页面与导出 | `_fc.html`、`_s1.html`、`_taobao_debug/`、`_dyx_debug/`、`test/_out/`、`test/_dump/` |
| 编辑器/Agent 暂存 | `.qoder-input-files/`、`.qoder-input-images/`、`.codeartsdoer/`、`.trae/`、`.trae-html-share-packages/`、`.workbuddy/`、`.workbuddy-ai/` |

发现散落烟测时先确认所有权；本任务产物可移入 `_smoking/`，他人或不明归属不得擅自整理。新增同类产物的忽略规则仅在本次授权范围内补齐，不改 `tests/` 忽略策略。

## 不得触碰

- 源码、资源、真实数据与凭据：不借清理删除 src/、用户 `config/` / `download/` / `logs/` / `models/`、登录快照或真实 Cookie。
- 默认不清理报告、证据、构建产物与未列明内容：Progress/、`build/`、`build_full_vendor/`、`dist/`、*.spec、docs/、task.md、_ref/、.uploads/、用户导出等。
- `_smoking/`real-snapshots/ 属于恢复点，遵守 [隔离测试](isolated-testing.md)，不得随缓存删除。
- 被跟踪文件先停止自动删除并核对用途。若确认为应保留本地的运行数据，按总约定和已授权清单 git rm --cached 并补准确忽略项，保留本地文件；不借清理修改他人源码或取消跟踪业务资产。

## 执行与验证

1. 读取最新状态，列明本次归属、删除范围与大致数量；并行时先协调。检查引用、进程占用与 `git ls-files -- <路径>`，被源码依赖、被跟踪或用途不明则保留并报告。
2. Windows 删除或移动前解析绝对目标，确认位于获准目录，检查链接/junction，避免越界。只用同一 shell 的原生命令和明确路径，不把枚举结果拼进另一 shell 的删除命令。
3. 取得所需确认后删除；文件占用时停止并说明，不为清理结束用户进程。自己的完全隔离实例先按 [运行保护](running-instance-guard.md) 正常收尾。失败不重复强删、不扩大范围。
4. 检查 git status 与 git ls-files _smoking，确认没有临时文件、缓存、凭据或真实数据入库；新增忽略项用 git check-ignore -v 核对。无需为证明已删启动应用。
5. 按总约定记录已删范围、数量/可可靠测量的空间、保留项及原因；无法清理的并行测试、占用或快照明确列出。再由负责提交者汇入唯一当日报告并本地提交。
