# 隔离测试与真实数据还原

本文件是隔离与还原的唯一正文，入口为 [testing-quality-gates](../SKILL.md)；旧名 [isolated-testing](../../isolated-testing/SKILL.md) 仅作兼容跳转。先遵守 [总约定](../../convention-skill/SKILL.md)、[真实凭据保护](../../cookie-data-protection/SKILL.md) 与 [运行保护](running-instance-guard.md)。

## 默认隔离与真实接入边界

人工测试、自动化验证、UI 冒烟、演示、截图与联调默认使用隔离程序副本，不在主工作区启动会初始化配置的脚本或应用，不连接用户实例。真实 `config/`、`download/` 及其他真实数据**默认只读**；这里的只读不是默认接入许可，读取真实配置、数据库或驱动真实界面仍需当次具体批准。只读检查进程/端口/窗口是否存在和必要日志尾部不算接入，日志不得输出凭据。

仅用户对本次具体范围明确批准后，列明的**非凭据文件**才可按下文快照与还原流程暂时写入；未获批的真实路径继续只读。授权接入不解除运行实例保护、录播核心保护或腾讯文档白名单。真实 Cookie、登录快照及关联凭据仍绝对禁止改动、复制或回滚，无“先备份再测试”例外；包含凭据的文件整体排除。

## 隔离副本要求

| 维度 | 必须满足 |
| --- | --- |
| 程序根 | 独立目录，建议 `_smoking/isolated/<任务名>/`；无指回真实数据的链接/junction |
| 数据根 | 副本自己的 `config/`、`download/`、`logs/`；启动前确认路径只落副本 |
| 凭据与样本 | 虚构凭据、假主播、临时空库和最小 fixture；不复制真实配置、主播列表、数据库、登录快照 |
| 进程与端口 | 新进程、独立生命周期；WebUI 使用未占用端口并记录 PID |
| 输出 | 测试媒体、截图、导出、日志只写副本或本任务 `_smoking/` 子目录 |

本项目没有 --work-dir 数据目录参数；get_app_root() 在开发态跟随程序文件所在根，打包态跟随 exe。因此切换 cwd 不能隔离，必须运行副本。

1. 复制本次所需源码与静态资源到独立目录，排除 .git、真实 `config/` / `download/` / `logs/`、模型缓存、构建产物、测试缓存和 `_smoking/` 自身；不要整树无筛选复制。可用独立 Git worktree 验证已提交版本，未提交改动须按本次文件归属精确同步。
2. 在副本中检查路径函数的实现，再在副本内执行所需路径确认；包括 get_config_dir() 在内的“读取”可能建目录，不能在真实根用导入来探测。若解析到真实目录立即停止并修复。
3. 手工构造假 `config/live_record.json`、临时 SQLite 和几秒测试媒体。不从真实账户取凭据来补隔离环境；获准的只读真实业务请求也不能混进默认隔离测试。
4. 在副本启动桌面或 `python main.py --webui --webui-port <空闲端口>`，记录 PID、端口、目录。改动后只同步相应源码再重启自己的副本；不关闭用户实例。
5. 大模型共享仅在可确认无写入的情况下可选，不能经链接启动下载、升级或清理；无法证明只读时不共享。凭据与用户数据绝不通过此方式共享。
6. 收尾按 [清理规则](test-cleanup.md) 处理本任务产物；隔离配置不复制回真实环境，Agent 自建完全隔离实例可正常关闭。

## 真实接入申请

能用隔离副本、最小 fixture 或静态分析证明的，先用这些方式。确需真实窗口状态或无法构造的数据结构时，申请中必须说明以下六项：

1. 目的与必要性：隔离方式为何不足。
2. 目标与范围：具体实例/窗口/PID、页面、只读或写入、线上副作用。
3. 数据清单：实际文件、数据库及计划任务；直播录制须点名实际涉及的 `config/live_record.json` 等。凭据文件明确排除。
4. 快照方案：非凭据快照范围、位置、一致性与 SHA-256 清单。
5. 还原方案与校验：还原时机、是否需要用户先关闭软件、对比方式。
6. 风险与时长：录制/采集/同步中断、可能覆盖的用户变更与预计时长。

当次明确同意才执行；“看一下”“试试”不构成真实写入授权。已有授权覆盖相同明确范围时不重复申请，但不得扩大到其他实例、文件、平台或操作。只读接入不做不必要的数据复制或恢复；写入前必须有可用快照。计划任务安装/删除必须单独列入申请，腾讯文档写入仍先核对白名单。

## 写入前快照

只对获批非凭据文件执行，快照放 `_smoking/real-snapshots/<日期>_<任务名>/`，不提交、不推送、不进入发行包。

- 普通文件：整文件复制并保留时间戳，记录相对路径、大小、修改时间、SHA-256；原本不存在的路径也记入清单，便于删除仅本次创建的文件。
- SQLite：使用只读源连接及备份 API 做一致性快照，记录各表行数与关键业务数据。不直接复制正在写入的裸库；必须裸复制时先确认停止写入，连同 -wal / -shm 记录一致集合。
- 计划任务：导出 XML 并记录原先存在/不存在的状态。
- 快照清单和报告只记必要路径、大小、哈希及状态，不输出数据正文、个人信息或凭据。没有快照、存在凭据混存、无法取得一致性或无法确保还原时不写入。

直播录制必须覆盖实际涉及文件，而不只单项主播记录：

| 文件 | 核对内容 |
| --- | --- |
| `config/live_record.json` | 主播列表、备注、平台/房间号、顺序、启用、录制质量/内容/分段、监控与录制状态 |
| `config/live_rooms.json` | 账号/房间号解析缓存 |
| `config/bili_live.json`、`config/douyin_live.json` | 最近连接房间与平台设置 |
| `config/douyin_live_rooms.json` | 抖音房间缓存 |

## 写入后还原

成功、失败、中断均须完成：停止本次测试操作 → 等待写入完成 → 按快照整文件还原 → 校验 → 报告。不得用“删除测试主播/测试项”或凭记忆重新添加代替还原。

1. 运行实例会回写内存状态时，请用户先正常关闭，或仅按已明确取得的本次指定实例关闭授权正常收尾；不能因需要还原而擅关。用户不关闭且无法安全还原时停止写入并报告风险，不声称已恢复。
2. 普通文件从快照覆盖；仅删除清单明确记为原本不存在、由本次测试创建的非凭据文件。数据库恢复一致的库与 WAL/SHM 状态，避免旧库配新日志；任务按原 XML/原存在状态恢复。
3. 普通文件 SHA-256 与清单一致；JSON 整体业务数据一致；SQLite 执行完整性检查并对比关键数据和行数。数据库物理字节可能因备份 API 改变，不能只以文件哈希代替数据库一致性。直播录制再逐项核对表中全部信息。
4. 若测试期间用户修改同一份数据，立即停止覆盖，说明新旧差异，请用户决定保留范围；不能用旧快照抹掉用户新改动。
5. 失败、被运行实例覆盖、快照损坏或文件占用时，停止继续写入，保留快照和现场，报告未还原项、原因、快照位置与下一步，不反复强制覆盖。

任务取消或切换前先还原；无法完成时当次明确交代已改路径、快照与所需操作。真实凭据若意外变化，遵守凭据保护规则立即停止，**不自行回滚凭据**。

快照是恢复点，还原校验完成且用户确认后才可按清理规则移入回收站，不能随普通缓存删除。报告遵守总约定，只写实际执行与未完成项。
