# 界面交互与反馈规范

先阅读 [convention-skill](../convention-skill/SKILL.md)（流程约定）与 [ui-visual-spec](../ui-visual-spec/SKILL.md)（颜色、字号、留白、页签层级、按钮排布）。三者分工：

| skill | 管什么 |
| --- | --- |
| `ui-visual-spec` | 长什么样：颜色、字号、圆角、留白、边框、图标、按钮排布 |
| 本 skill | 怎么用：弹窗、表格、状态、表单、文案、反馈通道 |
| `convention-skill` 约定 14 | 表格必须可排序（唯一实现 `gui_qt/table_sort.py`） |

本 skill 不改变业务逻辑，也不构成核心八模块的改动授权。数值与现有实现不一致时，**只在改到该处时收敛**，不批量返工。

## 一、弹窗与二级窗口

现状：`src/gui_qt` 下有 43 个 `QDialog` 子类，尺寸从 430×340 到 1320×800，按钮区、Esc/Enter、确认文案各写一套。新代码按本节，旧窗口改到时收敛。

### 1.1 先决定形态

| 场景 | 形态 |
| --- | --- |
| 必须用户当场决策才能继续（覆盖、删除、覆盖同名、授权） | 模态对话框 |
| 长任务、参数配置、需要边看主界面边操作（投稿、录制、弹幕） | 非模态独立窗口 |
| 一次性的短输入（改名、改时间、粘贴文本） | 模态对话框 |
| 只告知结果、无需决策 | `toast` 或状态栏，不弹窗 |

规则：

1. 模态只用于「不回答就不能继续」。耗时操作一律非模态独立窗口，主界面保持可操作。
2. 独立窗口可自由拖动、关闭不影响主界面正在跑的任务；关闭只停本窗口的渲染/预览。
3. 不得用 `QMessageBox` 承载需要输入或展示列表的内容。

### 1.2 尺寸

| 项 | 值 |
| --- | --- |
| 紧凑型（单表单） | 720×520 |
| 标准型（两栏或列表） | 900×640 |
| 宽型（表格/预览） | 1040×720 |
| 上限 | 不超过主窗口可用区；屏幕小时按可用区收缩 |
| 下限 | `setMinimumSize` 不低于 420×300，避免挤成一条 |

规则：

1. 首次打开居中于父窗口；不记忆上次位置，避免多屏拔插后跑出可见区。
2. 允许 `resize` 的窗口要设 `minimumSize`；不允许调整的设 `setFixedSize`，不留可拖拽的假象。
3. 内容超出高度时用 `QScrollArea`，不让按钮区被挤出屏幕（`bili_upload_dialog.py` 的 820×890 是反例，需改滚动）。

### 1.3 按钮区

统一 `QDialogButtonBox`，放在内容区下方、右对齐。

| 位置 | 内容 |
| --- | --- |
| 最右 | 主操作（确定 / 保存 / 开始），`variant="primary"` |
| 主操作左侧 | 取消 / 关闭（`secondary` 或默认样式） |
| 最左 | 破坏性操作（删除 / 清空），`variant="danger"`，与主操作隔开 |

规则：

1. 按钮顺序固定「危险 … 取消 主操作」，Windows 习惯，不按语序排。
2. `Esc` 等价取消；`Enter` 等价主操作——**破坏性操作不绑 Enter**，避免误触。
3. 主操作执行中禁用按钮并显示进度，不允许连点；关闭按钮此时应提示任务仍在后台。
4. 按钮文案用动词（保存 / 开始 / 删除），不用「确定 / 好的」这种无信息量词，除非纯确认框。

### 1.4 二次确认

破坏性、不可撤销、会影响真实数据的操作必须先确认。

确认框必须包含三段：

1. **做什么**：`删除「XX」？`（带对象名，不写「确定删除吗？」）
2. **影响**：`将同时移除本地文件与索引记录，不可恢复。`
3. **默认安全**：默认按钮是「取消」，`Esc` 也是取消。

规则：

- 一次只确认一件事；批量操作在正文写清数量与范围（`共 12 条，其中 3 条已上传`）。
- 已加二次确认的操作不再叠加第三层确认。
- 现状：`QMessageBox.question` 共 49 处、分布在 25 个文件里，各写按钮组合，改到时统一成「取消 + 确认」两键，确认键文案写具体动作。

### 1.5 标题与身份

1. 标题 = 动作或对象名，2–8 字（`封面制作`、`删除账号`），不带「窗口 / 对话框」后缀。
2. 带系统标题栏的窗口由 `theme._set_native_titlebar()` 对齐深色；无边框外壳走 `window_chrome`，**不要为单个窗口重写标题栏与缩放**。
3. 独立窗口在任务栏有独立条目时，标题要能区分（如「弹幕姬 · 抖音」）。

## 二、表格与列表

### 2.1 列与宽度

| 项 | 规则 |
| --- | --- |
| 勾选列 | 第一列，宽 36，表头空或复选框；不参与排序 |
| 序号 / 图标列 | 宽 40–56，固定 |
| 文本列 | 给 `setMinimumWidth(60~140)`，最后一列 `Stretch` 吃掉剩余宽度 |
| 长文本 | 省略号 + tooltip 全文；不换行撑高行 |
| 操作列 | 只用图标按钮 30×26 + tooltip；超过 2 个收进行内「更多」 |

规则：

1. 同一页同类表格列宽策略一致；不为个别数据临时调宽。
2. 不允许横向滚动条成为常态：列总宽超出时先砍非关键列或合并展示。
3. 表头文案 2–6 字，单位写进表头（`点赞数` 而不是 `点赞数量（个）`）。
4. 勾选列必须统一自绘：主程序用 `theme._CheckProxyStyle`（`QProxyStyle` 接管 `PE_IndicatorCheckBox` / `PE_IndicatorItemViewItemCheck`）——未选 `base` 底 + 1px `mid` 圆角 3，选中 `highlight` 实心 + `highlighted-text` 勾；QSS 只保留 `::indicator` 尺寸。不要只写 `::indicator:unchecked`（选中态会落回原生，一列两种观感）。若改用 delegate 自绘，必须 `opt.features &= ~QStyleOptionViewItem.HasCheckIndicator`，否则原生方框与自绘框叠成双层（样张实测）。

### 2.2 排序与分页

1. 排序按 `convention-skill` 约定 14，统一 `gui_qt/table_sort.py`，不自写比较。
2. 分页文案统一：`第 3 / 12 页 · 共 2 341 条`（`asset.py` 现有写法可作为基准）。
3. 分页控件放表格下方右侧：`首页 · 上一页 · 页码 · 下一页 · 末页`；首页/上一页在第一页置灰，下一页/末页在末页置灰。
4. 默认每页 200 条（`info_results.PAGE_SIZE`、`asset._DB_PAGE_SIZE`）；超过 200 条的渲染分批 20 条追加，避免一次建几千行卡顿。
5. 筛选条件变化后回到第 1 页；排序变化后也回到第 1 页（服务端分页表必须重查）。

### 2.3 列宽自适应 / 重置

所有表格必须支持列宽自适应与重置，统一由 `gui_qt/table_columns.py` 提供，页面不自写列宽菜单或第二套列宽逻辑。

| 入口 | 行为 |
| --- | --- |
| 表头右键 | 「列宽自适应」「重置列宽」 |
| 主窗口状态栏「自适应 / 重置」 | 两个直接按钮，对当前（最后聚焦的）表格执行同样操作 |

规则：

1. 列宽自适应按内容宽度分配并尽量填满视口；内容较宽的主列吸收剩余宽度。
2. 重置恢复表格首次显示时的宽度；没有快照时退化为自适应。
3. 默认布局应铺满且不出现横向滚动；手动拖宽后允许出现滚动条，用上述入口恢复。
4. 列宽操作不改变表格数据、勾选、排序方向或分页状态。
5. 统一实现只在 `gui_qt/table_columns.py`，页面不得新增列宽按钮或自建表头右键菜单。

### 2.4 空态与加载态

| 状态 | 表现 |
| --- | --- |
| 未开始 / 无数据 | 不显示空表头，显示一条引导：`还没有数据，点「抓取评论」开始` |
| 筛选无结果 | 说明原因与出口：`当前筛选无结果（共 320 条），可切回「全部」` |
| 加载中 | 骨架屏（`skeleton.LoadingSkeleton`）或表内一行「加载中…」，超过 1 秒才显示 |
| 加载失败 | 一行错误 + 「重试」按钮，错误写原因，不只写「失败」 |

规则：

1. 空态必须写「为什么空 + 下一步做什么」，禁止只写「暂无数据」。
2. 空态文案 11px `placeholder-text`，垂直居中，不撑满整块。
3. 加载中禁止用模态遮罩挡住主界面；表格区域局部提示即可。

### 2.5 双击与右键

1. 双击 = 打开详情 / 预览 / 进入下一级；**不执行删除、覆盖等破坏性动作**。
2. 右键菜单必须与工具栏同能力，只做就近入口，不新增长流程。
3. 右键菜单项超过 8 个要分组（分隔线），破坏性项放最后并独立分组。

## 三、状态与反馈

### 3.1 反馈通道怎么选

| 通道 | 用于 | 时长 / 位置 |
| --- | --- | --- |
| `toast` | 操作成功的轻提示、开关变化 | 2–3 秒，右下或底部居中 |
| 状态栏 | 常驻状态、当前任务、计数 | 窗口底部，`showMessage` 不写日志 |
| 行内提示 | 表单校验、字段错误 | 控件下方，11px |
| 对话框 | 需要决策、批量结果汇总 | 模态，用户必须响应 |
| 日志区 | 过程明细、失败原因 | 页面内只读区，可复制 |

规则：

1. 成功提示不弹窗（`toast` 足够）；失败如果影响用户继续操作，才弹窗。
2. 同一事件只走一个主通道，不 toast + 状态栏 + 日志三处重复同一句。
3. toast 语义色只有 info / success / warning / error 四种，不自定义颜色（见 `ui-visual-spec` 2.6）。

### 3.2 长任务

1. 必须有可见进度条（`QProgressBar`），不能只有「45%」文字。
2. 必须可取消；取消后停在该步并保留已完成部分，状态写「已取消（完成 3/8）」。
3. 任务期间主界面可操作，不弹模态；不可重复触发同一任务（按钮置禁用）。
4. 完成后的结果去向要写清（存到哪个目录/哪一页），不能只提示「完成」。
5. 进度不确定时用忙碌态（`setRange(0, 0)`）+ 当前动作文案，不假装百分比。

### 3.3 错误文案

统一三段式：**做什么失败 + 原因 + 下一步**。

| 反例 | 改法 |
| --- | --- |
| `出错了` | `抓取评论失败：登录已失效，请到「账号与登录」重新登录后重试` |
| `未知错误` | `保存失败：目标目录不可写（D:\…\导出），请改到其他目录` |
| `失败` + 堆栈 | 界面写人话，堆栈只进日志 |

规则：

1. 不显示堆栈、绝对路径、请求头、凭据、Cookie 字样（见约定 9）。
2. 同一失败在不同页面用同一句文案，不各写一版。
3. 可重试的失败必须给「重试」入口；不可重试要说明为什么。

### 3.4 状态词

全项目只用这一组：

| 状态 | 文案 |
| --- | --- |
| 未开始 | `未开始` |
| 进行中 | `进行中` / `抓取中`（带具体动作） |
| 成功 | `已完成` |
| 失败 | `失败`（后面必须跟原因） |
| 取消 | `已取消` |
| 跳过 | `已跳过`（后面跟原因，如「已存在」） |

禁止：「处理中」「正在处理」「完成」「OK」「Done」等自造词混用。

## 四、表单与输入

### 4.1 结构

1. 左标签、右控件；标签右对齐，同组标签等宽（取最长）。
2. 不用 placeholder 代替标签：placeholder 只放格式示例。
3. 表单分组用卡片或 `QGroupBox`，一组不超过 8 个字段。
4. 字段顺序按填写逻辑，不按代码结构。

### 4.2 必填与校验

1. 必填项标签后缀 `*`，并在表单底部说明 `* 为必填`。
2. 校验时机：格式错误在失焦时提示；完整性在提交时统一校验。
3. 错误提示显示在控件正下方，11px `danger`，同时把控件边框改成 `danger` 语义。
4. 提交校验失败时，焦点跳到第一个错误字段，并汇总一行「还差 2 项必填」。
5. 不做输入过程中的红框闪烁；用户还没填完不报错。

### 4.3 控件选择

| 数据 | 控件 |
| --- | --- |
| 目录 / 文件 | 只读输入框 + 「浏览」按钮；输入框显示末尾路径，tooltip 全文 |
| 数值 | `QSpinBox` / `QDoubleSpinBox`，带范围与后缀单位；不用 `QLineEdit` 收数字 |
| 枚举（≤12 项） | 下拉，规则见 `ui-visual-spec` 5.6 |
| 布尔 | `QCheckBox`；开关型功能勾选后 toast「已开启 XXX」（`common.bind_checkbox_toasts`） |
| 多行文本 | `QPlainTextEdit`，给最小高度，不自动撑高 |
| 日期时间 | 统一用现成控件（`calendar.py` / `time_wheel.py`），不自造 |

规则：下拉、滑条、数字框不响应滚轮改值（滚轮只滚页面），与 `ui-visual-spec` 5.6 一致。

### 4.4 提交与保存

1. 主操作固定在表单右下；保存中禁用并显示进度。
2. 保存成功后：`toast` + 关闭弹窗（或留在原页刷新数据），二选一，不两者都做。
3. 有未保存改动时关闭，必须确认「放弃修改？」。
4. 保存失败留在原页，不清空已填内容。

## 五、文案

### 5.1 按钮动词表

| 语义 | 用 | 不用 |
| --- | --- | --- |
| 从平台拉数据 | `抓取` | `获取`、`拉取`、`采集一下` |
| 启动任务 | `开始` | `启动`、`运行` |
| 中途停下 | `停止`（不可续）/ `暂停`（可续） | `结束`、`中断` |
| 重新执行 | `重试` | `再试一次`、`重新开始` |
| 输出文件 | `导出` | `保存为`、`下载`（下载专指从网盘取） |
| 写入配置 | `保存` | `确定`、`应用` |
| 删除 | `删除` | `移除`、`清理`（清理专指批量临时文件） |
| 刷新视图 | `刷新` | `更新`、`重新加载` |

规则：同一页面同类动作只用一个词；按钮不加标点；会弹窗的菜单项结尾加 `…`（`批量改名…`）。

### 5.2 数量与格式

1. 单位：`条 / 个 / 张 / 首 / 场 / 位`，按数据类型固定，不混用「个」表示评论。
2. 千分位用空格或逗号统一一种（分页文案用空格：`2 341 条`）。
3. 时长 `mm:ss` 或 `hh:mm:ss`，不写 `90 分钟` 与 `1:30:00` 混排。
4. 日期 `2026-11-21`，时间 `21:30`；相对时间只在「刚刚 / 3 分钟前」场景用。

### 5.3 禁止项

1. 界面文案出现 emoji（见 `ui-visual-spec` 3.3）。
2. 「请稍候」「正在努力加载」这类无进度承诺。
3. 「未知错误」「操作失败」这类无原因文案。
4. 面向开发者的词：`异常`、`null`、`None`、`token`、`接口 500`。
5. 凭据字样：`Cookie`、`cookie`、凭据文件名（约定 9）。

- [ ] 破坏性操作有二次确认，含对象名、影响、默认取消
- [ ] 弹窗尺寸在可用区内，超高有滚动，最小尺寸已设
- [ ] 表格列宽有策略，长文本省略 + tooltip，无常态横向滚动
- [ ] 排序走 `table_sort`，分页文案与置灰状态正确
- [ ] 所有表格已支持表头右键「列宽自适应 / 重置列宽」与状态栏「自适应 / 重置」两个直接按钮；默认无横向滚动，手动拖宽后可一键恢复
- [ ] 空态写清原因与下一步，未只写「暂无数据」

- [ ] 错误文案是「做什么失败 + 原因 + 下一步」，无堆栈与凭据
- [ ] 同一事件只走一个反馈通道，成功不弹窗
