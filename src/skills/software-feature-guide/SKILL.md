## 页签命名

- 同一组页签按同一内容维度命名；数据视图优先用具体对象或用途，操作工具用明确的操作名称。通常 2–6 字，不为凑字数改变含义，避免仅用「整体 / 历史 / 字段」等泛称。
- 资产库：资源归档 / 采集记录 / 本地文件 / 活动视频。归档包含未下载及下载不完整条目；显示名称不改变导出目录、数据库字段或已有文件。
- 采集工具：视频评论 / B站资源 / 公众号文章 / 抖音表情；B站资源内部为表情包 / 直播表情 / 装扮与收藏集 / 收藏集活动 / 用户空间。旧页面名称仍可作为搜索别名。
- 公众号文章：链接导出 / 公众号资料 / 文章归档，复用既有页面的三级页签，不增加侧栏或独立管理器。
- 腾讯文档：指标历史与修订记录、推送历史区分；映射回写内的远端预览叫「只读表格」。其余同步名称和操作范围保持。
- 证书制作：证书信息 / 选项复核 / 作品图片 / 证书记录；选项复核页签仍显示匹配进度。
- 批量改名：整体规则 / 文本替换 / 文本添加 / 文本删除 / 序号规则 / 命名模板 / 逐行命名 / 处理选项 / 时间修改。媒体筛选信息面板：文件信息 / 文件改名。
- 性能诊断：采样记录 / 页面控件 / 耗时明细 / Python 分配 / 分配增长 / 子进程 / 启动与报告。网媒账号详情：指标记录 N / 直播记录 N，数量动态更新。
- 桌面与 WebUI 的对应入口使用一致名称；只有显示文案变化时，已有路由键、请求参数、表名、文件夹名与写入范围不随之改动。网络库保留「网盘备份 / 网盘下载」两个业务页签，配置与资产备份入口统一在全局设置。

## 通用表格操作

-   所有表格的表头右键都有「列宽自适应」「重置列宽」；表格自己所在的卡片底部操作行右端还有「自适应」「重置」两个小按钮（右侧只有一个动作按钮时排在它左边，否则顶到最右；卡片没有操作行时贴在表格右下角），只对这张表生效，不再放在主窗口状态栏。列宽自适应按内容宽度分配并尽量铺满视口，重置恢复表格首次显示时的宽度。
-   默认布局应铺满且不出现横向滚动；手动拖宽后允许出现滚动条，用上述入口恢复。表头点击排序见约定 14（`table_sort`）。

## 工作台

-   桌面首帧显示后继续加载首页并移除启动骨架；窗口使用 Windows 原生过渡，隐藏到托盘、恢复与退出走正常窗口生命周期。该修复依赖桌面进程内窗口状态，WebUI 无对应窗口动画流程。
-   低频页面在首次访问时创建，切页保留输入与正在执行的任务；录播工具箱八模块仍沿用原有预载顺序和生命周期。
-   媒体筛选缩略图在可用时先缩小解码，超大图片限制同时解码数量；视频封面缓存按内存预算回收，离开页面清理可重建缓存，不改变分类、原文件或下载内容。
-   顶部只保留日期与「刷新数据」；没有页面标题和说明行。
-   工作台只展示数据总览，移除「常用工具」「更多信息工具」等快捷卡片；各工具继续从原侧栏进入。桌面与 WebUI 使用同一份本地统计数据。
-   统计卡：平台内容、微博超话帖子、腾讯文档行、资源归档、文档浏览量/成员数/已查看人数、追踪账号，以及站点访客/会话/浏览量/在线。平台内容优先采集主库，仅主库缺失时回退派生归档，二者不重复相加；资源归档统计登记条目，不代表磁盘文件总数。
-   下方显示「新增趋势」「内容分布」与七组「数据明细」：账号与达人、文档资料、资源与导出、音乐数据、群与直播、商品与演出、历史与任务成果。明细来自已有业务库、清单和固定层级的导出目录，不扫描任意自定义媒体目录；直播项为已保存设置，不代表实时监控或录制状态。
-   近 7 天趋势按北京时间统计平台内容入库、超话首次入库与表格新增，不将文件修改时间当作新增，也不涵盖全部明细。缺少本地来源显示空数据；来源损坏、正在更新或超出安全读取范围显示未知 / 读取失败，其余正常来源保留，支持刷新重试。
-   站点访问统计读取 `download/站点监控数据/访问统计.db` 的最近一次快照（优先当前统计口径）；点击站点卡先在所点卡片内展示该指标的最多 3 条记录（日期、口径、数值），不直接展开整行面板。文档指标卡同样先显示对应指标摘要，腾讯文档行卡显示文档名称，追踪账号卡显示最多 3 个账号及粉丝数；其余卡片保持紧凑、顶部对齐。
-   抽屉内可填写/保存 mandisa.wiki 后台（`/admin`）密码、选择统计口径、点「采集今日」；也可选历史日期「采集该日」，或「补采最近 7 天」（站点只保留近 90 天明细，单日失败会继续补后续日期）。下方同时列出最近 14 条每日快照与最近 50 次采集尝试（成功/失败原因）。密码只加密存本机，采集是唯一联网动作，页面加载本身不联网。
-   每日自动采集由「任务」页的「站点访问统计」管理（Windows 任务 `FengMingWebwikiAnalytics`，默认 09:10 / 13:00 / 17:00 三个时间点）；每个时间点先检查当天是否已有快照，有则跳过，没有才采集，失败可由后续时间点补采。任务页「设置」里可改主时间和两个补采时间（留空不启用）；抽屉只显示下次运行时间，不内嵌计划设置。
-   数据刷新在后台只读汇总已有本地业务数据，不触发采集、登录、同步、schema 迁移或腾讯文档写入；SQLite 读取使用请求级临时业务库副本处理 WAL，源目录不生成辅助文件，请求结束清理副本。此保证仅指总览刷新链路，既有下钻中的用户主动采集 / 设置操作仍沿用原行为。
-   卡片内「完整详情」按需打开原详情抽屉，历史表、筛选、采集与设置操作继续保留；再次点击指标标题或数字收起，切换卡片时关闭上一张摘要和完整抽屉。完整详情高度仍按当前页实际数据行数收紧（主表最多 10 行）。这些按需下钻交互仍在桌面端；WebUI 工作台展示同源的主指标、趋势与全部分组明细，并提供刷新 / 重试。

## 采集任务

-   批量输入（一行一个）：账号主页链接（B站空间/抖音/微博/快手/小红书）→ 添加为账号；作品链接、分享文案、纯 BV 号 → 解析并存入「采集结果」，同时写日志。
-   获取最新：勾选账号后批量抓取，可暂停/取消；结果进入「采集结果」与增量数据库。
-   增量模式：只入库新内容（数据库去重）。
-   获取后自动下载：获取→保存→下载一次完成；画质/线程数沿用「采集结果」页全局设置。
-   限流：每平台累计抓到设定条数后冷却，防止触发风控。
-   会话定时：软件运行期间按间隔抓取全部账号；不是 Windows 计划任务，关闭软件即停止。
-   作品增量：关闭软件也按计划把新作品写入「采集结果」（Windows 任务 `FengMingInfoCollect`，默认每天 08:30，也可按间隔），单账号各取最新 20 条；只入库不下载媒体文件，避免后台任务占满磁盘。计划时间统一在「任务」页修改。
-   日期段：日历选择发布时间范围，范围持久保存。
-   账号共享：在「账号与登录 → 账号配置」勾选「可用于」统一维护信息获取与网媒追踪的账号，本页不再保留旧双向同步与账号设置页签。
-   设置：采集范围、分组筛选、条数、限流、日期与策略开关；窄窗口时策略开关移到参数下方，恢复宽窗口后回到并排布局，不重置输入或勾选。窗口较矮时整页纵向滚动，卡片与输入框保留正常高度，避免控件重叠。账号名称、URL、所属分组与排序仍在统一账号配置维护。
-   登录态由软件统一管理，抓取时自动套用。

## 采集结果

-   抖音、B站、微博和其他平台四栏展示，按发布时间倒序；每栏每页 200 条，底部上一页/下一页翻页，数量显示完整记录数。
-   勾选按稳定条目键保留，翻页和刷新不丢勾选；全选、反选、全不选作用于该栏全部页，导出/下载/删除所有勾选也覆盖全部页。
-   每栏「清空」只清空该平台栏的全部条目，不影响其他栏；顶部「全部清空」清空所有栏。两者都是点击后直接清空、不弹确认框，只移除采集结果记录，不影响已下载的本地文件。
-   启动仅加载稳定键、平台和日期目录；展示页不读取原始响应，导出/下载/同步时按需读取完整字段，正文与原始数据不截断。
-   离开页面释放列表控件和当前页对象，返回后恢复页码、勾选与结果；删除只作用于明确选中的记录，不覆盖后台刚入库的其他记录。

## 账号名单

-   已并入「账号与登录 → 账号配置」，侧栏不再单独保留入口：账号的添加/删除、分组、可用功能与采集类型都在账号配置里维护。
-   「可用于」五个使用位置：信息获取 / 网媒追踪 / 音乐追踪 / 粉丝群快照 / 直播录制；粉丝群快照只对抖音、微博、B 站账号开放，是订阅项（勾选即每天存群列表与人数快照），没有分组概念，新录入账号默认不勾选。QQ 群不在账号勾选里，另在粉丝群页的平台下拉选「QQ群」后按分享链接订阅。
-   「直播录制」勾选：账号行右侧「直播: [房间号 / 直播间链接] ☐用于直播录制」。输入框两种都收，粘贴直播间链接会自动抽出房间号（`live_room_resolver.parse_room_input`）；支持自动获取的平台占位符是「房间号/直播间链接」，不支持自动的（微博/小红书/网易云的主页号）显示「无自动·手动贴链接」，勾选时也会提示该平台没有自动功能。勾选后把该直播间写成「直播录制」里的一条主播（同平台同房间号复用，不重复添加），取消勾选只移除主播、不删录制文件；清晰度/分段/监控等录制设置仍在「直播录制」页里调。B 站、抖音、快手、微博、小红书、网易云账号可用。

## 腾讯文档

-   登录：登录态由软件统一管理，本页不保存登录信息。
-   软件内腾讯文档登录框使用新的临时会话，不回种旧登录字段、不自动导入旧浏览器记录；等待扫码时只被动读取现有页面与框架，不为采集登录状态反复开关辅助标签页。软件仅在用户点击「刷新」时强制重载，完成登录后仍需手动保存。此流程依赖本机原生浏览器窗口，属于桌面专属；WebUI 不提供远程扫码或登录记录写入入口。
-   立即采集：采集全部文档浏览量/成员数，并全量翻页拉取「已查看」浏览人明细（昵称/来源/最近浏览时间，写入报表「浏览人」页签，按 UID 增量去重）；每次追加一行并相对上次计算增量；不包含表格同步。
-   文档管理：添加/编辑/删除任意腾讯文档，可生成页面诊断包。
-   表格同步：纯 HTTP 同步智能表格，版本没变化自动跳过；按记录比对新增/修改/删除；每次生成 Excel 到 `表格数据/`。普通表格、图表页、文章页会自动跳过。
    -   本地预览默认勾选「最新在前」：优先按日期列从新到旧，空日期放最后；没有日期列时倒序显示原行序。取消勾选恢复原序，只改变展示、不重排云端；表头支持升序 / 降序 / 默认三态，先整表排序再分页。同一文档同一子表刷新保留所选列的排序，切文档 / 子表或排序列消失时重置。
    -   「最近变更」已移到表格上方工具栏按钮，不再常驻底部占用表格高度；点击打开当前文档全部子表最近最多 60 条的只读非模态窗口，支持刷新、三态排序、列宽自适应 / 重置与关闭。记录来自本地同步时的快照对比，时间是本地检测时间，首次同步也会记为新增，不能当作云端完整编辑历史；真正的云端版本 / 编辑人通过既有「修订记录」另行抓取，受权限与云端历史可见性限制。WebUI 同步提供默认最新、每页 200 条、表头排序与同位置的最近变更浮层，读取同一份本地数据。
-   中间层同步：比对本地「已获取」+增量库与当前表格（链接/平台 ID/标题+日期三级匹配），列出未上传条目；支持复制 TSV、按行复制、图片检测与图片复制；默认不自动写入。
    -   图片列区分两种状态：中间层只比对元数据、不下载媒体，所以「图片链接 N 张」不等于本地有图。列内显示「本地 N 张 / 本地 x/y 张 / 缺 N 张」，汇总行给出「图片链接 N 行 / M 张，本地已下载 X 张、缺 Y 张」，避免出现「页面说 42 张、上传却说缺图」的矛盾。

## 票务解析

-   三平台：大麦 / 秀动 / B站会员购。输入区下方的「平台范围」复选框默认全部勾选，可自由组合；关键词搜索、链接解析及详情/导出只请求勾选的平台，未勾选平台的链接会直接提示。可粘贴链接或输入艺人/演出/场馆关键词；留空回车默认搜「封茗囧菌」（勾选大麦时其浏览器搜索约 20 秒）。全部取消勾选时不发起请求。
-   查询范围可选「近期（在售）」或「所有（含历史）」：近期会过滤已结束项目，只留今天及以后的场次；所有包含历史演出，关键词查询还会先按关键词匹配艺人，再走大麦/秀动艺人页通道补全历史场次。粘贴链接解析同样受范围影响；B站会员购没有艺人页通道，只在「所有」下保留其关键词结果中的历史项目。

-   导出列表输出全量 JSON，未拉详情的会自动逐场拉取并下载图片。
-   单件失败原地重试，不中断整批。
-   平台选择改变后，旧列表保留，未勾选平台的演出不再参与详情抓取与导出；任务期间暂时禁用平台复选框，结束后恢复。

## 购物解析

-   一个输入框，下方外置「平台范围」复选框（淘宝 / 抖音商城 / B站小店 / 闲鱼，默认全选），仅在勾选的平台中按链接头自动识别；识别后自动切到对应结果面板，各平台的业务逻辑与落盘目录互不影响。全部取消勾选时提示先选平台，不发起请求。
-   识别规则：`taobao.com` / `tmall.com` / `tb.cn` → 淘宝；`v.douyin.com` / `haohuo.jinritemai.com` / `douyin.com` / 【抖音商城】分享文案 → 抖音商城；`b23.tv` / `mall.bilibili.com` / `space.bilibili.com` / 纯数字 UID → B站小店。
-   淘宝：店铺链接（店铺信息游客可获取，商品列表需登录）或 `item.taobao.com/item.htm?id=xxx`；勾选商品后获取详情，主图/Excel 落 `download/淘宝商品/{标题}_{商品ID}_{时间}/`，可导出商品 JSON。
-   抖音商城：分享文案一行一条可批量，无需登录；拿到标题/商品ID/价格区间/销量/主图/店铺ID/带货达人ID，店铺名称、SKU、详情图需到 App 看；落 `download/抖音商品/<标题>_<商品ID>/`，整批可导出 Excel。
-   B站小店：小店短链/小店链接/UP 主主页或 UID → 小店信息与商品列表（综合/销量/价格/新品排序），游客可用；落 `download/B站小店/<小店名>_<UID>/`，商品列表可导出 Excel。
-   闲鱼：统一使用「搜索并解析」入口，输入 1–100 字关键词（如「封茗囧菌 周边」）时每页读取最多 30 件商品，可用「首页 / 上一页 / 下一页」继续翻页（平台最多 50 页，有结果总量时提前停在末页）；输入完整商品链接 `goofish.com/item?id=…` 时直接解析详情。搜索与解析仅读取，结果可三态排序、本页全选 / 清除勾选；已访问页保留结果与跨页勾选，每次最多勾选 30 件，入库后可继续下一批。翻页失败或取消保留原页与勾选，失败可重试；新关键词搜索成功后重置页码与勾选，商品详情与本地资料不显示搜索分页。点「入库并下载」确认后按商品 ID 重新获取详情，将商品信息、描述与图片保存到统一导出目录 `闲鱼商品/<商品ID>/item.json` 和 `images/`。这是本地商品资料库，不写视频采集数据库或腾讯文档；资产库通过既有目录扫描识别该分类。「本地资料」读取已完整保存的商品；已完整入库会跳过，缺图可重试补全，支持停止并保留已保存部分。需要登录、验证码、限流或网络错误时明确停止 / 提示，不绕过验证。登录状态仍由统一管理入口维护；平台当前实际可用性未用真实账号实测。
-   闲鱼访问策略：请求前选定当前有效登录态；已登录时直接使用独立临时页面，不再先发游客请求，避免游客访问限制提前阻断搜索与详情。无有效登录态才走公开页面与游客临时页面。临时页面与登录浏览器使用相同直连策略及完整桌面标识，仅等待官网自身的临时票据重试；验证码、限流、明确登录失效均停止，不切换身份继续。已启用登录态的搜索 / 详情需要采集引擎；导航超时但已收到有效商品响应时保留结果。桌面与 WebUI 共用此策略，不保存页面会话或回写登录记录。
-   一次只解析一个平台：混合粘贴时跳过未勾选平台，按首个已勾选且识别成功的平台解析（抖音同组多行；淘宝 / B站 / 闲鱼一次一条）；跳过、未处理与未识别条数在顶部提示里说明。取消平台勾选后，该平台已有结果面板禁用，避免继续抓取详情；原任务执行期间平台范围暂时锁定。

## 公众号文章

-   页面分为「链接导出 / 公众号资料 / 文章归档」。链接导出每行输入一篇 `mp.weixin.qq.com` 图文（每批最多 30 篇）；自动提取公开链接、去重、逐篇限速并支持停止。收录只保存资料与文章元数据，导出时才抓取正文与图片。
-   「公众号资料」可从一篇文章识别账号，显示名称、标识、备注、文章数与最近同步；支持搜索、编辑备注、查看该账号文章、「同步最新」与「继续抓取」。同步最新遇到已有完整元数据时停止；继续抓取按已保存的分页断点向前读取，每次默认最多 10 页，上限 50 页。失败占位不作为增量停止边界，重复识别不覆盖已有备注。
-   「文章归档」按公众号、标题关键词、起止日期（含结束当日）和状态筛选；状态为已归档 / 已导出 / 失败 / 待生成 PDF。每页 200 条，表头升序 → 降序 → 默认按全结果排序后分页，支持列宽自适应 / 重置、跨页勾选、打开原文、导出勾选和失败重试。单批导出最多 200 篇；失败重试最多读取当前公众号范围的前 200 条失败文章，数量更多时分批继续。导出清单为当前筛选范围的 UTF-8 BOM CSV（最多 50000 条），只含公开元数据，不是整库备份。
-   正文支持 HTML（图片内嵌）、PDF（桌面 Qt 渲染，A4）、Word（docx）、图片文本 MD（Markdown + 图片文件夹）。导出位置可选默认（统一导出目录/公众号文章）或固定位置，按公众号名 / 文章名建文件夹。图片抓取不完整会标为失败；停止保留已完成文件，未生成的 PDF 可从失败状态重试。
-   资料与分页断点统一存于本地 `config/wechat_library.db`，schema 1，由共享存储 owner 管理；文章长链按公众号标识 / mid / idx 去重，短链按文章路径去重。库中不保存正文、图片、请求头或登录信息；无自动清理、迁移或整库导入入口。
-   历史列表需要目标公众号对应的短期阅读会话。输入入口只在统一「Cookie 管理」的「微信公众号 → 输入阅读信息」：由用户自行提供含有效阅读参数的完整微信文章请求地址，普通分享链接不能代替。会话仅保留内存，最长 10 分钟；清除、关闭账号使用、过期或身份变化后停止继续读取，不自动刷新或写回已有登录数据。业务页不提供登录或信息输入入口。
-   WebUI 同步三个视图、资料编辑、筛选分页、历史同步、HTML / Word / Markdown 导出、重试和 CSV；导出位置由服务端配置决定。PDF 依赖桌面 Qt，属于本机渲染专属。桌面主动启动的 WebUI 子进程通过受随机能力保护的回环只读通道使用同一临时会话，浏览器不接收原始信息；独立启动 WebUI 无该桥接，也不提供第二个输入入口。
-   本轮没有实现 WeDown 式自动代理抓取，没有启动其程序、安装根证书、切换系统代理或复用其闭源组件。历史适配为未公开的微信列表协议，已用虚构响应验证，真实平台可用性尚未实测；付费、加密、删除、登录失效、验证码与平台限制会明确停止，不绕过访问控制。互动计数、关注状态、自动发现账号等参考软件能力尚未实现。

## 下载

-   一页一条主线：平台选择 + 模式 + 输入 → 结果表 → 勾选后「下载选中」或「导出选中」。原来「音乐信息获取」与「音乐下载」两个页签已合并，不再分页。
-   平台下拉第一项「五平台对比」：酷狗 / QQ / 网易云 / 酷我 / 5sing 并行搜索，结果按平台分成五个独立栏（每栏一框、各自滚动，行内带封面、歌名/歌手、时长），可「平台筛选」只看某一平台；勾选后混合下载（网易云默认优先超清母带，其余按最高可用音质），也可导出。
-   单平台四个页签与网易云持平：搜索 / 单曲解析 / 歌单解析 / 专辑解析；酷狗概念版单独入口（搜索需扫码登录），页签也已补齐，歌单/专辑/歌手数据复用主版酷狗同库、下载走概念版通道。5sing 没有专辑概念，只有搜索 / 单曲解析 / 歌单解析 / 歌手主页三个页签，不提供专辑检索与整张下载。
-   单曲解析：详情自动选中唯一歌曲，不显示勾选框或全选 / 反选 / 全不选操作；点击底部「下载选中」即可下载。多首歌曲结果仍保留勾选与批量选择。
-   WebUI 在同一「搜索并下载」卡片切换「关键词搜索 / 单曲解析」：单曲需指定平台，输入官方完整歌曲链接或 ID 后显示元数据、封面预览与最多 100 行歌词；唯一歌曲自动选中，底部「下载歌曲」复用音质、封面与换源设置。修改链接、平台或模式后旧详情失效。暂不展开分享短链；酷狗及概念版需完整 32 位 hash，5sing 支持 yc/fc/bz 分类 ID。缺歌名或歌曲不可访问时提示重试。解析可取消，正在执行的平台请求需返回后才响应取消。
-   WebUI 单曲详情可用既有结果快照导出 JSON / Excel / Markdown 信息包，属于网页附加能力；桌面单曲详情目前不支持导出。封面预览由服务端校验并缩放，不从浏览器直连平台。
-   专辑解析：贴专辑链接 / 平台专辑 ID 直接出专辑详情，只填专辑名则先出专辑搜索结果（封面、歌手、曲目数）再勾选整张下载；除 5sing 外均支持按专辑名搜索后展开曲目。
-   歌手主页：新增页签，输入歌手名或主页链接（网易云 `artist?id=`、QQ `singer/{mid}`、酷狗 `singer/{id}.html`、酷我 `singer_detail/{id}`（兼容历史别名 `artist_detail/{id}`）、5sing `/{uid或自定义域名}/default.html`）。展示歌手头像/名称/歌曲与专辑数/简介 + 热门歌曲 + 专辑列表，歌曲与专辑都可勾选下载；名称匹配到多位歌手时顶部下拉切换。QQ 未登录不开放歌手歌曲接口，走同名歌曲搜索结果并按歌手过滤；5sing 空间页直接解析昵称/头像/粉丝与原唱/翻唱/伴奏曲目（每类最多 500 首；列表不暴露单曲封面，封面统一用空间头像，时长按播放文件大小折算，下载按 5sing 实际返回的可用音质选择），主页不出专辑区块。酷狗概念版复用主版酷狗歌手数据，下载仍走概念版。
-   「从完整歌曲选择」只在五平台对比模式出现：从腾讯文档「完整歌曲」本地快照选歌，链接优先、缺失平台回退歌名搜索。
-   导出：把勾选结果导出 Excel / JSON / Markdown 到统一导出目录的 `音乐信息` 子目录；歌单/专辑/专辑搜索结果不行，需先解析成歌曲列表。
-   音质：QQ音乐、酷狗、酷我、5sing、酷狗概念版五个平台默认「最高可用」，按平台实际返回且当前账号获准的文件选择；QQ / 酷狗 / 酷我 / 概念版可选无损 FLAC / APE、320k、128k，5sing 可选 SQ 320k / HQ 192k / LQ 128k。指定档位不足时明确报错，不静默降低；下载结果回显媒体实际格式与码率，试听片段单独标明，不以所选档位冒充实际音质。
-   平台能力：网易云默认「超清母带」（jymaster），单曲、批量、混合下载与最高可用换源均优先请求该档，手选其他音质继续生效；会员档需相应登录与权限，保留原有无链接时回退规则；QQ音乐使用原生 vkey 接口，按媒体文件标识申请当前账号获准的无损 / 320k / 128k 地址；酷狗按平台给出的各档 hash 解析，不固定为游客 128k。未登录、权限不足或歌曲暂无版权时会明确提示，不保证所有歌曲都有最高档。
-   酷我优先使用平台已经提供的授权直链；只有格式声明、没有可用下载地址时，不生成或猜测无损地址，受接口或歌曲权限限制时仍可能无法下载无损。5sing 原生歌曲按实际响应中的 SQ / HQ / LQ 及对应格式选档，不保证每首都有 SQ；共享酷狗 hash 的结果沿用酷狗通道。酷狗概念版使用现有有效登录态尝试最高可用音质，不自动领取或改变账号权益。
-   自动换源（默认开启）：下载失败或只拿到试听时，按酷我 → 酷狗 → 酷狗概念版 → 网易云 搜索同名曲继续下载；保留本次音质要求，指定无损时不会改为有损文件。实际平台与音质会在下载结果中标明。
-   下载目录：默认 `download/歌曲文件` 或固定位置（自选文件夹）。

## 歌单

-   页面：音乐工具 →「歌单」（`src/gui_qt/pages/music_playlist.py`）；桌面与 WebUI 来源固定为线下活动曲目。命令行 `python main.py --music-playlist ...` 保留原有独立来源，无窗口、不加载界面。
-   活动：默认选择活动日期最新的一场（含未来活动；同日按快照行号倒序），可在框内搜索、清空或改选；清空只取消选择，不删除活动记录。曲目取「标准化曲目」（缺失时解析「演唱曲目」），仍复用「完整歌曲」的官方平台链接。歌单名称默认「封茗囧菌数据汇总库-」+ 活动名，包含前缀的完整名称均可修改或删除；提交只校验非空与总长不超过 60 字，不自动补回前缀。自动生成的默认名最多 60 字；直接重选同一活动保留手改名称，改选不同活动重置默认名；主动清空后重新选中则重新生成默认名。
-   **取歌走官方**：快照里的平台链接就是该平台官方歌曲 ID，匹配时直接使用，不再搜索；只有该平台链接缺失或无法解析时才调用平台官方搜索接口（网易云 `api/search/get`、QQ `client_search_cp`、酷狗/酷我官方搜索）。歌名与歌手都参与打分，同名翻唱只算「待确认」，默认不写入。
-   目标：网易云 / QQ音乐 / 酷狗 / 酷我 均可勾选；酷狗云歌单需要 App 令牌，可在「账号与登录 → 登录状态 → 酷狗 → App扫码」扫一次（令牌存 `config/kugou_app_session.json`，不写网页登录态；写入遇 20017 会自动刷新一次）。**未登录酷狗 App 时**，写入确认框会先提示，写入结果也会明确显示「酷狗云歌单需要登录酷狗 App：请到账号与登录 → 酷狗 → App扫码」，不影响其他平台；酷我同样支持「App扫码」（存 `config/kuwo_app_session.json`）：扫码后建单走 `pl3_addlist`（body 含 title/intro/ispub）、加歌走 `pl3_add`（body `{"data":[歌曲ID],"pid":…,"pos":0}`），与 PC 客户端同款；网页建单已下线，仅保留报错提示；未扫码时提示去登录；5sing 已支持创建与加歌：走网页「歌单」JSONP 接口（`service.5sing.kugou.com/songlist/`），程序自动上传封面、填「流行」标签，曲目按歌名+歌手回查 5sing 自己的「类型$ID」（yc/fc/bz）后按批加入，歌单 ID 从「歌单管理」页回查。
-   重复执行：QQ 音乐同名歌单已存在时直接复用该歌单继续加歌（创建接口 `code=21` 返回 `dirid`），不会因为上次中断而无法重跑；加歌遇到非 JSON 响应（风控页/空响应）会换新签名重试一次，仍失败才报错，错误提示带 HTTP 状态、Content-Type 与响应摘要。
-   预览：逐平台搜索并生成计划，结果表按「已匹配 / 待确认 / 未找到 / 重复」标注，支持表头排序；默认只预览，不创建任何歌单。 修改歌单名、清空活动或改选活动会清除旧预览与逐首勾选，需重新预览才能写入；直接重选同一活动且名称未变时保留预览。
-   逐首勾选（2026-11-26）：结果表第一列「写入」是勾选框，勾选＝写这首歌、取消＝这次跳过；「已匹配」默认勾上、「待确认」默认不勾（未找到 / 重复的行没有勾选框，显示「—」）。表上方「全选 / 只选已匹配 / 全不选」批量切换，并实时显示「已勾选 N / M 首写入」；顶部「同时加入待确认歌曲」勾上等于把待确认行整批勾上（仍可逐首取消）。写入只按勾选执行（`MatchItem.selected`，`PlatformPlan.selected()` 统一判断），勾选为空的平台整条跳过，确认框按平台列出实际勾选数量。WebUI 同一套语义，写入请求带 `selection={平台: [序号…]}`。
-   写入：预览后点「写入平台」二次确认，按平台创建同名歌单并分批加歌，进度与失败原因写入运行日志；每个平台写 `journal_<平台>.json`，中断后可用命令行 `--resume` 续跑。
-   线下活动回填：来源选「线下活动曲目」时，平台创建成功后自动把歌单链接写回腾讯文档「线下活动」的 `活动歌单_网易云` / `活动歌单_酷狗` / `活动歌单_QQ` 三列（只更新该活动行、只写这三列；已有其它链接不覆盖；酷狗链接先做只读网页探测，未通过不写）。回执区分已写入 / 已是该链接 / 已有其它链接 / 缺少目标列 / 链接未通过校验 / 失败，并写进 `result_*.json` 的 `writeback`。
    - 曲目来源：优先用「完整歌曲」表里该平台的歌曲链接（酷狗存的是 `m.kugou.com/mixsong/<短码>.html`，程序会取一次页面解析出 hash / mixsongid，不再退回搜索，避免匹配到翻唱）。
    - 链接口径：网易云用 `playlist?id=`；QQ 建单返回的是 `dirId`，会自动调 `GetPlaylistByUin` 换成公开页用的 `tid`（`y.qq.com/n/ryqq_v2/playlist/{tid}`），再用 `fcg_ucc_getcdinfo_byids_cp` 核对歌单名是否与本次一致，不一致就不写（`dirId 201` 是「我喜欢」，不能当自建歌单）；酷狗用 `global_collection_id` 拼 `yy/special/single/collection_3_<uid>_<listid>_0.html`（实测自建云歌单无需 specialid 也能打开，页面标题即歌单名），拼出的歌单名与本次不一致、或歌单已下架时返回空链接，回执「平台无网页链接」。
    - 已有链接若被探测为「已失效」（404 / 显示不存在 / 跳非歌单页），自动替换为本次新链接；网络异常不算失效，保持不覆盖。
-   顺序：按来源列表顺序写入；网易云批量加歌会倒置，自动调用排序接口；QQ 新歌插到最前，逐首反向添加。平台无原曲的歌曲跳过，不拿翻唱硬顶。
-   酷狗定位音频：云歌单按 `album_audio_id`（mixsongid）+ hash 定位，**不能**用单曲 `audio_id`——实测《声声慢》用 audio_id 会被换成同名无关的有声书；`KugouPlaylistWriter.add_songs` 已固定优先 `album_audio_id`。
-   报告：预览与执行报告写到统一导出目录的 `音乐信息/歌曲合集`，页面可直接打开该目录。
-   登录：目标平台需已在统一登录入口完成登录；页面只读使用当前登录态，不保存、刷新、迁移或展示登录内容。写入节奏默认搜索间隔 0.35 秒、加歌批次间隔 0.8 秒，可用命令行参数调整。
-   网易云分权账号：建单读「网易云（歌单创建）」`netease_playlist` 的登录态（`netease` 主账号只用于会员下载/采集）；未单独登录歌单账号时回落主账号，页面说明与写入日志会注明当前用的是哪个账号；WebUI 与命令行同一条 `playlist_service.get_login_jar`，行为一致。

## 自动整理

-   维护 A 端来源文件夹（可多个）；扫描用 `os.walk`，**勾选「包含来源子文件夹」才会递归进子目录**（默认关闭），任意层级都能读到，例如直播录制的 `<主播名>/<YYYYMMDD>/`。
-   「扫描并预览」同时统计工作目录里的视频与来源迁移计划；有同场附属文件时在预览行尾标注「附带 N 个：弹幕/封面/时间轴…」。
-   「从来源迁移视频（按日期）」：只迁移来源里的视频，文件名能识别日期就按文件名，识别不到按文件修改时间建 `YYYY-MM-DD` 文件夹；工作目录里已有的视频不动；确认后逐个复制校验、再删除来源。
-   附属文件同步：迁移视频时把同目录同主干的 `_弹幕.jsonl/.xml`、`_封面.jpg`、`_时间轴.json`、截图、`<视频>.ffmpeg.log` 等一起搬到目标日期文件夹，重名自动加 `_1`（不覆盖）；附属文件失败只记日志，不影响视频迁移；分段 `_001.ts` 仍按独立视频处理。
-   跨天录制（例如从凌晨播到次日或隔日）的目标日期文件夹按整组视频的时长取 `开始~结束`，命名为 `20261124~20261126`；时长无法识别时退回单日文件夹。
-   日期文件夹整日补搬：没对上当前视频主干的孤儿附属文件（视频已删除/已改名）会随同一天的视频一起搬走；仍对应其它未迁移视频（可能还在录制）的附属文件留给该视频迁移时再搬，避免拆散场次。
-   暂缓项可见：扫描时因空文件或最近 30 秒仍在写入而跳过的视频/附属文件，会出现在预览、确认框和完成日志里，不会静默只搬一部分。
-   「执行迁移 / 整理」：把来源迁移计划与工作目录里可识别日期的散装视频一起整理进日期文件夹，工作目录内的散装视频也会带出它的附属文件。
-   「合并弹幕 / 时间轴」：选择日期文件夹、目标视频和多个 `_弹幕.jsonl` / `_时间轴.json`；弹幕按时间排序去重，时间轴按录制顺序把锚点换算到目标视频，输出 `<目标视频>_弹幕.jsonl` / `<目标视频>_时间轴.json`；可勾选同时把最新一张封面复制为 `<目标视频>_封面`。原文件保留，同名目标先备份 `.bak-时间`；源视频已删除时按相邻场次时间估算偏移并在日志提示。
-   迁移完成的视频前往「命名投稿」继续处理；本页不上传投稿。

## 视频操作

- 短枚举、数字参数及转换复选项按内容宽度紧凑排列，空间不足时整组换行；下拉保留可读的稳定宽度，标题、备注和文件名等长文本仍可伸展。
- 参数区的页签头固定；各页只纵向滚动，字段与按钮随可用宽度换行，窄窗口不会再出现横向滚动。左侧文件队列的上移、下移、删除与清空在「更多」中；预览的片头、片尾和十秒步进在「定位」中，正负一秒与时间跳转保留直接入口。
- 移动播放指针后点「标记开始 / 标记结束」，或在预览区用 I / O 标记；未标开始时，结束标记从零秒开始，结束不能早于或等于开始。填写元数据或文件名时，I / O 仍正常输入文字。
- 时间轴以颜色显示已标片段、当前选中片段和待定起点；桌面选中片段显示绿色开始线、红色结束线，待定起点为黄色。切割列表单击选中、双击定位开始；删除、清空、检测生成与导入片段会同步刷新颜色。切换视频会清除桌面当前片段及待定起点。
- 元数据的「标题 / 备注 / 作者 / 日期」直接作为输入框提示，填入内容后可用悬停提示辨认；写入仍生成新文件，保留原画质与旋转方向。
- 旋转移到「转换」页的独立区域：选角度后点「导出旋转」，只处理当前视频、生成新文件，保留原标签，不参与批量转换。沿用无损显示矩阵方式，MP4 支持，部分播放器可能忽略 MKV 的旋转信息。
- WebUI 同步字段顺序、独立旋转区与彩色时间轴：只勾选一个视频后标记或编辑片段清单，选中片段后可删除，双击片段定位开始；当前页面内按视频分别保留片段草稿，换视频不会混用。浏览器编解码不支持的格式仍可使用桌面预览。

## 命名投稿

-   直播类型随中栏宽度自动换行，类型区高度跟随实际行数；窗口缩放不会重建复选框，勾选顺序、编号和数字键操作保持不变。
-   三栏工作流：左栏日期文件夹→文件列表；中栏直播账户（单选）+ 直播类型（多选，数字键 1-9）；右栏视频信息、弹幕版本、平台、标题模式、截图与新文件名预览。
-   标准文件名日期前缀支持跨天范围：开始日期 + 视频时长推算出结束日期后，写成 `2026-11-24~2026-11-26_HH-MM-SS_…`；结束日期与开始日期相同（未跨天）时保持单个日期 `2026-11-24`。
-   当前日期文件夹同步扩展：`20261124` → `20261124~20261126`（保留 `_备份` 等后缀）；目标文件夹已存在时只记日志、不覆盖；已重命名/失败记录会跟随新路径更新。
-   文件列表按参数里的「视频后缀」筛选（默认 `.mp4`，录 `.ts` 时可改）；新文件名沿用该后缀。
-   重命名视频时同步改名同场附属文件（`_弹幕.jsonl/.xml`、`_封面.jpg`、`_时间轴.json`、`<视频>.ffmpeg.log` 等），重名自动加 `_1`；视频从 `.ts` 改为 `.mp4` 时日志扩展名跟随改成 `.mp4.ffmpeg.log`。
-   `_时间轴.json` 里的视频路径与 `base` 会同步改到新文件名，重命名后弹幕对齐 / 写时间码仍然有效；分段 `_001` 的附属文件留给分段自己改名。
-   Enter 确认重命名，Esc 跳过当前视频。
-   改名不会被本软件内的预览挡住：确认时会先让「视频操作」松开正在预览的同一文件（切页时也会松手，回来按原位置续播）；若文件仍被杀软/同步盘等外部程序短暂占用，会自动等待重试约 1.5 秒，仍失败才提示「视频仍被占用，改名未执行」。
- 可写入版权属性（ffmpeg 写元数据）：写入标准 `copyright` 标签（MP4 落在 `cprt`），并在 mp4/mov/m4v 上同时写一份到「备注」。
  - 实测限制：Windows 资源管理器**不显示 MP4 的「版权」字段**（写进去后 属性 → 详细信息 → 版权 仍为空；标题/备注/作者/专辑/流派都能显示）。所以看版权请用 属性 → 备注，或 MediaInfo / 剪辑软件的标准版权字段。
  - 写入后会读回校验，校验不一致或失败都保留原视频；勾选状态下写入不成功会暂停自动投稿。
-   参数设置 Tab 维护账户/类型/平台列表、视频后缀、匹配阈值、附加信息。
-   投稿入口统一为「投稿已重命名视频」，不再单列「投稿设置」。没有视频或尚未设置工作目录时也能打开投稿窗口，配置、保存及另存为投稿模板；选择可投稿视频并完成账号验证后才可开始上传。WebUI 的「B站投稿上传」配置区同样始终可用，空目录可先保存模板，选视频后再预检与确认投稿。
-   投稿窗口：标题模板、直播日期、来源平台、简介、标签、分区、创作声明、加入合集、视频来源、封面、并行线程与自动投稿开关。标题模板 `{日期}` 与「本次直播日期」支持跨天 `20261124~20261126`：选中范围内的视频后自动带出，单日时保持 `20261124`；手填范围时不能倒序。分P仍要求同一主播/平台/弹幕版本，且日期范围包含今天。创作声明默认「内容为自制：未经作者允许，禁止转载」（版权类型自制 + 禁止转载）；选「内容为转载（原直播录播）」时才必须填视频来源，其余声明只换稿件页标签。加入合集默认「封茗囧菌直播」，验证账号后下拉列出该账号可用合集，填写名称不在列表时在投稿前拦下；投稿成功后按合集名匹配合集 ID 并调用合集切换接口加入，失败只在状态栏提示，不回滚已完成的投稿。

-   随机底图 + 标题/日期/备注三段文字，快速产出静态封面。
-   底图缩放缓存设有内存预算；离开页面释放底图与成品预览，返回时按原有文字、样式和位置重建，导出仍使用所选分辨率。

-   导出 PNG 无损或 JPG（质量 60~100）到 `download/套版封面/`（主按钮为「导出 JPG」）。
-   模板存 `config/cover_templates/`，保存样式/位置比例、底图记忆及底图适配、整体 Y 偏移、导出分辨率和 JPG 质量，不保存文字内容；旧 v1 模板仍可读取，缺少的新参数采用默认值。
-   「批量补封面」使用打开窗口时的当前样式、底图和备注快照：选择本地视频目录，可包含子目录，扫描后双击标题 / 日期修正，勾选并确认生成。日期识别支持紧凑 / 分隔 / 中文日期及跨日范围，文件名没有日期时取扫描目录以内最近的日期目录；没有日期时留空，不用修改时间猜测。非法 / 多个无范围关系的日期须人工修正，同主名多格式视频冲突须先区分主名。
-   批量输出位于视频旁，命名为 `<视频主名>.jpg`；同名图片以及 `_封面` / `_cover` / `.cover` 附属图都视为已有封面并跳过。生成前后复核已有文件，原子创建且不覆盖，取消保留已完成文件；视频本身不修改。不接投稿、自动整理或其它录播核心模块，也不安装定时任务。扫描 / 生成用例位于 Qt-free 的 `toolbox/cover_automation.py`，可供后续流程调用。
-   WebUI 的「封面制作」提供模板选择、工作目录内相对子目录扫描、标题 / 日期修正、勾选和可取消补全；复用桌面保存的模板与相同引擎。自绘排版编辑仍在桌面，Web 不建立另一套模板存储。
-   下拉/滑条/数字框不响应滚轮；字体可直接输入；颜色使用内置主题色板。

## 证书制作

-   用途：录入「封茗囧菌数据汇总库·美工作品授权与二级分发协议」后，自动匹配字段与 □ 勾选项，人工复核后输出横版 A4 内部认证证书。
-   录入：工具栏「导入文档」支持 txt / md / docx / pdf 协议，以及 xlsx 填写表（按「字段名称 / 填写内容」匹配三张表）；「粘贴文本」直接贴协议全文。字段覆盖配套填写表的三张表（协议正文 17 项、附件一 23 项、内部认证证书 23 项），含管理组代表、对接人、歌曲/项目名、双方确认签名与日期、图片内署名、署名写法说明、证书载明项。
-   自动匹配：内部认证号、作品标题与类型、授权方圈名与邮箱、主要与协作设计人、授权期限、签发日期、水印样本文件名；附件一「图片中应清晰可辨」的署名默认跟随正文，可单独覆盖。
-   选项复核：左栏「选项复核」页签列出文档里的六组 □（作品类型、样本格式、水印内容核对、计划使用位置、证书状态、图片格式），自动匹配到的项带「已匹配」并预先勾选；单选组互斥但允许全不选；勾「其他」才启用相邻的说明输入框。
-   联动：勾选作品类型后自动写入用途摘要与证书副标题；勾选「已续签」才启用「续签至」；勾选水印内容后自动生成对应图片水印文字；手动改过用途摘要后不再自动覆盖，可点「按类型恢复」。
-   编号：只保留「内部认证号」一个编号，格式 `FMJJ-DB-ART-<年份>-<6 位序号>-<8 位校验哈希>`。五段在编号卡片里分控：前三个前缀各一个可编辑下拉（选项来自历史已用值，也可直接输入），年份下拉默认「自动（本机当前年份）」且覆盖 1900–2199，序号下拉默认「自动（下一个）」并可手填；下方只读显示五段合成后的完整编号与校验码。序号按所选年份在输出目录、历史记录与保留/作废清单里的最大序号 +1 顺延（历史 3 位旧编号保持原样，不回改）；校验哈希取「编号主干 + 作品标题 + 授权方 + 授权期限 + 签发日期」的 SHA-256 前 8 位（大写），作品信息改动后自动重算。
-   授权方联系方式：原「授权方邮箱」改为「联系方式」（邮箱 / 微信 / 其他均可）。
-   署名写法说明为选填，留空不影响生成。
-   授权起始 / 截止改用下拉日历选择；截止默认按起始日 +3 年自动带出，手动改过后不再跟随；清空则按协议第四条表述。
-   「导出 Word」输出 .docx（证书页含内部认证号 / 校验哈希 / 全部证书字段 + 完整协议正文八条 + 附件一 + 附件二）到该证书的专属文件夹，可在 Word 里继续编辑；协议全文由 `src/toolbox/certificate_agreement.py` 内置模板按软件当前字段填充，导入文档里的旧值不会覆盖，冲突一律以软件生成为准；证书图片仍走「生成证书」的 PNG + PDF，若同目录已有 zip 会自动重打。
-   图片与自动水印：「图片」页签添加作品图 / 水印样本，最多 6 张，可上移下移、完整显示不裁切；「自动生成水印」默认开启，导出时按水印内容勾选把署名/认证号以淡纹稀疏平铺到作品图（不压主体），并在右下角带一个小标签，另存到证书文件夹的「水印件」子目录；重复的署名会去重。
-   预览：右侧实时预览默认「适配宽度」，可切 100% / 125% / 150% / 200%，放大后出现滚动条查看细节；窗口缩放时自动重新适配。
-   证书记录：「证书记录」页签保存字段数据及可选的产物引用与校验值，不保存原图副本；同一认证号重复生成会合并为一条并累计 revision。勾选框用于加密导出，「载入 / 删除」仍只作用于当前行；筛选不清除已勾选记录，筛选外的已选数量会显式显示。「全选结果」勾选当前筛选范围，「取消选择」清除全部勾选。载入后图片列表保持当前内容。右键记录可选「载入 / 删除记录（保留序号）/ 删除记录并作废序号」；保留与作废的序号写入 `config/certificate_history.json` 的 `retired` 清单，自动编号不再发到它们，也不出现在序号下拉里；「清空」会把这些记录的序号一并作废。
-   加密导出：勾选一条或多条记录后点「加密导出」，核对清单并两次输入 12–128 位密码，导出一个 AES-256 ZIP；密码仅本次使用，不保存、不能找回。批量最多 42 条，整包最多 128 个文件条目且明文总量不超过 64 MiB，附件较多时需进一步分批；超限会明确提示，不静默漏导。多条按 `records/0001/` 等通用编号目录分开，每条含字段快照、来源/校验清单与可用附件，全部文件内容加密。单条允许补充材料并注明「本次补充」，批量不共用补材；不会把当前表单图片当作历史证据。缺失或校验不符的旧材料会明确列出，未留存的原协议与原图无法凭字段还原；仅有字段的旧记录仍可导出快照。桌面导出可取消，不覆盖已有同名文件，期间暂停本页生成及记录修改入口，结束后恢复。
-   WebUI：侧栏「证书制作」提供「证书记录」的筛选、勾选、全选结果、取消选择与同一加密导出能力，显示数量、进度与取消；不接受浏览器传入本机附件路径。证书制作的自绘预览/排版仍在桌面端，Web 页保留说明。记录数据与桌面同源，导出不改写历史或原文件。
-   输出：固定两页（证书页 + 图片页），横版 A4 300dpi；每份证书在「输出目录」（默认 `download/证书/`）下建一个 `<内部认证号>_<作品标题>_内部认证证书/` 文件夹，内含 `_01/_02.png`、同名 `.pdf` 与 `水印件/`，并在同级生成同名 `.zip` 附属包（解压后仍是同名文件夹）。
-   证书状态：有效 / 已终止 / 已作废 / 已续签由「证书状态」勾选决定；非「有效」时右上角胶囊标签与页面淡斜水印同步变色，便于识别旧证。
-   必填校验：填写表里标「是」的字段在标签后带红色 `*`，未填时输入框或单选组显示红色边框，顶部汇总「必填未填 N 项」；导出前再确认一次，可继续生成但不会静默放过。
-   字段记忆：字段、图片列表、输出目录、编号年份与自动水印开关存 `config/config.json` 的 `certificate_maker` 段；历史数据单独存 `config/certificate_history.json`。

## 弹幕姬

-   入口：侧栏「直播录制」→ 页面工具栏「弹幕姬」按钮（弹幕页顶部不再是页签），打开独立窗口，里面按平台分「抖音弹幕 / B站弹幕」两个页签；录制页「工具 → 弹幕姬…」同样可开。窗口居中显示、可自由拖动，关闭只停弹幕渲染/回放，不影响正在进行的录制。
-   B站/抖音直播弹幕实时采集与回放，共用一套框架。
-   连接：输入房间号或直播间链接（含 [b23.tv](http://b23.tv)），留空填默认房号；按钮连接后变为断开。
-   实时数据：弹幕、礼物、SC/上舰（B站）、进场、关注、点赞；主播信息实时刷新。
-   两种模式：仅弹幕 / 回放（导入回放包重演整场）。
-   录制：视频录制统一在同一页的「直播录制」页签，支持开播自动录制、断流重连、分段、录满停止。
-   轮询等开播：未开播按间隔重试，开播自动接入，下播后自动恢复轮询。
-   搜索/筛选：弹幕关键字、按人筛选，事件区可独立筛选。
-   保存与回放：保存弹幕/统计；导出/导入/合并回放包；可自动导出。
-   转弹幕机 TXT：工具栏「转弹幕机 TXT」可多选 `.jsonl`（抖音/录播姬）或 `.xml`（B站）弹幕文件，批量输出到 `导出目录/弹幕文件`；每行 `HH:mm:ss.SSS|[昵称]：内容`，最早一条对齐 `00:00:00.000`，只含聊天/表情弹幕，重名自动加序号、不覆盖旧文件。
-   弹幕实时落盘到 `导出目录/弹幕文件/实时记录/房间号_日期.jsonl`；游客优先，不影响登录态。

## 直播录制

-   入口：侧栏「直播录制」是内嵌页面（不再是独立窗口），菜单栏在页面顶部，工具栏分两行：上排主播与监控、下排设置工具，右端「弹幕姬」按钮打开弹幕窗口。
-   多平台：抖音 / B站 / 快手 / 微博 / 小红书 / 网易云，底部切换，列表与录制任务互不影响。
-   添加主播：房间号或直播间链接；「监控状态」列（未监控 / 等待开播 / 下播检测）+「开启监控录制」实现开播自动录制；录制中监控不停，只做下播检测。
-   启动恢复：「是否录制」与「监控状态」按上次保存的意图跨重启保留（直播/在线/录制中/已录时间等运行态归零）；上次还有主播在监控里时，启动后自动恢复监控。
-   录制设置：输出格式、录制方式、分段、录满停止、保存目录、断流重连、标题过滤、弹幕录制、封面保存。
-   独立设置：单个主播的录制内容/清晰度/分段/录满/提醒/备注。
-   推送：企业微信/钉钉/飞书/自定义 WebHook 按事件推送。
-   右键菜单只保留：立即检测开播、已录时间归零重新录制、独立设置、修改备注、复制直播源、复制直播网址、复制主播整体数据、删除当前选择。其余右键入口已删除；顶部工具栏、顶部菜单与批量操作仍在使用的功能保留。
-   主播表格的表头为单行，窄列显示省略号，悬停显示完整说明；不再强制换行或固定两行。列宽随窗口变化自适应，固定勾选列与序号列，为主播名和直播标题保留空间；手动拖宽后暂停自动调整，点「自适应 / 重置」恢复。表头点击按升序、降序、默认顺序循环，只改变展示顺序，勾选和当前选择随主播保持，不改保存顺序。
-   工具 → FLV / TS 修复：FLV 沿用截断标签、时间戳与断流拼接修复；TS 使用 FFmpeg 跳过损坏数据包、补时间戳并流复制重封装，不能恢复已丢失的画面或声音。修复窗口非模态，支持进度与取消；只处理已停止录制的文件，源文件保留，输出为 `原名_修复.flv/ts`，不覆盖已有结果。
-   WebUI 的直播录制页同样提供 FLV / TS 修复：从当前平台已配置录制目录选择文件，勾选确认已停止录制后提交，可查看进度、取消并下载结果；源文件只读，结果写入本次任务目录。实时录制状态与右键菜单仍属于桌面进程内交互，WebUI 不另建一套主播配置或监控状态。
-   工具 → 写时间码：录制结束后把 `.ts/.flv` 重封装成 mp4，写入一条 tmcd 时间码轨（画质不变、不重编码）；起始时间优先取录制时间轴的首帧锚点，没有时间轴才退回文件名里的 `<日期时间>`，分段文件可手动改成本段起点，重名自动加序号，可勾选覆盖。
-   录制时间轴：每场录制旁写 `<视频主干>_时间轴.json`，记录每个文件（含分段、断流续录）的 `{pts_ms, wall_ms}` 锚点；用于把弹幕的绝对时间换算成视频内时间（停顿段不外推），也是「写时间码」首帧时间的来源。
-   录制文件：`<保存目录>/<主播名>/<YYYYMMDD>/<主播名>_<日期时间>.ts`（抖音及新增平台）/ `.flv`（B站）；同一天的弹幕、封面、时间轴都在该日期文件夹里。日期层与「自动整理」一致（8 位 YYYYMMDD），可在「录制设置 → 日期文件夹」关闭，关闭后文件直接放在主播目录下。
-   关闭保护：录制中或监控中关闭「直播录制」窗口会先弹窗提示（录制中明确说明直接关闭可能损坏文件）；点「停止并打包后关闭」会逐个停止录制、等 ffmpeg 写完文件，再把同场分段合并、重封装成 `<主干>_打包.mp4` 后关闭，原始录制文件保留不删。关闭主窗口时：后台模式下可选「隐藏到托盘继续录制」或「停止录制、打包并退出」；未开后台模式则确认后停止并打包再退出；托盘菜单「退出」同样会先收尾打包。
-   快手可游客取流；微博/小红书/网易云使用无头浏览器嗅探，已登录账号自动带登录态。
-   账号状态：平台信息条显示「账号：已登录 / 游客态」；B站、抖音取流自动使用软件统一管理的当前登录态（未登录或已关闭时按游客态录制），页面不保存也不展示凭据内容。

## 定时任务

-   统一在「任务」页查看 / 设置 / 删除本软件注册的 Windows 计划任务；由系统计划任务执行，关闭软件也按时运行。
-   当前 9 个任务：腾讯文档监控、网媒账号追踪、音乐账号追踪、网盘备份、站点访问统计、粉丝群快照、作品增量、微博超话采集、抖音指数快照。
-   「设置」对话框：执行方式（每天一次 / 按间隔）、每天时间、间隔；保存后立即注册或更新计划任务。
-   时间用 24 小时制数字滚轮选择：时 / 分两列，鼠标滚轮上下滚动、按住拖动或键盘上下键都能改；无限循环（23 点后回到 0 点、59 分后回到 0 分），中间一行为选中值并高亮。选「按间隔」时每天时间置灰。
-   站点访问统计额外有两个补采时间，各带「补采 1 / 补采 2」勾选框：取消勾选即不启用该时间点。
-   微博超话采集：在任务「设置」里勾选已采集过的超话，并设每频道页数（1–20，默认 3）。默认每天 09:30，也可按间隔执行；每轮重新读取频道，串行抓取并写入原有超话历史库，不发帖、不签到。尚无候选时先到「微博超话」完成一次采集，再重新打开设置。
-   抖音指数快照：在任务「设置」里勾选已有本地快照的达人，选择近 30 / 90 / 180 / 365 天。默认每天 09:45，也可按间隔执行；只保存指数历史快照，不回写资产或发布平台内容。尚无候选时先到「抖音指数」完成一次抓取，再重新打开设置。
-   上述两项默认不订阅任何对象，至少勾选一个对象后才能保存并安装；取消设置不落盘，删除系统计划保留订阅和历史。业务参数统一存 `config/content_collect.json`（唯一写入方 `content_collect_store`），计划仍沿用全局配置；已订阅对象即使本地快照暂缺也不会静默退订。同类任务防重复执行，目标间低频串行，单对象失败继续其余对象，失败及跳过记录在独立任务日志。
-   桌面与 WebUI 的任务设置读取同一份字段定义、订阅与计划；Web 安装前二次确认对象数量。命令行 `python main.py --chaohua-collect` / `--douyin-index-collect`（打包版为对应 exe 参数）只执行一次，不创建桌面窗口；没有订阅时安全跳过，不自动安装计划。
-   功能页不再内嵌定时设置（约定 10），只保留指向本页的说明。

## 直播总结

-   在既有「直播总结」页选择工作目录内 TXT / SRT 转录，使用「模型接口 / 本地模型（CPU / GPU）/ 本地规则保底」三种模式；模型模式复用同一分块提取、合并、终稿与格式校验流程，本地规则不调用模型。结果保存到统一导出目录的「直播总结」，支持预览已保存结果、进度与停止。
-   本地模式无需安装 Ollama；使用可选的 llama.cpp 独立运行组件，目前支持 Windows x64。CPU 与 GPU（Vulkan）分别选择，GPU 需显卡驱动支持 Vulkan；不会自动切换模块。每次总结或测试连接新建仅监听本机的独立进程，结束或取消只回收该任务的进程。
-   安装、导入与卸载只有「全局设置 → 运行环境与组件 → 本地总结组件（可选）」入口，属于既有设置页的 L2 面板，不新增侧栏或管理器。CPU/GPU 模块和 GGUF 模型均可按需准备，标准版、FULL 版都不内置、不自动下载、不计入必需依赖缺失。
-   推荐模型提供通义千问 2.5 3B / 7B 的 Q4_K_M GGUF；也可导入用户自行持有且 llama.cpp 支持的 GGUF v2/v3。分片模型选择 00001 首文件，其余分片放同一目录；导入只建立受控副本，不移动或改写源文件。安装与导入校验文件完整性；卸载需确认，只删除受控模块或所选模型及其分片，保留导入源文件和配置。已有完整模块执行校验，损坏模块重新下载。
-   总结页可配置推理模块、已准备的模型、上下文长度、CPU 线程数（0 自动）、GPU 卸载层数、批处理大小、最大输出长度与采样温度；模型列表超过 12 项支持名称筛选。CPU 模式忽略 GPU 层数；最大输出长度小于上下文，批处理大小不能超过上下文。较长规则与转录需要更大上下文和足够内存，模型兼容性、速度与总结质量取决于硬件及模型；连接成功只证明推理链路可用。
-   切换本地或规则模式保留原接口配置与已保存的 API Key。推理参数仍由既有配置 owner 写入 `convert.livestream_summary_local`；组件唯一写入方为 Qt-free 的 `livestream_summary/optional_runtime.py`，manifest schema=1，以模型首文件名标识受控副本，组件位于程序根 `optional_components/local_llm/`，只读安装位置回退到 LocalAppData 同名目录。模型不随配置备份或发行包收集，许可证按各模型卡单独确认。
-   WebUI 同步三种模式、八项参数、组件下载 / 校验 / 卸载、模型下载 / 导入 / 删除及可取消任务；使用同一共享用例和存储。Web 导入只列出服务端工作目录内的 GGUF 首文件，不接受客户端任意绝对路径；桌面可用本机文件选择框导入。

## 性能诊断

-   顶栏「性能」进入既有诊断页；「启动软件后自动监控」是页内选项，默认不勾选，勾选后立即开始普通采样，并记住以后每次启动桌面软件自动开启。无需先打开性能页，切换页面或卸载诊断页后仍由主程序继续采样。
-   自动模式在桌面 `main.py` 的 Python 入口就保留时间基准，并在 Qt / 主界面模块导入前开始进程采样；无窗口 WebUI / 定时任务 / CLI 入口先分流，不参与桌面启动监控。入口仅读既有开关，缺失、损坏或关闭时不创建诊断线程、报告目录或文件，不改写设置；Qt 接管同一记录器，不清空早期采样。
-   「启动与报告」列出 Qt / 主界面模块导入、配置、日志、Qt 应用、主题、主窗口、首页、本地状态恢复和预载的阶段耗时与工作集 / 私有提交增量，启动汇总独立于普通事件缓冲保留。早期尚无界面时，界面延迟和控件读数标为未测；阶段可能嵌套或并发，数据不可直接相加。
-   取消勾选只关闭下次启动自动开启；当前采样用「停止检测」停止。手动停止不会清除自动开启偏好，本次切页、重建页面不会自行恢复，下次启动软件才按偏好恢复。
-   「追踪 Python 分配（较慢）」仍需单独手动勾选后开始；自动监控只做普通采样，不自动开启分配追踪。已有检测正在运行时再勾选自动监控，只保存偏好，不重建会话、不清空采样。
-   「开始检测 / 停止检测 / 记录标记 / Python 快照 / 导出报告」保留；每秒采样，最多保留 3600 次采样和 2000 个事件，图表显示最近 10 分钟。停止后仍可导出，重新开始建立新记录；仅软件运行期间有效，不安装 Windows 计划任务。
-   检测开启后自动写入 `logs/performance/performance_日期_时间_进程ID_随机标识.json`：启动时先保存，之后每 15 秒后台原子更新同一会话文件，阶段边界触发保存请求；停止 / 正常退出保存最终状态，新会话另建文件。有效自动报告默认保留最近 20 份，单份最多 32 MiB；只轮转本模块格式完整的自动报告，不删除手动导出或损坏 / 无标记文件。程序目录不可写时，报告根随配置 owner 回退到 AppData 的程序数据目录，读取列表不创建目录。
-   「启动与报告」可在当前会话与已保存报告间切换，查看阶段、刷新列表、立即保存；选中历史报告时，上方「导出报告」另存该报告。读取历史报告时清空上一份阶段并暂时禁用导出；读取失败显示原因与刷新重试提示，不保留旧内容或一直显示加载中。保存状态显示最后成功时间或失败提示，保存失败仍保留内存记录与上次完整文件，可重试。自动报告是诊断日志，不新增用户备份入口。
-   覆盖从 Python 脚本入口开始的阶段，无法覆盖解释器或打包引导加载；首条内存采样在诊断初始化后取得。可捕获的 Python 启动失败会尽力保存固定阶段与异常类型，不记录异常正文、配置、请求参数或用户目录。原生崩溃、强杀、断电只保证最后一次成功落盘，不能承诺最后瞬间或每个函数 / 请求都被完整记录。
-   配置是 `config/config.json` 的 `convert.performance_auto_start` 布尔值（旧配置缺省为 `false`）；主数据仍由 `toolbox/config_manager.py` 写入，桌面与 WebUI 统一调用 `toolbox/performance.py` 的用例保存并回读确认，不增加另一份配置或迁移旧数据。
-   WebUI 的同页可修改「启动桌面软件后自动监控」，保存后供下次启动桌面软件使用；下方「已保存报告」显示历史记录、查看启动阶段并下载同一份 JSON，支持表头三态排序与列宽自适应 / 重置。实时采样曲线、任务标记与 Python 分配快照依赖桌面进程内状态，Web 不控制它们；历史报告通过共享 owner 读取，不另建 Web 数据或采样器。
