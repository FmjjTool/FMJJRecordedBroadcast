# 直播总结

-   在既有「直播总结」页选择工作目录内 TXT / SRT 转录，使用「模型接口 / 本地模型（CPU / GPU）/ 本地规则保底」三种模式；模型模式复用同一分块提取、合并、终稿与格式校验流程，本地规则不调用模型。结果保存到统一导出目录的「直播总结」，支持预览已保存结果、进度与停止。
-   本地模式无需安装 Ollama；使用可选的 llama.cpp 独立运行组件，目前支持 Windows x64。CPU 与 GPU（Vulkan）分别选择，GPU 需显卡驱动支持 Vulkan；不会自动切换模块。每次总结或测试连接新建仅监听本机的独立进程，结束或取消只回收该任务的进程。
-   安装、导入与卸载只有「全局设置 → 运行环境与组件 → 本地总结组件（可选）」入口，属于既有设置页的 L2 面板，不新增侧栏或管理器。CPU/GPU 模块和 GGUF 模型均可按需准备，标准版、FULL 版都不内置、不自动下载、不计入必需依赖缺失。
-   推荐模型提供通义千问 2.5 3B / 7B 的 Q4_K_M GGUF；也可导入用户自行持有且 llama.cpp 支持的 GGUF v2/v3。分片模型选择 00001 首文件，其余分片放同一目录；导入只建立受控副本，不移动或改写源文件。安装与导入校验文件完整性；卸载需确认，只删除受控模块或所选模型及其分片，保留导入源文件和配置。已有完整模块执行校验，损坏模块重新下载。
-   总结页可配置推理模块、已准备的模型、上下文长度、CPU 线程数（0 自动）、GPU 卸载层数、批处理大小、最大输出长度与采样温度；模型列表超过 12 项支持名称筛选。CPU 模式忽略 GPU 层数；最大输出长度小于上下文，批处理大小不能超过上下文。较长规则与转录需要更大上下文和足够内存，模型兼容性、速度与总结质量取决于硬件及模型；连接成功只证明推理链路可用。
-   切换本地或规则模式保留原接口配置与已保存的 API Key。推理参数仍由既有配置 owner 写入 `convert.livestream_summary_local`；组件唯一写入方为 Qt-free 的 `livestream_summary/optional_runtime.py`，manifest schema=1，以模型首文件名标识受控副本，组件位于程序根 `optional_components/local_llm/`，只读安装位置回退到 LocalAppData 同名目录。模型不随配置备份或发行包收集，许可证按各模型卡单独确认。
-   模型接口支持 OpenAI Chat Completions、OpenAI Responses API 与 Anthropic Messages API。可按当前接口地址和格式获取模型列表，再下拉选择或输入关键词筛选；服务未返回列表时仍可手动填写模型名。修改接口地址或格式后需重新获取列表；获取过程可取消，设置须由用户显式保存。API Key 使用直播总结现有的本机加密存储。
-   WebUI 同步三种模式、八项参数、组件下载 / 校验 / 卸载、模型下载 / 导入 / 删除及可取消任务；使用同一共享用例和存储。Web 导入只列出服务端工作目录内的 GGUF 首文件，不接受客户端任意绝对路径；桌面可用本机文件选择框导入。
