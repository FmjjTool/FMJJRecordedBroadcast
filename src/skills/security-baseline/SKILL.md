# 应用安全基线（Security Baseline）

先阅读 [convention-skill](../convention-skill/SKILL.md) 与 [cookie-data-protection](../cookie-data-protection/SKILL.md)。涉及登录/凭据时再读 [cookie-manager](../cookie-manager/SKILL.md)；涉及发布时再读 [summarize-update](../summarize-update/SKILL.md)。

本 skill 从 **Cookie 保护结束的地方开始**：真实 Cookie 的读取、写入、迁移、清除仍只按 `cookie-data-protection` 与 `cookie-manager` 执行，本 skill 不重复、不放宽、也不授权任何真实凭据操作。

## 适用与不适用

**适用**：新增/修改密钥或 Token、日志与报错、文件导入/导出、ZIP/压缩包处理、subprocess、网络请求、依赖升级、安装包与发布产物。

**不适用**：纯 UI 文案、纯视觉调整、纯业务参数修正；但不得借本 skill 绕过 Cookie、录播核心或腾讯文档写入约束。

本 skill 是纯 Markdown 约束，不安装运行时拦截器；由 Agent 阅读后人工核对。所有安全验证只在独立临时目录使用虚构数据，不复制真实凭据、不访问真实账户。

## 资产分级

| 级别 | 例子 | 规则 |
| --- | --- | --- |
| **Secret** | Cookie、Token、API Key、LLM Key、腾讯 OpenAPI、浏览器 storage_state、登录快照 | 只存受控加密存储；不打印、不写日志/报告/Git/截图；只在内存中传给对应目标 |
| **Sensitive** | 账号 ID、昵称、粉丝数据、聊天/弹幕、下载媒体、文件路径、报表 | 只在功能需要时展示；日志/图片/导出避免无关暴露；遵守保留与删除规则 |
| **Public** | 平台公开作品、公开统计、UI 文案 | 可正常使用，但仍不得夹带 Secret/Sensitive 字段 |

应用账户认证统一走 cookie-manager 的管理层；Cookie / Token / 腾讯 OpenAPI 不另建业务页入口。LLM 等非账户服务密钥沿用其已存在且受控的设置，不为本轮任务新建第二套存储。开发工具 git / gh 只读使用宿主既有原生认证，不复制到应用或临时文件。禁止硬编码密钥、重复凭据文件、业务页面级登录控件或临时明文配置。

## 密钥与日志

1. 任何 Secret 不得进入源码、默认配置、示例数据、测试夹具、日志、异常消息、报告、截图、导出文件、Git 提交或安装包。
2. 日志只记录**必要上下文**：模块、操作、平台、结果、耗时；不记录完整 Cookie/Token、Authorization 头、请求体、签名串、带签名的完整 URL。
3. 错误提示面向用户时不含 Secret；诊断信息写日志时也必须脱敏。禁止把 `repr(response)`、`repr(headers)`、完整配置对象直接打进日志。
4. 调试输出（`print`、临时 `logging.debug`、截图）在提交前清理；不得以“只在本地”为由提交含 Secret 的调试代码。
5. 发现疑似泄漏：立即停止相关操作，记录不含 Secret 的证据（文件、调用、时间、类型），按 `convention-skill` 报告；不自行回写、轮换或删除真实凭据。

## 用户输入与文件

1. URL：默认只允许 `http` / `https`；拒绝 `file://`、`javascript:` 等协议。用户可控 URL 的网络请求要限制目标主机、超时、重定向次数和响应大小；任意抓取场景要防 SSRF（本机、内网、云元数据地址）。
2. 路径：使用 `pathlib` / `os.path` 规范化后，确认目标位于允许的根目录内；拒绝 `..`、绝对路径逃逸、Windows 保留设备名；文件名清洗后再落盘。
3. ZIP/压缩包：解压前逐条校验目标路径，拒绝 Zip Slip；限制条目数、单文件大小、总解压大小和压缩比，防解压炸弹；只解压允许的扩展名。
4. 导入备份/配置：先校验格式与版本；在临时目录解压/解析；成功后再原子替换；不直接覆盖正在使用的真实数据。
5. 删除/覆盖：用户数据先备份或移入回收站；批量删除、覆盖、清空必须有明确确认；不得用清理临时文件的方式删除业务数据。
6. 图片/媒体：解码前限制尺寸/像素数；损坏文件返回占位/错误，不崩溃；生成图片不带 EXIF/路径/凭据。

## 子进程

1. 使用参数列表调用，禁止 `shell=True` 和拼接用户输入的命令字符串。
2. 可执行文件用明确路径或受控的 PATH 查找；参数逐项校验；工作目录限定在允许范围。
3. 设置超时、捕获输出、限制输出大小；非零退出码按错误处理，不静默忽略。
4. Secret 不放命令行参数（进程列表可见）；必须传递时用 stdin/环境变量，并在日志中脱敏。
5. 外部二进制（ffmpeg / 7z / node / git 等）来源要可信；下载安装时校验来源与完整性，不执行未知脚本。
6. 子进程创建/终止遵守 `process_tree` 既有约定；不留下孤儿进程。

## 网络请求

1. TLS 校验默认开启；禁止关闭证书校验来“绕过”问题。
2. 设置连接/读取超时、最大重定向、最大响应体；大文件下载要限速/分块/可取消。
3. 只向必要域名发送凭据；跨域重定向时丢弃 Authorization/Cookie；不把平台 Cookie 发给 CDN/第三方。
4. 响应按预期格式校验（状态码、Content-Type、JSON 结构、字段类型）；解析失败归类为 `ParseChanged`，不要当成空数据。
5. 游客票据、临时签名只用于当次请求；不持久化为用户登录态。
6. 不绕过付费、DRM、平台访问控制或风控；不共享/转卖账户凭据。

## 依赖与供应链

1. 新增依赖必须说明用途、版本、许可证与失败降级；优先标准库和现有依赖，避免为小功能引入大包。
2. 依赖版本应可复现：生产/打包环境锁定版本或使用锁文件；升级时记录变更与验证结果。
3. 可选依赖缺失时必须有明确降级或提示，不得静默崩溃；不得在运行时从不可信地址下载并执行代码。
4. 第三方二进制/模型/字体/图标遵守许可证，更新 `THIRD_PARTY_NOTICES.md`。
5. 定期检查已知漏洞与废弃依赖；发现高危问题先评估影响，再决定升级/替换。

## 发布与打包

1. 打包前隐私扫描必须通过；扫描中止 = 发布中止，不得绕过。
2. 安装包/产物不得包含 `config/`、`download/`、`logs/`、真实账号数据、Cookie/Token、浏览器 profile 或调试端点。
3. 发布 Token 只存在于内存变量；不打印、不写文件、不进入提交/日志。
4. 安装器不做静默提权、不写入非必要系统位置、不创建可被其他用户读取的凭据文件。
5. 构建产物与源码版本可追溯；Release 资产大小/校验信息与本地一致。

## 检查清单

- [ ] 本次是否新增/修改 Secret？是否只走既有管理层，未新增硬编码或第二套存储？
- [ ] 日志、异常、报告、截图是否可能包含 Cookie/Token/Authorization/带签名 URL？
- [ ] 用户可控 URL/路径是否做了协议、主机、根目录、`..`、超时、大小校验？
- [ ] ZIP/备份导入是否防 Zip Slip、解压炸弹和覆盖正在使用的数据？
- [ ] subprocess 是否无 `shell=True`、无用户拼接命令、有超时、Secret 不在 argv？
- [ ] 新依赖是否说明用途/版本/许可证/降级，是否可复现？
- [ ] 发布产物是否通过隐私扫描，未包含配置/下载/日志/凭据？
- [ ] 安全验证是否只使用临时目录和虚构数据，未触碰真实账户/凭据？
- [ ] 本次改动是否需要同步 `ui-visual-spec`（图片/截图）与当日报告？

## 与其他 skill 的关系

- `cookie-data-protection` / `cookie-manager`：真实 Cookie 与统一登录，优先级更高；本 skill 只补其余安全边界。
- `summarize-update`：发布流程与安全红线；本 skill 补依赖、文件、网络、日志的通用规则。
- `layering-contract`：安全能力放在 L5 / 横切层；页面不直接处理 Secret。
- `testing-quality-gates`：安全校验需要测试用例与隔离夹具。
- `tcdoc-sync-scope`：腾讯文档写入白名单；本 skill 不放宽写入范围。
