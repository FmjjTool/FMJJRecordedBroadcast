# Cookie 数据绝对保护（强制中的强制）

先阅读 [convention-skill](../convention-skill/SKILL.md)，再完整阅读本 skill，之后才执行项目操作。**Cookie 管理器中已经保存的真实 Cookie 绝对、绝对不允许 Agent 改动。** 这是项目内最高优先级的数据保护禁令，适用于所有 Agent、子 Agent、自动化与后台任务。

## 保护对象与优先级

- 保护全部真实已存 Cookie，包括原值、所属平台/账号、保存时间、有效期记录、加密表示及其真实存储文件。文件不在 Git 中、被 `.gitignore` 忽略、位于 AppData 或工作区外，都不能触碰。
- 保护管理器关联的浏览器登录快照、localStorage、旧格式 Cookie、凭据副本及承载相同登录态的会话文件，不能通过删除副本或改另一份状态间接改变已有账户。
- 本禁令优先于项目内的登录统一、自动验证、失效处理、迁移清理、源码备份、核心模块具体授权与发布要求。**不设临时授权、确认后覆盖、测试、修复或迁移例外**；不能把普通登录/更新指令解释为解除禁令。
- 约束对象是 Agent 的操作及其触发的应用/脚本副作用。源码中已有保存或清除按钮，不代表 Agent 可以调用；用户数据也不能因历史代码已有自动写回就被改动。

## 绝对禁止

1. 直接写入、覆盖、替换、删除、清空、截断、合并、刷新、迁移或重新加密真实 Cookie；修改保存时间、平台映射、账号绑定或改密钥/加密规则使旧 Cookie 失效。
2. 整份改写真实凭据文件，即使最终 Cookie 明文相同、只改总开关、只增加一个平台、只调整格式或宣称“整理缓存”也禁止。
3. 通过手工输入、扫码登录、重新登录、切换账户、浏览器 profile、登录快照、旧文件补登记或接口响应的 `Set-Cookie` 自动回写。只读请求产生的临时响应票据不得持久化回真实管理器。
4. 通过配置导入/恢复、目录迁移、清理临时文件、卸载重装、发布打包或批量删除配置触碰真实凭据；不得为了保护数据而自动改文件权限、移动数据或复制真实 Cookie。
5. 将真实 Cookie 输出到终端、报告、skill、日志、截图、导出、发行包或 Git；不得用真实 Cookie、真实配置副本构造测试数据。源码备份规则不包含任何凭据文件。
6. 为测试先清空/替换真实 Cookie，再声称结束后恢复；恢复也属于再次写入，不能用“可回滚”规避禁令。

## 当前路径与有副作用的入口

以下是源码中的定位线索，**不是许可执行的操作清单**。只静态读取源码核对，不为查找路径而启动真实登录管理器。

| 定位 | 保护或禁止执行的内容 |
| --- | --- |
| `src/auth.py` 的 `COOKIE_FILE` | 由配置目录定位的 `cookies.json`，通常是项目/安装目录的 `config/cookies.json`，也可能是 `%APPDATA%/FengMingToolbox/config/cookies.json` |
| `src/auth.py` | `save_cookies()`、`set_cookie()`、`clear_cookie()`、`set_cookie_enabled()` 会写真实凭据文件；禁止对真实环境调用 |
| `src/auth.py` | `get_netease_cookie()`、`get_netease_cookie_stored()` 可能触发 `_netease_legacy_migrate()` 并写入/删除旧文件；`sync_netease_to_legacy()` 会写旧副本，不能当作纯读取 |
| `src/netease/cookie.txt`、`src/netease/cookie_manager.py` | 旧网易云凭据及其保存/清除链路，不能因迁移/过期而处理真实文件 |
| `src/toolbox/tcdoc/session.py` | `save_from_context()`、`save_state_snapshot()`、`sync_from_state()`、`clear()` 可能改 `config/tcdoc_state.json` 或调用统一 Cookie 写入/清除 |
| `src/gui_qt/cookie_manager.py` | 手工输入、扫码、浏览器保存与清除操作；腾讯文档快照、酷狗概念版会话及浏览器 profile 也纳入相关存储保护 |

文件名或目录不是完整范围；所有实际保存同一账户凭据的位置均受保护。`get_config_dir()` 等路径函数还可能创建目录或做探测，真实环境的查找与验证优先用源码静态分析，不能假定导入模块/打开管理窗口没有副作用。

## 允许的读取与隔离验证

- 业务可通过已确认无写入、迁移、刷新或清除副作用的有效凭据接口只读使用现有 Cookie，仅在请求内存中传给相应平台；不得输出、转储或回写。无需要时不打开真实 Cookie 文件。
- 名称带 `get`、`load`、`verify` 不足以证明安全：先静态核对整个调用链。不能安全使用时保留现有数据，停止依赖该调用的部分，并说明具体阻碍。
- 代码/界面/迁移能力验证只用新建的独立临时目录和虚构凭据，测试目录、配置路径、浏览器 profile 与快照都必须隔离；不可引用真实目录、真实凭据或指向它们的链接/junction。
- 测试前确认所有可能的读写入口都指向隔离环境，再运行实例化、保存、清除、换号等验证；无法确认就继续静态检查，不启动真实应用“试一下”。
- 只新增保护文档时检查 Markdown、引用与提交范围即可，不调用真实认证接口，不读取真实 Cookie 内容，不执行登录、刷新、迁移、配置写入或删除。

## 遇到冲突或意外变化

需求依赖修改已存 Cookie 时，停止该部分，说明本 skill 的具体禁令，继续可以独立完成的工作；不提供“确认后覆盖/删除 Cookie”的默认放行路径。其他 skill 的登录、迁移、清除流程一律仅在隔离虚构环境讨论或验证，不对真实账户执行。

发现意外变化时立即停止相关操作，记录路径、相关调用和变化类型等不含凭据内容的证据并汇报；不能自动继续保存、重新登录或回滚真实凭据。不能为证明“未改动”而输出凭据或再做一次写入。

按总约定将实际范围、检查结果、未执行事项和提交信息汇入唯一当日报告，再本地提交文档。skill 只使用 Markdown，不附带拦截脚本或配置；文档约束不等于现有应用已安装运行时写入锁，不得虚报实现。
