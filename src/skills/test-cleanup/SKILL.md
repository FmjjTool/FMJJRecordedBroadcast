# 测试文件与本地残留清理（Test Cleanup）

## 定位

本项目的 `tests/` 目录整体被 `.gitignore` 的 `tests/` 规则忽略，测试文件只作本地临时验证产物：不进 Git、不随任务交付、删除后无法从版本库恢复。任何代码任务完成后，必须按本 skill 清空 `tests/` 与测试缓存，保持本地工作区不留测试残留。

根目录还会积累开发过程产物（临时脚本、冒烟截图、页面快照、编辑器/Agent 暂存目录、功能调试导出等）。这些同样只在本地保留、可重建；用户要求清理或明确列出残留时，按本 skill 的「根目录临时产物」范围处理。

本 skill 只规定「什么时候删、删什么、不删什么」；测试层级、用例质量与门禁仍以 [testing-quality-gates](../testing-quality-gates/SKILL.md) 为准，本 skill 不降低任何测试要求。

## 固定烟测目录 `_smoking/`（强制）

1. 所有手动冒烟 / 联调脚本、harness、临时数据、日志与过程截图统一放在项目根目录 `_smoking/`；不得散落到根目录、`tests/`、`src/` 或 `Progress/`。
2. `_smoking/` 已加入 `.gitignore`，只留本地：禁止 `git add -f`、禁止提交或推送；提交前用 `git status` 与 `git ls-files _smoking` 确认没有烟测文件进入版本库。
3. `_smoking/` 是可复用的本地临时工作区：任务结束默认保留脚本供下次复用，只清理其中可再生的截图、日志与临时数据；删除整个目录或用户提供的烟测脚本必须先取得确认。
4. 只有需要作为长期报告证据的最终截图才另存到 `Progress/ui/<日期>/`（PNG 已被忽略）；harness、原始截图与中间产物一律留在 `_smoking/`。
5. 发现根目录散落的烟测文件时，优先移动到 `_smoking/`；属于并行会话或无法确认归属的文件先报告，不擅自移动。
6. 自动化测试仍放 `tests/`，并按本 skill 的删除范围处理；`_smoking/` 不能替代测试目录。

## 触发条件

1. 任何修改、新增或删除源码、资源、配置、文档的任务，在验证完成后的收尾阶段。
2. Agent 本次创建了临时测试、冒烟脚本或测试夹具。
3. 用户发出「清理测试」「测试文件删掉」「缓存也删」等指令，或指出根目录有很多无用文件、明确列出待清理路径。
4. 纯只读任务不触发清理；若发现上次残留的测试文件或缓存，在报告中提示，交由下一次代码任务收尾时清理，不擅自删除。

## 执行顺序（不可颠倒）

1. 先按 `testing-quality-gates` 编写并运行本次需要的测试，记录真实结果。
2. 验证通过，或失败已定位、已如实记录后，再执行清理；不得为了「删得干净」而跳过、缩减或伪造测试。
3. 执行清理（见下节），并记录删除前的范围与大致数量。
4. 更新当日报告 `Progress/YYYY-MM-DD_当日总结.md`，写明清理范围与残留。
5. 本地 `git commit`（测试文件被忽略，提交内容只含业务/文档改动）；提交前用 `git status` 确认没有测试文件或缓存进入暂存区。

## 删除范围

### 一、测试文件与测试缓存（全部删除，不备份）

1. `tests/` 目录下全部内容：所有 `test_*.py`、测试夹具、测试数据、子目录与历史用例，整目录删除，不逐文件挑选。
2. 测试缓存：
   - `tests/` 下任意 `__pycache__/`；
   - 项目根及各级目录的 `.pytest_cache/`；
   - 测试运行产生的 `*.pyc` / `*.pyo`；
   - 覆盖率与测试报告产物：`.coverage`、`coverage.xml`、`htmlcov/`、`.tox/`、`.nox/`；
   - 测试运行生成、只用于本次验证的临时日志、导出物与截图（确认不属于用户数据）。
3. 删除后不保留空的 `tests/` 目录；下次需要测试时按 `testing-quality-gates` 重新创建。

### 二、根目录临时产物（用户确认后删除）

以下类别的共同点：未跟踪或已被 `.gitignore` 忽略、可重建、不参与运行。用户明确列出或要求清理时成组删除，不逐文件挑选；无法确定归属的保留并询问。

| 类别 | 当前实际路径（示例） |
| --- | --- |
| 临时工作目录与一次性脚本 | `.tmp/`、`_tmp_*`、`_probe_*`、`_test_ks_*` |
| 冒烟测试产物（历史散落） | `_smoke/`、`/_smoke_*.py`、`_smoke_*.png`；新烟测统一放 `_smoking/`，不在此清单默认清理 |
| 调试抓取页面快照 | 根目录 `/*_*.html`（如 `_fc.html`、`_s1.html`） |
| 编辑器 / Agent 暂存与工作区 | `.qoder-input-files/`、`.qoder-input-images/`、`.codeartsdoer/`、`.trae/`、`.trae-html-share-packages/`、`.workbuddy/`、`.workbuddy-ai/` |
| 功能调试目录 | `_taobao_debug/`、`_dyx_debug/`、`test/_out/`、`test/_dump/` |
| 根级 Python 缓存 | `__pycache__/`、`*.pyc` |

新增同类目录时先补进 `.gitignore` 再清理，避免反复出现在 `git status`。

## 不清理与需确认的内容

1. 不删除 `src/` 下任何源码、资源或非测试文件；不删除未列入上表的根目录文件与目录。
2. 不删除用户数据、真实凭据、Cookie 存储与登录快照：[cookie-data-protection](../cookie-data-protection/SKILL.md) 最高优先，清理永远不覆盖该禁令。
3. 运行数据与用户产物不清理：`config/`、`download/`、`logs/`、`models/`、`Progress/`（含 `Progress/ui/` 证据截图）；打包产物 `build/`、`build_full_vendor/`、`dist/`、`*.spec`，以及 `docs/`、`task.md`、`_ref/`、`.uploads/`、`peachring_export/` 等未列入清单的项。
4. 备份与快照目录（如 `_backup/`）可能承载用户数据或迁移恢复点：先取得用户对具体目录的明确确认，确认后移入回收站（PowerShell `Microsoft.VisualBasic.FileIO.FileSystem::DeleteDirectory(..., 'SendToRecycleBin')`），不直接 `unlink`/`rmtree`。
5. 被 Git 跟踪的本地数据文件（如根目录导出的作品清单 xlsx）：默认 `git rm --cached` 移出版本跟踪并在 `.gitignore` 增加对应规则，保留本地文件；只有用户明确要求删除文件本身时才删除。
6. 不删除需要作为证据的截图：按 `testing-quality-gates`，最终证据截图放 `Progress/ui/<日期>/`；烟测过程截图与 harness 固定在 `_smoking/`，不在 `tests/` 或 Progress 内。
7. 批量删除前必须取得用户对删除清单的明确确认（列出清单或逐项确认）；用户只说「文件很乱/没用」不构成删除授权。
8. 删除前对每个待删路径执行 `git ls-files <路径>`：有输出（被跟踪）时立即停止并询问用户，不直接删除被跟踪文件。
9. 不为清理修改 `.gitignore` 的 `tests/` 忽略规则，或把测试文件改为入库；根目录临时产物的忽略规则可以补齐。
10. 删除失败（权限不足、文件被占用）时如实报告残留位置与原因，不重复强删，不扩大删除范围。

## 安全与并行

1. 删除前确认没有正在运行的测试或软件进程占用这些文件；被占用时停止并说明，不得结束进程（[running-instance-guard](../running-instance-guard/SKILL.md)）。
2. 多 Agent / 并行工作时，删除 `tests/` 前按 [agent-coordination](../agent-coordination/SKILL.md) 确认没有其他任务正在使用或编写测试；有冲突时先协商，不单方面清空共享测试目录。
3. 清理前检查 `src/`、`main.py`、`build.py` 等是否有指向待删路径的字面引用；存在引用时保留并报告。
4. 本 skill 不构成对真实 Cookie、用户数据或核心八模块的改动授权；测试本身仍只能使用临时目录与虚构数据。

## 验证

1. 清理后 `git status` 只应出现预期的业务/文档改动，不得出现测试文件或缓存。
2. 对新增的忽略规则执行 `git check-ignore -v <路径>` 确认生效。
3. 报告写明删除范围、释放空间，以及被占用或保留的残留。

## 例外

1. 用户当次明确要求保留部分或全部测试文件时，以用户指示为准，只跳过对应范围，并在当日报告注明保留原因。
2. 任务本身就是在维护测试基础设施（例如用户要求修复或补充 `tests/`）时，清理范围以用户当次的明确说明为准，不默认全部删除。

## 检查清单

- [ ] 本次测试已先运行并记录真实结果，未为清理跳过或缩减测试。
- [ ] `tests/` 下测试文件已全部删除（用户当次明确保留的除外），未保留空目录。
- [ ] `__pycache__`、`.pytest_cache`、`*.pyc`、覆盖率与测试报告产物等测试缓存已删除。
- [ ] 本次烟测脚本、harness、临时数据与过程截图均在 `_smoking/`，未散落到根目录、`tests/` 或 `Progress/`。
- [ ] `_smoking/` 未被 `git add -f`、未进入提交或远端（`git ls-files _smoking` 为空）。
- [ ] 根目录临时产物只在用户确认的清单内删除，未扩大范围。
- [ ] 待删路径均已核对 `git ls-files` 为空；被跟踪的本地数据文件只移出版本跟踪、未删本地文件。
- [ ] 备份/快照类目录经用户明确确认后移入回收站，未直接删除。
- [ ] 未删除源码、用户数据、凭据或证据截图；文件被占用时未结束进程。
- [ ] 已更新当日报告并本地提交，报告写明清理范围、释放空间与残留（如有）。

## 与其他 skill 的关系

- `testing-quality-gates`：先测后删；测试层级、数据隔离与质量门禁不变。
- `cookie-data-protection`：真实凭据绝对保护，清理不触及凭据。
- `running-instance-guard`：文件被占用时停止，不结束进程。
- `agent-coordination`：并行时先确认测试目录所有权，再执行删除。
- `data-lifecycle`：备份/快照与用户数据的保留清理规则；批量删除前确认、优先回收站。
